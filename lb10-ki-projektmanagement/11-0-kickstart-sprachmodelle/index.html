11.0 KI-Kickstart: Wie funktionieren Sprachmodelle?

Einführung 2Übungen 4Vertiefung 3

In diesem Kurs arbeitest du regelmäßig mit schulKI.de. schulKI ist selbst kein Sprachmodell, sondern eine Schulplattform, die deine Eingaben an große Sprachmodelle weiterleitet (Standardmodell: Haiku 5.5 von Anthropic, weitere Modelle wählbar). Bevor du das tust, sollst du verstehen, was dabei technisch passiert: wie aus deinem Text Zahlen werden, wie das Modell das nächste Wort auswählt, wie es trainiert wurde und warum es deshalb manchmal überzeugend klingenden Unsinn schreibt. Am Ende stehen die Regeln, nach denen wir KI in diesem Kurs einsetzen, und die Frage, welche Daten du einem Sprachmodell anvertrauen darfst.

Nach dieser Seite kannst du

  • den Weg vom Prompt zur Antwort in sechs Schritten beschreiben (Tokenisierung, Embedding, Attention, Logits, Softmax, Auswahl),
  • einen Text mit einem gegebenen Vokabular tokenisieren und Wahrscheinlichkeiten mit Softmax und Temperatur berechnen,
  • die wichtigsten Fehlerquellen eines Sprachmodells aus seiner Funktionsweise begründen,
  • beurteilen, welche Daten in einen Prompt gehören und wie du KI-Nutzung kennzeichnest.

1. Die Grundidee: das nächste Token vorhersagen

Ein Sprachmodell ist mathematisch gesehen eine Funktion. Sie bekommt eine Folge von Textbausteinen (Tokens) t1, t2, …, tn−1 und liefert für jedes Token ihres Vokabulars eine Wahrscheinlichkeit, dass es als Nächstes kommt:

P(tn | t1, …, tn−1)

Mehr kann das Modell nicht. Eine ganze Antwort entsteht, indem diese Vorhersage in einer Schleife wiederholt wird: Ein Token wird ausgewählt, an den Text angehängt, und der verlängerte Text ist die Eingabe für den nächsten Durchlauf. Man nennt das autoregressiv.

text = prompt
solange das Modell nicht das Ende-Token wählt:
    verteilung = modell(text)        # Wahrscheinlichkeit für jedes Token im Vokabular
    token = auswaehlen(verteilung)   # z. B. das wahrscheinlichste oder zufällig gewichtet
    text = text + token

Innerhalb von modell(text) laufen sechs Schritte ab, die du auf dieser Seite nacheinander kennenlernst:

SchrittWas passiert?Abschnitt
1. TokenisierungText wird in Tokens zerlegt, jedes Token bekommt eine Nummer (ID).2
2. EmbeddingJede ID wird durch einen Zahlenvektor ersetzt, der die Bedeutung „codiert“.3
3. Transformer-SchichtenAttention mischt die Vektoren so, dass jedes Token seinen Kontext „kennt“.4
4. LogitsFür jedes Token im Vokabular entsteht eine Bewertungszahl.5
5. SoftmaxDie Bewertungen werden in Wahrscheinlichkeiten umgerechnet (Temperatur).5
6. AuswahlEin Token wird gewählt: das wahrscheinlichste oder gewichtet zufällig.5

Im Video siehst du die Schleife einmal ganz durchlaufen: vom Prompt über die Verteilung bis zum Ende-Token.

2. Tokenisierung: aus Text werden Zahlen

Ein neuronales Netz rechnet nur mit Zahlen. Deshalb wird der Text zuerst in Tokens zerlegt. Ein Token ist meist ein häufiges Wort oder ein Wortteil, manchmal auch ein einzelnes Zeichen. Jedes Token hat eine feste Nummer, seine Token-ID. Das Vokabular eines großen Modells umfasst typischerweise einige Zehntausend bis einige Hunderttausend Tokens.

  • Häufige Wörter wie „und“ oder „Haus“ sind ein einziges Token. Als Faustregel nennt schulKI für englische Texte etwa vier Zeichen pro Token; der Satz „Hallo, wie geht es dir?“ hat 23 Zeichen und ergibt 7 Tokens. Satzzeichen sind meist ein Token, Emojis zwei bis drei.
  • Seltene oder lange Wörter werden in mehrere Teile zerlegt, z. B. „Informatik|erin“. Deutsche Texte brauchen deshalb oft mehr Tokens pro Wort als englische.
  • Das Vokabular wird vor dem eigentlichen Training aus großen Textmengen bestimmt. Das verbreitete Verfahren Byte-Pair-Encoding beginnt mit einzelnen Zeichen und fasst immer wieder das häufigste benachbarte Paar zu einem neuen Token zusammen, bis das Vokabular die gewünschte Größe hat.

Beim Zerlegen eines neuen Textes nehmen wir hier eine vereinfachte, aber verbreitete Regel: An jeder Stelle wird das längste Stück gewählt, das im Vokabular steht (greedy longest match). Einzelne Buchstaben stehen immer im Vokabular, so lässt sich jedes Wort zerlegen.

Beispiel 1 einfach

Ausgangssituation: Das Vokabular besteht aus diesen Tokens (ID in Klammern) und danach den Einzelbuchstaben a–z, ä, ö, ü, ß mit den IDs 8 bis 37 (a = 8, b = 9, …, z = 33):

informat (0), inform (1), iker (2), ik (3), er (4), in (5), atik (6), ung (7)

Das Wort „informatikerin“ soll tokenisiert werden.

  1. Was: An Position 0 das längste passende Stück suchen. „informatikerin“, „informatikeri“, … stehen nicht im Vokabular; das erste Stück, das passt, ist „informat“ (8 Zeichen). – warum: Wir prüfen von lang nach kurz, damit „informat“ vor „inform“ und vor „i“ gewinnt.
  2. Was: Ab Position 8 bleibt „ikerin“. Längstes passendes Stück: „iker“ (nicht „ik“). – warum: Gleiche Regel; „ikerin“ und „ikeri“ gibt es nicht.
  3. Was: Ab Position 12 bleibt „in“, und „in“ steht im Vokabular. – warum: Damit ist das Wortende erreicht.
  4. Was: Die Tokens in IDs übersetzen: informat → 0, iker → 2, in → 5. – warum: Nur diese Zahlen gehen in das neuronale Netz.

Ergebnis: „informatikerin“ → informat | iker | in → IDs [0, 2, 5], also 3 Tokens für 14 Buchstaben.

Kontrolle: Hängt man die Tokens wieder aneinander, entsteht genau das Ausgangswort. Zum Vergleich: Das Wort „spielerin“ kommt im Vokabular kaum vor und wird zu s | p | i | e | l | er | in, also 7 Tokens für 9 Buchstaben.

vokabular = ["informat", "inform", "iker", "ik", "er", "in", "atik", "ung"]
for buchstabe in "abcdefghijklmnopqrstuvwxyzäöüß":
    vokabular.append(buchstabe)        # IDs 8 bis 37

def tokenisiere(wort, vokabular):
    """Zerlegt wort: an jeder Stelle das längste passende Vokabular-Stück."""
    tokens = []
    pos = 0
    while pos < len(wort):
        laenge = len(wort) - pos       # mit dem längsten möglichen Stück beginnen
        gefunden = False
        while laenge > 0 and not gefunden:
            stueck = wort[pos:pos + laenge]
            if stueck in vokabular:
                tokens.append(stueck)
                pos = pos + laenge
                gefunden = True
            else:
                laenge = laenge - 1
        if not gefunden:               # Zeichen steht nicht im Vokabular
            tokens.append("<unbekannt>")
            pos = pos + 1
    return tokens

def token_ids(tokens, vokabular):
    ids = []
    for t in tokens:
        if t in vokabular:
            ids.append(vokabular.index(t))
        else:
            ids.append(-1)             # -1 steht für „unbekannt“
    return ids

# Testfälle (erwartete Ausgabe als Kommentar)
print(tokenisiere("informatikerin", vokabular))   # ['informat', 'iker', 'in']
print(token_ids(["informat", "iker", "in"], vokabular))   # [0, 2, 5]
print(tokenisiere("spielerin", vokabular))        # ['s', 'p', 'i', 'e', 'l', 'er', 'in']
print(tokenisiere("", vokabular))                 # []
print(tokenisiere("c3po", vokabular))             # ['c', '<unbekannt>', 'p', 'o']

Folge für die Praxis: Das Modell sieht „informat“ als eine Zahl, nicht als acht Buchstaben. Fragen wie „Wie viele r stecken in ‚Erdbeere‘?“ oder „Schreibe das Wort rückwärts“ sind für ein Sprachmodell deshalb überraschend schwer, obwohl sie für dich trivial sind.

3. Embeddings: Bedeutung als Vektor

Eine Token-ID ist nur eine Nummer; ID 5 ist nicht „ähnlicher“ zu ID 6 als zu ID 3000. Deshalb ersetzt das Modell jede ID durch einen Embedding-Vektor, eine Liste aus mehreren Hundert bis einigen Tausend Kommazahlen. Diese Zahlen sind nicht von Menschen festgelegt, sondern werden beim Training gelernt. Dabei landen Tokens, die in ähnlichen Zusammenhängen vorkommen, bei Vektoren, die in eine ähnliche Richtung zeigen.

Wie ähnlich zwei Vektoren a und b sind, misst die Kosinus-Ähnlichkeit:

cos(a, b) = (a · b) / (|a| · |b|),   mit a · b = a1b1 + a2b2 + … und |a| = √(a1² + a2² + …)

Der Wert liegt zwischen −1 und 1. Werte nahe 1 bedeuten „gleiche Richtung“, also ähnliche Bedeutung.

Beispiel 2 einfach

Ausgangssituation: Stark vereinfachte Embeddings mit nur 3 Zahlen: Hund = (0,8; 0,6; 0,1), Katze = (0,7; 0,7; 0,2), Auto = (0,1; 0,2; 0,9). Welches Wort ist „Hund“ ähnlicher?

  1. Was: Skalarprodukte berechnen: Hund · Katze = 0,56 + 0,42 + 0,02 = 1,00; Hund · Auto = 0,08 + 0,12 + 0,09 = 0,29. – warum: Das Skalarprodukt ist groß, wenn große Einträge an denselben Stellen stehen.
  2. Was: Längen berechnen: |Hund| = √1,01 ≈ 1,005; |Katze| = √1,02 ≈ 1,010; |Auto| = √0,86 ≈ 0,927. – warum: Wir teilen durch die Längen, damit nur die Richtung zählt, nicht die Größe der Zahlen.
  3. Was: Kosinus bilden: cos(Hund, Katze) = 1,00 / (1,005 · 1,010) ≈ 0,985; cos(Hund, Auto) = 0,29 / (1,005 · 0,927) ≈ 0,311. – warum: Das ist die Formel von oben.

Ergebnis: „Katze“ ist „Hund“ deutlich ähnlicher (0,985) als „Auto“ (0,311).

Kontrolle: cos(Hund, Hund) = 1,01 / (1,005 · 1,005) = 1, wie es für identische Vektoren sein muss. In echten Modellen haben die einzelnen Zahlen keine einfache Bedeutung wie „ist ein Tier“; nur die Richtung im hochdimensionalen Raum zählt.

import math

def kosinus(a, b):
    skalar = 0
    laenge_a = 0
    laenge_b = 0
    for i in range(len(a)):
        skalar = skalar + a[i] * b[i]
        laenge_a = laenge_a + a[i] ** 2
        laenge_b = laenge_b + b[i] ** 2
    return skalar / (math.sqrt(laenge_a) * math.sqrt(laenge_b))

hund  = [0.8, 0.6, 0.1]
katze = [0.7, 0.7, 0.2]
auto  = [0.1, 0.2, 0.9]
print(round(kosinus(hund, katze), 3))   # 0.985
print(round(kosinus(hund, auto), 3))    # 0.311
print(round(kosinus(hund, hund), 3))    # 1.0

4. Kontext verstehen: Attention und Transformer

Ein Embedding allein kennt keinen Zusammenhang. Das Token „Bank“ hat zunächst denselben Vektor in „Am Elbufer sitze ich auf der Bank“ und in „Ich hebe Geld ab bei der Bank“. Moderne Sprachmodelle verwenden deshalb die Transformer-Architektur, deren Kern der Attention-Mechanismus ist:

  1. Für jedes Token berechnet das Modell, wie wichtig jedes vorherige Token für seine Bedeutung ist. Heraus kommen Gewichte zwischen 0 und 1, die zusammen 1 ergeben (sie werden ebenfalls mit Softmax berechnet, siehe Abschnitt 5).
  2. Der neue Vektor des Tokens ist eine gewichtete Mischung der Vektoren dieser Tokens. Im ersten Satz fließt viel von „Elbufer“ und „sitze“ ein, im zweiten viel von „Geld“ und „hebe … ab“. Beide Sätze sind so gebaut, dass diese Wörter vor „Bank“ stehen, denn nur auf diese darf ein Token schauen (siehe unten).
  3. Dieser Schritt wird in vielen Schichten hintereinander und mit mehreren „Köpfen“ parallel wiederholt. Dazwischen liegen kleine neuronale Netze. Alle Gewichte zusammen sind die Parameter des Modells, bei großen Modellen viele Milliarden.

Ein Token darf dabei nur auf Tokens vor sich schauen, denn bei der Vorhersage ist die Zukunft ja noch unbekannt. Wie viele Tokens das Modell gleichzeitig berücksichtigen kann, legt das Kontextfenster fest. Was nicht mehr hineinpasst, zum Beispiel der Anfang eines sehr langen Chats, existiert für das Modell nicht mehr.

So ist es bei schulKI: Das Modell selbst merkt sich nichts zwischen zwei Nachrichten. Bei jeder neuen Eingabe schickt schulKI deshalb deinen Prompt und den bisherigen Chatverlauf erneut an das Modell, laut Anleitung etwa die letzten sieben Nachrichten. Ältere Nachrichten fallen heraus und werden nicht mehr berücksichtigt. Alle mitgeschickten Tokens werden jedes Mal neu berechnet und vom Token-Konto deiner Lehrkraft abgezogen.

5. Von Bewertungen zu Wahrscheinlichkeiten: Softmax und Temperatur

Am Ende der Transformer-Schichten berechnet das Modell für jedes Token des Vokabulars eine reelle Zahl, seinen Logit. Je größer der Logit, desto passender findet das Modell das Token. Logits können negativ sein und ergeben zusammen nicht 1. Die Softmax-Funktion rechnet sie in Wahrscheinlichkeiten um; die Temperatur T steuert dabei, wie „spitz“ die Verteilung wird:

pi = ezi / T / (ez1 / T + ez2 / T + … + ezk / T)

  • Alle pi sind positiv und ergeben zusammen 1; die Reihenfolge der Logits bleibt erhalten.
  • T < 1: Unterschiede werden verstärkt, das beste Token wird noch wahrscheinlicher (vorhersehbarer Text).
  • T > 1: Unterschiede werden abgeschwächt, auch unwahrscheinliche Tokens kommen öfter vor (abwechslungsreicher, aber fehleranfälliger).
  • T → 0: Praktisch immer das beste Token (greedy). Gleicher Prompt, gleiche Antwort.

Für die Auswahl gibt es mehrere Strategien: immer das wahrscheinlichste Token (greedy), gewichtet zufällig ziehen (Sampling) oder nur unter den k wahrscheinlichsten Tokens ziehen (Top-k).

Die drei Videos rechnen Beispiel 3 Schritt für Schritt vor: erst die Softmax, dann die Wirkung der Temperatur, zuletzt die Auswahl mit Zufallszahlen.

Beispiel 3 komplex

Ausgangssituation: Prompt: „Die Landeshauptstadt von Sachsen ist“. Das Modell liefert für vier Kandidaten diese Logits (alle übrigen Tokens lassen wir weg): Dresden 4,0 · Leipzig 2,5 · Chemnitz 1,5 · schön 1,0. Gesucht sind die Wahrscheinlichkeiten für T = 1, T = 0,5 und T = 2 sowie der Trainingsverlust.

  1. Was: Für T = 1 die Exponentialwerte berechnen: e4,0 ≈ 54,598; e2,5 ≈ 12,182; e1,5 ≈ 4,482; e1,0 ≈ 2,718. – warum: Die e-Funktion macht jeden Wert positiv und verstärkt Unterschiede: 1,5 Logit-Punkte Abstand bedeuten Faktor e1,5 ≈ 4,5.
  2. Was: Summe bilden: 54,598 + 12,182 + 4,482 + 2,718 = 73,981. – warum: Durch diese Summe teilen wir, damit sich alles zu 1 addiert.
  3. Was: Teilen: p(Dresden) = 54,598 / 73,981 ≈ 0,738; p(Leipzig) ≈ 0,165; p(Chemnitz) ≈ 0,061; p(schön) ≈ 0,037. – warum: Das ist die Softmax-Formel mit T = 1.
  4. Was: Für T = 0,5 zuerst die Logits durch 0,5 teilen (8; 5; 3; 2), dann wie oben rechnen: e8 ≈ 2980,96; e5 ≈ 148,41; e3 ≈ 20,09; e2 ≈ 7,39; Summe ≈ 3156,85. – warum: Teilen durch T < 1 vergrößert die Abstände zwischen den Logits.
  5. Was: Für T = 2 die Logits halbieren (2; 1,25; 0,75; 0,5): e-Werte ≈ 7,389; 3,490; 2,117; 1,649; Summe ≈ 14,645. – warum: Teilen durch T > 1 verkleinert die Abstände.
  6. Was: Verlust berechnen, falls im Trainingstext tatsächlich „Dresden“ folgt: L = −ln(0,738) ≈ 0,304. Stünde dort „Leipzig“, wäre L = −ln(0,165) ≈ 1,804. – warum: Beim Training wird genau diese Größe verkleinert (Abschnitt 6). Ein unwahrscheinlich bewertetes richtiges Token erzeugt einen hohen Verlust.

Kontrolle: Jede Spalte ergibt (bis auf Rundung) 1. Die beiden Verluste unterscheiden sich um 1,804 − 0,304 = 1,5, genau den Abstand der Logits von Dresden und Leipzig. Das muss so sein, weil −ln pi = −zi + ln(Summe) gilt und die Summe für beide gleich ist.

import math
import random

def softmax(logits, temperatur=1.0):
    exps = []
    for z in logits:
        exps.append(math.exp(z / temperatur))
    summe = sum(exps)
    wahrscheinlichkeiten = []
    for e in exps:
        wahrscheinlichkeiten.append(e / summe)
    return wahrscheinlichkeiten

kandidaten = ["Dresden", "Leipzig", "Chemnitz", "schön"]
logits = [4.0, 2.5, 1.5, 1.0]

for T in [0.5, 1.0, 2.0]:
    p = softmax(logits, T)
    gerundet = []
    for wert in p:
        gerundet.append(round(wert, 3))
    print(T, gerundet)
# 0.5 [0.944, 0.047, 0.006, 0.002]
# 1.0 [0.738, 0.165, 0.061, 0.037]
# 2.0 [0.505, 0.238, 0.145, 0.113]

p = softmax(logits, 1.0)
print(kandidaten[p.index(max(p))])                  # Dresden   (greedy)
print(random.choices(kandidaten, weights=p, k=10))  # zufällig, meist 'Dresden'
print(round(-math.log(p[0]), 3))                    # 0.304     Verlust, wenn "Dresden" richtig ist
print(round(-math.log(p[1]), 3))                    # 1.804     Verlust, wenn "Leipzig" richtig wäre

6. Wie ein Sprachmodell trainiert wird

Das Training läuft in mehreren Phasen:

  1. Vortraining: Das Modell liest riesige Textmengen (Webseiten, Bücher, Code; insgesamt Billionen Tokens). An jeder Stelle sagt es das nächste Token voraus und vergleicht mit dem Token, das tatsächlich folgt. Man braucht dafür keine von Menschen beschrifteten Daten, denn der Text liefert die richtige Antwort selbst (selbstüberwachtes Lernen).
  2. Verlust und Anpassung: Der Fehler wird mit dem Verlust L = −ln(prichtig) gemessen. Ein Optimierungsverfahren (Gradientenabstieg, siehe Seite 11.8 Neuronale Netze) verändert alle Parameter ein kleines Stück so, dass L sinkt. Das wird Milliarden Male wiederholt.
  3. Feinabstimmung: Danach wird das Modell mit Beispiel-Dialogen weitertrainiert, damit es Fragen beantwortet, statt einfach Text fortzusetzen. Häufig bewerten Menschen zusätzlich Antworten, und das Modell wird auf die bevorzugten Antworten hin trainiert (Reinforcement Learning from Human Feedback, RLHF).
  4. Systemprompt: Im Betrieb setzt der Anbieter vor deinen Prompt meist unsichtbare Anweisungen, zum Beispiel zu Tonfall und Grenzen. Auch die Plattform deiner Schule kann so eingestellt sein.

8. Datenschutz: Was gehört in einen Prompt?

Dein Prompt wird an einen Server geschickt, dort verarbeitet und kann gespeichert werden. Die Datenschutz-Grundverordnung (DSGVO) schützt personenbezogene Daten, also alle Angaben, die sich einer Person zuordnen lassen: Namen, Noten, Adressen, Fotos, Gesundheitsangaben.

Was mit deinen Eingaben bei schulKI passiert (laut Datenschutzerklärung und Anleitung von schulKI, Stand Oktober 2026):

FrageAntwort
Wie meldest du dich an?Gar nicht: Deine Lehrkraft teilt einen Freigabeschlüssel (QR-Code oder Link), der nur für eine festgelegte Zeit gilt. Du arbeitest anonym unter einem zufälligen Pseudonym wie „lebhafter Nasenbär“ und verbrauchst die Tokens deiner Lehrkraft.
Wer sieht deine Chats?Die Chats werden gespeichert. Deine Lehrkraft sieht alle Chats, die über ihren Freigabeschlüssel entstanden sind, kann darin mitschreiben und sie von einer KI zusammenfassend auswerten lassen. Ob du Chats löschen darfst, legt sie beim Erstellen des Schlüssels fest.
Wohin geht dein Text?schulKI selbst läuft auf Servern in Deutschland. Den Inhalt deines Chats leitet schulKI aber an den Anbieter des gewählten Modells weiter: beim Standardmodell Haiku 5.5 an Anthropic, ein US-Unternehmen. schulKI tritt dabei selbst als Nutzer auf; dein Name und deine IP-Adresse werden nicht übertragen, der Text, den du schreibst, schon.

Wie lange wird gespeichert?Bis zum Löschen. Wird ein Chat am Tag der Erstellung gelöscht, ist er sofort weg, sonst bleibt er noch 14 Tage in Sicherungskopien. Sprachaufnahmen werden bei der Deutschen Telekom in Deutschland in Text umgewandelt und danach sofort gelöscht.

Daraus folgen diese Regeln:

  • Keine personenbezogenen Daten anderer (Mitschüler, Lehrkräfte, Familie) und keine besonders schützenswerten eigenen Daten (Gesundheit, Religion, …).
  • Keine Zugangsdaten wie Passwörter, PINs oder API-Schlüssel, auch nicht in eingefügtem Code.
  • Anonymisieren: „Schüler A hat …“ statt eines Namens; nur so viel Kontext wie nötig.
  • Fremde Texte und Bilder (z. B. urheberrechtlich geschütztes Material) nur, wenn du sie nutzen darfst. Das gilt auch für hochgeladene PDFs und Fotos: Auf einem Foto vom Arbeitsplatz können Namen oder Gesichter zu sehen sein.
  • Schreib nur, was deine Lehrkraft lesen darf. Der Chat ist kein privates Tagebuch.

schulKI selbst schreibt in seinen häufigen Fragen: Alle aktuellen KIs können sich irren, der Einsatz wird nur im begleiteten Unterricht empfohlen. Maßgeblich sind außerdem die Nutzungsregeln deiner Schule. Wenn du unsicher bist, ob etwas in den Prompt darf: weglassen oder vorher fragen.

Praxisbezug: Sprachmodelle im Alltag und im Beruf

Alltag: Die Wortvorschläge deiner Handytastatur, automatische Übersetzungen und Untertitel arbeiten nach demselben Prinzip „nächstes Token vorhersagen“, nur mit kleineren Modellen.

Beruf: Softwareentwicklerinnen und -entwickler nutzen Sprachmodelle als Programmierassistenz und müssen deren Code genauso prüfen und testen wie den eines Kollegen. Machine-Learning-Engineers passen Modelle an Firmendaten an und messen, wie oft sie halluzinieren. In Dresden und Leipzig forscht das KI-Kompetenzzentrum ScaDS.AI unter anderem daran, wie man solche Modelle zuverlässiger und nachvollziehbarer macht.

Das Wichtigste

Sprachmodell: berechnet für jedes Token seines Vokabulars die Wahrscheinlichkeit, als Nächstes zu kommen.

Autoregressiv: Text entsteht Token für Token: Token wählen, anhängen, neu berechnen.

Training: Das Modell wird an riesigen Textmengen so angepasst, dass das tatsächlich folgende Token eine möglichst hohe Wahrscheinlichkeit bekommt. Es lernt statistische Muster, legt aber keine Faktendatenbank an.

Wahrscheinlich statt wahr: Häufiges und Einheitliches gibt ein Sprachmodell meist richtig wieder; Seltenes, Widersprüchliches und alles nach dem Wissensstichtag nicht.

Attention: macht aus festen Wort-Vektoren kontextabhängige Vektoren: Jedes Token mischt sich mit den vorherigen Tokens, gewichtet nach deren Bedeutung für es.

Kontextfenster: begrenzt, wie viel Text dabei berücksichtigt wird.
