2.2.3 Einführung in Komplexität und die O-Notation

Einführung 2Übungen 3Vertiefung 1

Die Analyse der Laufzeit von Algorithmen ist ein wichtiger Bestandteil der Informatik. Sie hilft dabei, die Effizienz von Algorithmen zu verstehen und zu vergleichen – unabhängig davon, wie schnell der konkrete Rechner ist. Das wichtigste Werkzeug dafür ist die O-Notation (engl. Big-O-Notation).

Schritt 1: Schritte zählen statt Sekunden messen

Sekunden hängen vom Rechner ab, die Anzahl der Schritte nur vom Algorithmus und von der Eingabegröße n. Im Video zählst du in Thonny die Schritte der Funktion summe für die Liste [4, 8, 1] mit. Achte darauf, welche Anweisungen einmal zählen und welche so oft, wie die Schleife läuft.

Zum Nachlesen steht die Zählung mit dem Nachweis über die Definition in Beispiel 1:

Beispiel 1 einfach

Ausgangssituation: Summe einer Liste

def summe(liste):
    s = 0                 # 1 Schritt
    for x in liste:       # n Durchläufe
        s = s + x         # je 1 Schritt
    return s              # 1 Schritt

Insgesamt n + 2 Schritte, also O(n): Doppelt so viele Elemente bedeuten etwa doppelt so viel Zeit.

  1. Schritte zählen: f(n) = 1 + n + 1 = n + 2. Warum: Die Anweisungen außerhalb der Schleife laufen einmal, der Schleifenrumpf n-mal.
  2. Definition anwenden: Gesucht sind c und n0 mit n + 2 ≤ c · n für alle n ≥ n0. Mit c = 3 und n0 = 1 gilt n + 2 ≤ 3n ⇔ 2 ≤ 2n ⇔ n ≥ 1. Warum genügt das: Die Definition verlangt nur eine passende Konstante.
  3. Deuten: Die Konstante +2 spielt für große n keine Rolle. Es bleibt lineares Wachstum.

Ergebnis: f(n) = n + 2 ∈ O(n). Probe: Für n = 10 gilt 12 ≤ 30, für n = 1 gilt 3 ≤ 3.

summe([])0leere Liste, 2 Schritte
summe([5])5ein Element
summe([-2, 7, 1])6negative Zahlen

Kurz geprüft 1: Schritte von summe AFB I

Was gibt summe([3, 1, 4, 1, 5, 9]) zurück, und wie viele Schritte braucht die Funktion dafür?

Lösung zeigen

Rückgabe 23. Die Liste hat n = 6 Zahlen, also 1 + 6 + 1 = 8 Schritte.

Schritt 2: Schleifen in Schleifen zählen

Steckt eine Schleife in einer anderen, zählt man, wie oft die innere Schleife insgesamt läuft. Im Video läuft Bubblesort ohne Abbruch mit der Liste [5, 2, 9, 1], und eine Zähler-Tabelle hält fest, wie oft verglichen wird. Achte darauf, dass die innere Schleife mit jedem Durchlauf von i kürzer wird – deshalb bilden die Vergleiche ein Dreieck.

Zum Nachlesen: Bubblesort als Pseudocode

Um die O-Notation besser zu verstehen, betrachten wir den Bubblesort-Algorithmus. Er vergleicht Elemente einer Liste wiederholt und vertauscht sie, bis die Liste sortiert ist.

Prozedur BubbleSort(arr):
    n = Länge(arr)
    für i von 0 bis n − 2:
        für j von 0 bis n − i − 2:
            wenn arr[j] > arr[j + 1] dann:
                tausche arr[j] und arr[j + 1]

Die Grenzen sind einschließlich gemeint. Die innere Schleife endet bei j = n − i − 2, damit arr[j + 1] höchstens auf das letzte Element arr[n − 1] zugreift. Die Anzahl der Vergleiche ist (n − 1) + (n − 2) + … + 1 = n · (n − 1) / 2 = ½n² − ½n. Das liegt in O(n²).

Kurz geprüft 2: Vergleiche im Dreieck AFB I

Bubblesort ohne Abbruch sortiert eine Liste mit 7 Elementen. Wie viele Vergleiche macht die innere Schleife im Durchlauf i = 2, und wie viele Vergleiche sind es insgesamt?

Lösung zeigen

Bei i = 2 läuft j durch range(7 - 2 - 1) = range(4), also 4 Vergleiche. Insgesamt 6 + 5 + 4 + 3 + 2 + 1 = 21 = 7 · 6 / 2 Vergleiche.

Schritt 3: Das Verdopplungsexperiment

Ob die Rechnung n · (n − 1) / 2 stimmt, zeigt eine Messung: Man misst die Zeit für n und für 2n und bildet den Faktor. Im Video wird das Messprogramm in Thonny geschrieben; neu sind dabei time.perf_counter(), die Zufallszahlen mit random.randint, die per append in eine Liste kommen, und das Runden mit round. Achte darauf, welcher Faktor bei Verdopplung von n herauskommt – und warum er nicht vom Rechner abhängt.

Kurz geprüft 3: Zeit hochrechnen AFB I

Ein Programm mit quadratischer Laufzeit braucht für n = 3000 Elemente 0,5 s. Wie lange braucht es ungefähr für n = 6000 und für n = 12 000?

Lösung zeigen

Schritt 4: Was bedeutet O(n²) genau?

Bisher hieß es „wächst etwa wie n²“. Die formale Definition (unten bei „Das Wichtigste“ zum Nachlesen) macht das genau. Im Video wendest du sie auf summe und Bubblesort an und siehst, warum konstante Faktoren und kleinere Terme wegfallen. Achte auf die Falle: O ist eine obere Schranke – man gibt trotzdem immer die kleinste passende Klasse an.

Zum Nachlesen: Definition, Nachweis und Messung

Die O-Notation beschreibt, wie sich die Laufzeit verhält, wenn die Größe der Eingabe gegen unendlich strebt. Meist gibt man sie für den schlechtesten Fall (worst case) an, man kann sie aber genauso für den besten oder den mittleren Fall verwenden. Ein Algorithmus mit f(n) = 3n² + 5n + 2 Schritten liegt in O(n²), denn für n ≥ 1 gilt 3n² + 5n + 2 ≤ 10 · n².

Beispiel 2 komplex

Ausgangssituation: Für Bubblesort ohne Abbruch soll die Zugehörigkeit zu O(n²) mit der Definition nachgewiesen und mit den Messwerten oben überprüft werden.

  1. Vergleiche zählen: f(n) = n(n − 1)/2 = ½n² − ½n (siehe oben).
  2. Obere Schranke nachweisen: Für alle n ≥ 1 gilt ½n² − ½n ≤ ½n², weil ½n ≥ 0 ist. Mit c = ½ und n0 = 1 ist die Definition erfüllt, also f(n) ∈ O(n²). Warum darf der Term −½n wegfallen: Er verkleinert f nur, und eine obere Schranke darf größer sein.
  3. Falle „obere Schranke“: Nach der Definition gilt auch f(n) ∈ O(n³), denn n² ≤ n³ für n ≥ 1. Diese Aussage ist wahr, aber wenig hilfreich. Man gibt deshalb die kleinste passende Klasse an. Dass f nicht langsamer als quadratisch wächst, zeigt die Gegenrichtung: Für n ≥ 2 ist n − 1 ≥ n/2, also f(n) ≥ ¼n².
  4. Mit den Messwerten prüfen: Bei O(n²) gilt t ≈ c · n². Verdoppelt sich n, vervierfacht sich t.
    VerdopplungZeitenFaktor
    2000 → 4000178 ms → 646 ms≈ 3,6
    6000 → 120001538 ms → 6067 ms≈ 3,9
    8000 → 160002739 ms → 10826 ms≈ 4,0
    Warum ist der erste Faktor kleiner? Vor allem schwanken kurze Messungen stärker. Dazu kommen Anteile, die nicht quadratisch wachsen (Funktionsaufruf, Schleifenverwaltung); sie fallen bei kleinen n etwas mehr ins Gewicht. Je größer n, desto näher liegt der Faktor bei 4.
  5. Selbst messen: Für Laufzeitmessungen nimmt man time.perf_counter(). Diese Uhr ist genauer als time.time() und für Zeitdifferenzen gedacht. 
    import random
import time

def bubblesort(arr):
    n = len(arr)
    for i in range(n - 1):
        for j in range(n - i - 1):
            if arr[j] > arr[j + 1]:
                temp = arr[j]
                arr[j] = arr[j + 1]
                arr[j + 1] = temp

for n in [2000, 4000, 8000]:
    daten = []
    for i in range(n):
        daten.append(random.randint(1, 10**6))
    start = time.perf_counter()
    bubblesort(daten)
    ms = round((time.perf_counter() - start) * 1000)
    print("n =", n, "->", ms, "ms")

Ergebnis: f(n) ∈ O(n²) mit c = ½, n0 = 1. Die Messwerte bestätigen den Faktor ≈ 4 bei Verdopplung von n. Absolute Zeiten hängen vom Rechner ab, der Faktor nicht.

Kurz geprüft 4: Welcher Term gewinnt? AFB I–II

Ein Algorithmus braucht f(n) = 2n² + 100n + 7 Schritte. Welcher Teil ist bei n = 10 größer, 2n² oder 100n + 7? Welcher bei n = 1000? In welcher Komplexitätsklasse liegt f?

Lösung zeigen

n = 10: 2n² = 200, 100n + 7 = 1007 – hier überwiegt noch der lineare Teil. n = 1000: 2n² = 2 000 000, 100n + 7 = 100 007 – jetzt überwiegt der quadratische Teil, und sein Vorsprung wächst weiter. Für große n zählt nur der höchste Term, der Faktor 2 fällt weg: f liegt in O(n²).

Danach: Aufgabe 2.2.3.2 – Komplexität von Programmstücken bestimmen.

Praxisbezug: Skalierung

Alltag: Eine App, die mit 100 Testnutzern flüssig läuft, kann mit 100 000 Nutzern unbenutzbar werden, wenn ein Teil davon in O(n²) arbeitet.

Beruf: Performance-Engineers und Backend-Entwicklerinnen messen Laufzeiten mit Profilern und schätzen mit der O-Notation ab, ob ein System auch bei zehnfacher Last noch reicht. Bei Online-Händlern oder Banken ist das wichtig, bevor sich zum Beispiel am „Black Friday“ die Zugriffe vervielfachen.

Zusammenfassung

Den Aufwand eines Algorithmus misst man in Schritten in Abhängigkeit von der Eingabegröße n. Anweisungen außerhalb von Schleifen zählen einmal, Schleifenrümpfe so oft, wie die Schleife läuft; bei geschachtelten Schleifen addiert man die Durchläufe der inneren Schleife. Die O-Notation fasst das Ergebnis zusammen: Konstante Faktoren und kleinere Terme fallen weg, angegeben wird die kleinste passende Klasse. Messungen bestätigen die Klasse über den Faktor bei Verdopplung von n – bei O(n²) etwa 4.

Einschätzen: zurück zum Streamingdienst

Die Messung im Messlabor ist ein Verdopplungsexperiment. So sieht eine Beispielmessung mit der Songliste aus: Bubblesort sortiert die ersten n Songs nach Streams, ein Zähler zählt die Vergleiche.

nZeitVergleiche
1 0000,143 s497 289
2 0000,585 s1 995 430
4 0001,921 s7 994 172
  1. Bestimme die Klasse aus den Faktoren bei Verdopplung.
  2. Bestimme eine Konstante c mit Zeit ≈ c · n² und sage damit die Zeit für 8 000 Songs und für 100 Millionen Songs voraus. Kontrolliere mit dem Hochrechner.
  3. Ein Mitschüler misst auf einem doppelt so schnellen Rechner. Was ändert sich: c, die Klasse oder beides?
  4. Bearbeite im Messlabor Teil 1–3: Vervollständige Bubblesort mit dem Vergleichszähler, führe das Verdopplungsexperiment durch und füge dein eigenes Verfahren aus 2.2.1 ein. Zu welcher Klasse gehört dein Verfahren?
Lösung zeigen

Vergleiche: Faktor 4,0 und 4,0, Zeit: 4,1 und 3,3 – das passt zu O(n²); die Zeit schwankt stärker als die Zahl der Vergleiche. c ≈ 1,921 s / 4 000² ≈ 1,2 · 10−7 s. Vorhersage: 8 000 Songs ≈ 1,2 · 10−7 · 6,4 · 107 ≈ 7,7 s; 100 Millionen Songs ≈ 1,2 · 10−7 · 1016 ≈ 1,2 · 109 s ≈ 38 Jahre. Auf dem schnelleren Rechner halbiert sich c, die Klasse O(n²) bleibt: Aus 38 werden 19 Jahre. Genau das meint die O-Notation – konstante Faktoren werden weggelassen, weil sie an der Einschätzung „geht“ oder „geht nicht“ nichts ändern. Dein eigenes Verfahren: Wird die Zeit beim Verdoppeln etwa viermal so groß, gehört es ebenfalls zu O(n²) – das gilt für fast alle Verfahren aus dem Kartenspiel. Ob es etwas schneller oder langsamer als Bubblesort ist, ändert an der Klasse nichts.

Das Wichtigste

O-Notation: beschreibt, wie stark der Aufwand eines Algorithmus wächst, wenn die Eingabe größer wird. Man betrachtet nur den am schnellsten wachsenden Teil: Ein Algorithmus mit 3n² + 5n + 2 Schritten liegt in O(n²).

Vereinfachen: Konstante Faktoren und Terme niedrigerer Ordnung werden weggelassen. Angegeben wird die kleinste passende Klasse.

Schritte zählen: Schleifenrümpfe zählen so oft, wie die Schleife läuft; bei geschachtelten Schleifen addiert man die Durchläufe der inneren Schleife.

Verdopplungsexperiment: Messungen bestätigen die Klasse über den Faktor bei Verdopplung von n, bei O(n²) etwa 4.

Zum Nachlesen: formale Definition der O-Notation

Beschreibt f(n) die Anzahl der Schritte eines Algorithmus bei Eingabegröße n, dann bedeutet f(n) ∈ O(g(n)):
Es gibt eine Konstante c > 0 und eine Zahl n0, sodass f(n) ≤ c · g(n) für alle n ≥ n0 gilt.
