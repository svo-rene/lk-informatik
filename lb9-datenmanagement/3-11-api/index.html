3.11 APIs verstehen und nutzen

Einführung 2Übungen 1Vertiefung 2

APIs (Application Programming Interfaces) sind essenziell für die moderne Softwareentwicklung. Sie ermöglichen die Kommunikation zwischen verschiedenen Anwendungen und Systemen und sind aus der heutigen IT-Landschaft nicht mehr wegzudenken.

Praxisbezug: APIs im Bankwesen (Open Banking / PSD2)

Ein sehr konkretes Alltagsbeispiel für APIs findet sich im Finanzsektor: Seit der EU-Zahlungsdiensterichtlinie PSD2 sind Banken verpflichtet, standardisierte, sichere Schnittstellen (APIs) bereitzustellen. Über diese „Open Banking“-APIs können Multibanking-Apps oder Budget-Apps mit Zustimmung der Kundschaft automatisch Kontostände und Umsätze mehrerer Banken abrufen oder sogar Überweisungen direkt auslösen – im Hintergrund laufen dabei ständig API-Anfragen zwischen App, Bank und ggf. weiteren Drittanbietern.

Berufsfelder: Innerhalb der Informatik arbeiten hier z. B. Backend- und API-Entwickler*innen sowie Integrations- und IT-Sicherheitsspezialist*innen, die solche Schnittstellen programmieren, testen und absichern. Außerhalb der klassischen IT sind u. a. Produktmanager*innen bei Fintech-Unternehmen, Bankkaufleute und Bankberater*innen sowie Mitarbeitende in Compliance/Regulatorik und im Business Development (Aufbau von Partnerschaften zwischen Banken und Drittanbietern) beteiligt.

Weiterlesen: Neue und alte Banken-APIs – eine Übersicht (heise online)

Was ist eine API?

Eine API ist eine Schnittstelle, die es ermöglicht, Funktionen und Daten einer Software für andere Anwendungen bereitzustellen. Sie definiert, wie Anfragen gestellt und Antworten empfangen werden. APIs werden oft genutzt, um komplexe Prozesse zu abstrahieren, sodass Entwickler*innen nur die notwendigen Parameter bereitstellen müssen.

Hier stand eine Abbildung, deren Nutzungsrechte für die Webseite nicht geklärt sind.

Warum wird häufig JSON verwendet?

JSON (JavaScript Object Notation) ist ein beliebtes Format für die Datenübertragung in APIs, da es:

  • leicht lesbar und schreibbar für Menschen ist,
  • einfach von Programmen geparst werden kann,
  • kompakt und effizient für die Übertragung ist,
  • nativ in JavaScript unterstützt wird, was es ideal für Webanwendungen macht,
  • aber auch in fast allen anderen modernen Programmiersprachen genutzt werden kann.

Wo findet man Informationen über eine API?

Informationen zu APIs werden typischerweise in der sogenannten API-Dokumentation bereitgestellt. Diese enthält:

  • Details über die verfügbaren Endpunkte und deren Funktionalität,
  • Beispiele für Anfragen und Antworten,
  • Beschreibung der benötigten Parameter,
  • Fehlercodes und deren Bedeutung.

Die Dokumentation wird oft von den Anbietern auf deren Webseite bereitgestellt.

Freie APIs zum Testen

Es gibt viele freie APIs, die ohne Anmeldung oder Authentifizierung genutzt werden können. Beispiele sind:

  • PokeAPI: Daten zu Pokémon.
  • Open-Meteo: Wetterdaten für beliebige Standorte.
  • Cat Facts: Zufällige Fakten über Katzen.

APIs mit Python nutzen

Mit dem Modul requests kannst du eine API direkt aus Python heraus abfragen. Die Methode .json() wandelt die JSON-Antwort automatisch in ein Python-Dictionary bzw. eine Liste um. requests gehört nicht zur Standardbibliothek; auf dem eigenen Rechner installierst du es einmal mit pip install requests (bei Anaconda ist es schon dabei). 

import requests

antwort = requests.get("https://catfact.ninja/fact")
daten = antwort.json()
print(daten["fact"])

Beispiel: Wetterdaten von Open-Meteo abfragen

Bei Open-Meteo übergibst du Breiten- und Längengrad als Parameter in der URL. Die Antwort enthält u. a. die aktuelle Temperatur. 

import requests

url = "https://api.open-meteo.com/v1/forecast"
parameter = {
    "latitude": 52.52,
    "longitude": 13.41,
    "current_weather": True
}

antwort = requests.get(url, params=parameter)
daten = antwort.json()
print("Aktuelle Temperatur in Berlin:", daten["current_weather"]["temperature"], "°C")

params hängt die Parameter automatisch an die Adresse an – die tatsächlich abgerufene URL lautet https://api.open-meteo.com/v1/forecast?latitude=52.52&longitude=13.41&current_weather=True. Die Antwort hat genau den Aufbau der Datei wetter_dresden.json von Seite 3.10.

Komplexeres Beispiel: Statuscode prüfen

Nicht jede Anfrage klappt: Ein falsch geschriebener Name oder ein Serverproblem liefert keinen Datensatz, sondern einen Fehlercode. Deshalb prüft man vor dem Auslesen den Statuscode: 

import requests

name = "pikachuu"          # Tippfehler!
antwort = requests.get(f"https://pokeapi.co/api/v2/pokemon/{name}", timeout=10)

if antwort.status_code == 200:
    daten = antwort.json()
    print(daten["name"], daten["height"])
else:
    print("Fehler", antwort.status_code)     # Fehler 404
Beispiel 1 einfach Eine API-Anfrage lesen und die Antwort ansprechen

Ausgangssituation: In der Dokumentation von Open-Meteo steht die Beispieladresse https://api.open-meteo.com/v1/forecast?latitude=51.05&longitude=13.74&current_weather=true. Die Antwort hat den Aufbau von wetter_dresden.json (Seite 3.10). Gesucht sind die Bestandteile der Anfrage und der Python-Zugriff auf die Windrichtung.

  1. Adresse zerlegen – https:// (verschlüsseltes Protokoll), api.open-meteo.com (Server), /v1/forecast (Endpunkt, v1 = Version der API).
  2. Parameter erkennen – Alles nach dem ? sind Parameter, getrennt durch &: latitude=51.05, longitude=13.74, current_weather=true. In Python übergibt man sie als Dictionary an params; requests baut daraus genau diese Adresse.
  3. Statuscode prüfen – Nur bei 200 steht in der Antwort das erwartete JSON.
  4. Pfad zum Wert bestimmen – In der Antwort liegt winddirection im Objekt current_weather, die Einheit im Objekt current_weather_units.
import json

with open('wetter_dresden.json', encoding='utf-8') as datei:   # statt requests.get(...).json()
    daten = json.load(datei)
print(daten['current_weather']['winddirection'], daten['current_weather_units']['winddirection'])

Ergebnis: Ausgabe 250 ° – der Wind kommt aus Westsüdwest.

Kontrolle: Die Adresse im Browser öffnen: Die Antwort muss ein Objekt current_weather enthalten. Fehlt der Parameter current_weather=true, fehlt auch dieses Objekt – dann gäbe es in Python einen KeyError.

Beispiel 2 komplex Abruf und Auswertung trennen – robust und testbar

Ausgangssituation: Ein Programm soll aus der stündlichen Vorhersage die höchste Temperatur mit Uhrzeit bestimmen. Dabei kann einiges schiefgehen: keine Internetverbindung, ein Fehlercode, eine Antwort ohne die erwarteten Daten oder einzelne fehlende Werte (null). Weil Live-Daten sich ständig ändern, lässt sich die Auswertung nur mit festen Beispielantworten testen.

import json
import requests

def abrufen(lat, lon):
    """Holt die Antwort. Liefert (Statuscode, Text) oder (None, Fehlermeldung)."""
    try:
        antwort = requests.get("https://api.open-meteo.com/v1/forecast",
                               params={"latitude": lat, "longitude": lon,
                                       "hourly": "temperature_2m"},
                               timeout=10)
        return antwort.status_code, antwort.text
    except requests.RequestException as fehler:
        return None, str(fehler)

def auswerten(status, text):
    """Liefert (Maximum, Uhrzeit) oder eine Fehlermeldung als Text."""
    if status is None:
        return "Keine Verbindung"
    if status != 200:
        return f"Fehler {status}"
    daten = json.loads(text)
    stunden = daten.get("hourly")
    if stunden is None:
        return "Antwort ohne Stundenwerte"
    werte = [(t, z) for z, t in zip(stunden["time"], stunden["temperature_2m"]) if t is not None]
    if not werte:
        return "Keine gültigen Messwerte"
    t_max, zeit = max(werte)
    return t_max, zeit[11:]

# live (Ergebnis hängt vom Zeitpunkt ab):
# print(auswerten(*abrufen(51.05, 13.74)))
  1. Trennen – abrufen erledigt nur das Netzwerk, auswerten nur die Verarbeitung. So kann man auswerten mit festen Texten testen, ohne Internet und mit immer gleichem Ergebnis.
  2. Netzwerkfehler abfangen – timeout=10 verhindert endloses Warten; RequestException fängt fehlende Verbindung und Zeitüberschreitung ab.
  3. Statuscode vor dem JSON prüfen – Bei 400 oder 404 enthält die Antwort eine Fehlerbeschreibung, keine Messwerte.
  4. Fehlende Schlüssel – daten.get("hourly") liefert None statt eines KeyError.
  5. Fehlende Einzelwerte – JSON null wird None. max mit None in der Liste bricht mit TypeError ab, deshalb werden solche Paare vorher aussortiert.
  6. Maximum mit Uhrzeit – Die Paare stehen als (Temperatur, Zeit) in der Liste, damit max nach der Temperatur vergleicht; zeit[11:] schneidet das Datum ab.

Ergebnis – Testfälle mit festen Antworten:

Aufruferwartete Ausgabe
auswerten(200, text) mit dem Inhalt von wetter_dresden.json(16.1, '11:00')
auswerten(200, '{"hourly": {"time": ["2026-09-27T08:00", "2026-09-27T09:00"], "temperature_2m": [null, 12.5]}}')(12.5, '09:00')
auswerten(400, '{"error": true, "reason": "Latitude must be in range of -90 to 90°."}')'Fehler 400'
auswerten(200, '{"latitude": 51.06}')'Antwort ohne Stundenwerte'
auswerten(None, 'Connection refused')'Keine Verbindung'

Kontrolle: Jeder Zweig der Funktion wird von mindestens einem Testfall durchlaufen (vier Fehlerfälle, ein Normalfall). Für wetter_dresden.json von Hand: Die Werte 11.9, 13.2, 14.8, 16.1 haben ihr Maximum 16.1 um 11:00 Uhr.

Praxisbezug: API-Schlüssel und Datenschutz

Viele kommerzielle APIs (Kartendienste, Zahlungsanbieter, KI-Dienste) verlangen einen persönlichen API-Schlüssel, über den abgerechnet und begrenzt wird, wie viele Anfragen man stellen darf. Backend-Entwickler*innen achten deshalb darauf, solche Schlüssel nie im Quelltext zu veröffentlichen. Werden über eine API personenbezogene Daten übertragen, etwa Kontodaten beim Open Banking, gilt die DSGVO: Die Übertragung muss verschlüsselt (HTTPS) sein und die Kundschaft muss zugestimmt haben.

Das Wichtigste

API (Application Programming Interface): festgelegte Schnittstelle, über die ein Programm Daten oder Funktionen eines anderen Programms nutzen kann.

Web-API: Das Programm schickt eine HTTP-Anfrage an eine Adresse (Endpunkt), meist mit Parametern.

Antwort: Der Server liefert einen Statuscode (200 = OK, 404 = nicht gefunden) und die Daten, meist im JSON-Format.

In Python: requests.get(url) stellt die Anfrage, .json() macht aus der Antwort Dictionaries und Listen.
