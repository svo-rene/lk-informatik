Rückblick: logische Schaltungen

Bevor wir Programmiersprachen einordnen, lohnt ein Blick zurück: Logische Schaltungen sind die Grundbausteine der Computer-Hardware. Mit ihnen werden logische Operationen wie AND, OR und NOT umgesetzt. Der Volladdierer ist ein Beispiel für eine zusammengesetzte Schaltung, mit der Prozessoren Zahlen addieren. Jede Programmiersprache wird am Ende in Befehle übersetzt, die genau solche Schaltungen ansteuern.

Klassifizierung nach Abstraktionsebene

Maschinensprache

Maschinensprache besteht aus Binärcode, den der Prozessor direkt ausführt. Sie ist für Menschen schwer lesbar und hängt vom jeweiligen Prozessortyp ab.

Maschinennahe Sprachen

Maschinennahe Sprachen wie Assembler liegen eine Ebene über der Maschinensprache. Sie verwenden kurze Textsymbole (Mnemonics) wie ADD oder MOV für die Maschinenbefehle. Obwohl Assembler hardwarenah ist, bietet er eine höhere Abstraktion als reiner Binärcode und erleichtert so die Programmierung.

Höhere Programmiersprachen

Höhere Programmiersprachen sind benutzerfreundlicher und weitgehend unabhängig von der Hardware. Ein Compiler oder Interpreter übersetzt sie in Maschinensprache. So können sich Entwicklerinnen und Entwickler auf die Problemlösung statt auf Hardwaredetails konzentrieren. Beispiele sind Python, Java, C# und JavaScript.

Beispiel 1 einfach Dieselbe Addition auf drei Ebenen

Ausgangssituation: Ein Programm soll zwei Zahlen addieren, z. B. a = 7 und b = 5. Wir vergleichen, wie dieselbe Anweisung auf den drei Abstraktionsebenen aussieht. Im vereinfachten Assembler bedeutet LOAD R1, a „lade den Wert von a in das Register R1“, ADD R1, R2 „R1 := R1 + R2“ und STORE R1, summe „schreibe R1 in die Speicherzelle summe“.

# höhere Programmiersprache (Python)
summe = a + b
# maschinennah (vereinfachter Assembler)
LOAD  R1, a
LOAD  R2, b
ADD   R1, R2
STORE R1, summe

# Maschinensprache (Ausschnitt, binär)
0001 0001 ...  0011 0001 0010 ...
  1. Höhere Sprache: In Python genügt eine Zeile. Wo a und b im Speicher liegen und welches Register rechnet, entscheidet der Interpreter. Deshalb sieht die Zeile auf jedem Rechner gleich aus.
  2. Maschinennah: Im Assembler wird die Zeile in vier Befehle zerlegt: a nach R1 laden, b nach R2 laden, addieren, Ergebnis zurückschreiben. Warum so viele? Der Prozessor rechnet nur mit Registern, nicht direkt mit Variablen im Speicher. Die Registernamen R1, R2 gibt es nur bei einem bestimmten Prozessortyp.
  3. Maschinensprache: Jeder Assemblerbefehl entspricht genau einem Binärbefehl aus Operationscode und Register- bzw. Adressangaben. Diese 1:1-Übersetzung erledigt ein Assembler-Programm. Welche Bitmuster entstehen, hängt vom Befehlssatz des Prozessors ab.

Ergebnis: 1 Python-Zeile → 4 Assemblerbefehle → 4 Maschinenbefehle. Je höher die Abstraktionsebene, desto weniger muss man über die Hardware wissen – und desto mehr Arbeit übernimmt der Übersetzer (Compiler, Interpreter, Assembler).

Kontrolle: Registerinhalte nach jedem Befehl für a = 7 und b = 5:

Die Python-Zeile summe = a + b liefert für dieselben Werte ebenfalls 12.

Klassifizierung nach Programmierparadigma

Die Paradigmen bilden eine Hierarchie. Auf oberster Ebene unterscheidet man imperative und deklarative Programmierung. Darunter liegen die einzelnen Paradigmen:

imperativ – „wie wird das Ergebnis berechnet?“deklarativ – „was soll herauskommen?“
prozeduralobjektorientiertfunktionallogischAbfragesprachen

Imperative Sprachen

In imperativen Sprachen besteht ein Programm aus einer Folge von Anweisungen, die den Zustand (die Werte der Variablen) Schritt für Schritt verändern. Die prozedurale Programmierung gliedert diese Anweisungen in Unterprogramme. Die objektorientierte Programmierung fasst Daten und die zugehörigen Methoden zu Objekten zusammen. Beispiele sind C, C++ und Python.

Deklarative Sprachen

Deklarative Sprachen beschreiben, was erreicht werden soll, und überlassen das Wie dem System.

  • Funktionale Sprachen beschreiben Programme als Zusammensetzung von Funktionen ohne veränderlichen Zustand. Bekannte Vertreter sind Haskell und Lisp. Auch in Python kann man funktional programmieren.
  • Logische Sprachen beschreiben ein Problem durch Fakten und Regeln. Das System leitet daraus Antworten ab. Prolog ist das bekannteste Beispiel.
  • Abfragesprachen wie SQL beschreiben, welche Daten aus einer Datenbank gebraucht werden, nicht wie sie gesucht werden.
Beispiel 2 komplex Die Summe aller geraden Zahlen einer Liste – imperativ und deklarativ

Ausgangssituation: Aus der Liste [3, 8, 5, 12, 7, 4] sollen alle geraden Zahlen addiert werden. Dasselbe Problem wird dreimal gelöst: imperativ in Python, funktional in Python und als SQL-Abfrage. Anschließend ordnen wir jede Lösung in die Paradigmen-Hierarchie ein.

zahlen = [3, 8, 5, 12, 7, 4]

# imperativ: Schritt für Schritt den Zustand (summe) verändern
summe = 0
for z in zahlen:
    if z % 2 == 0:
        summe = summe + z
print(summe)        # 24

# funktional/deklarativ: beschreiben, was berechnet werden soll
print(sum(z for z in zahlen if z % 2 == 0))   # 24
-- deklarativ in SQL (Tabelle zahlen mit Spalte wert)
SELECT SUM(wert) FROM zahlen WHERE wert % 2 = 0;
  1. Imperativ: Die Variable summe startet bei 0. Die Schleife nimmt jede Zahl einzeln, prüft mit z % 2 == 0, ob sie gerade ist, und verändert gegebenenfalls summe. Warum imperativ? Wir legen die Reihenfolge der Schritte und jede Zustandsänderung selbst fest.

  2. Funktional: Der Ausdruck z for z in zahlen if z % 2 == 0 beschreibt „die geraden Zahlen der Liste“ (8, 12, 4), sum addiert sie. Wir verändern keine eigene Variable. Warum deklarativ? Es wird beschrieben, was berechnet wird; wie sum intern zählt, bleibt verborgen.
  3. SQL: WHERE wert % 2 = 0 wählt die passenden Zeilen aus, SUM fasst sie zusammen. In welcher Reihenfolge die Datenbank die Zeilen liest, entscheidet sie selbst.
  4. Einordnung: Lösung 1 gehört zu imperativ → prozedural, Lösung 2 zu deklarativ → funktional, Lösung 3 zu deklarativ → Abfragesprache. Python taucht also an zwei Stellen der Hierarchie auf: Es ist eine Multiparadigmen-Sprache.

Ergebnis: Alle drei Lösungen liefern 24. Die imperative Lösung braucht fünf Zeilen und eine Hilfsvariable, die deklarativen Lösungen je eine Zeile.

Achtung, Sonderfall: In SQL liefert SUM über keine passende Zeile den Wert NULL und nicht 0. Auch bei deklarativen Lösungen muss man also die Sonderfälle der jeweiligen Sprache kennen.

Die Wahl der Programmiersprache hängt von den Anforderungen des Projekts, der Problemstellung und der vorhandenen Erfahrung ab. Viele moderne Sprachen wie Python unterstützen mehrere Paradigmen.

Praxisbezug: Welche Sprache für welchen Job?

Alltag: In deinem Smartphone arbeiten viele Sprachen zusammen: Der Treiber für die Kamera ist hardwarenah in C geschrieben, die App selbst in Kotlin oder Swift (objektorientiert), und die Kontaktsuche fragt eine SQLite-Datenbank mit SQL ab.

Beruf: Embedded-Software-Entwicklerinnen und -Entwickler, etwa bei den Halbleiterherstellern im „Silicon Saxony“ rund um Dresden, programmieren Mikrocontroller in C und lesen dabei auch Assembler-Code, um Laufzeit und Speicher zu optimieren. Datenbankentwickler (z. B. bei Dresdner Softwarefirmen für Verwaltungssoftware) arbeiten dagegen täglich deklarativ mit SQL.

Das Wichtigste

Programmiersprachen lassen sich nach zwei Gesichtspunkten einordnen:
1. nach der Abstraktionsebene: Wie nah ist die Sprache an der Hardware?
2. nach dem Programmierparadigma: Welche Denkweise liegt der Sprache zugrunde?
