Aufgabe 4.10.8: Fehler finden – „ist ein“ oder „hat ein“? AFB III

In einem Entwurf für eine Schul-App finden sich diese Klassen:

class Motor:
    def __init__(self, ps: int):
        self.ps = ps

    def starten(self) -> str:
        return "Brumm"

class Auto(Motor):                       # (1)
    def __init__(self, marke: str, ps: int):
        super().__init__(ps)
        self.marke = marke

class Person:
    def __init__(self, name: str):
        self.name = name

class Lehrkraft(Person):                 # (2)
    def __init__(self, name: str, kuerzel: str):
        self.kuerzel = kuerzel

class Schulklasse(Person):               # (3)
    def __init__(self, bezeichnung: str):
        super().__init__(bezeichnung)
        self.schueler: list[Person] = []

frau_k = Lehrkraft("Frau Krause", "KR")
print(frau_k.kuerzel)
print(frau_k.name)
  1. Sage die Ausgabe des Programms vorher.
  2. Prüfe die drei Vererbungen (1)–(3) mit dem „ist-ein“-Test. Gib bei falscher Vererbung an, welche Beziehung stattdessen passt.
  3. Finde den Programmierfehler in der Klasse, deren Vererbung fachlich richtig ist.
  4. Korrigiere den Code vollständig und gib Testfälle an, die zeigen, dass alles funktioniert.
Aufgabe 4.10.10: Vererbung beurteilen – wenn die Hierarchie explodiert AFB III

In einem Rollenspiel gibt es Ritter und Magier. Nach und nach kamen Fähigkeiten dazu, und das Team hat jedes Mal eine neue Unterklasse angelegt:

Figur
 ├── Ritter
 │    ├── FliegenderRitter
 │    └── SchwimmenderRitter
 └── Magier
      ├── FliegenderMagier
      ├── SchwimmenderMagier
      └── FliegenderSchwimmenderMagier
  1. Beurteile diesen Entwurf. Wie viele Klassen bräuchte man bei 2 Figurtypen und 4 kombinierbaren Fähigkeiten (fliegen, schwimmen, klettern, tauchen), wenn jede Kombination eine eigene Klasse bekommt?
  2. Prüfe mit dem „ist-ein“-Test: Ist „fliegend“ eine Spezialisierung der Figur oder eine Fähigkeit, die eine Figur hat?
  3. Entwirf einen alternativen Aufbau nach dem Grundsatz „Komposition vor Vererbung“ (Klassendiagramm und Python-Skizze). Eine Figur soll eine Fähigkeit auch während des Spiels dazugewinnen können.
