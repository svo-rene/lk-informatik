Schritt 1: 0..1, 1 und * im Code

Jede Multiplizität hat eine typische Form im Code: Genau 1 wird zu einem Pflichtparameter, 0..1 zu einem Attribut, das None sein darf, und * zu einer Liste von Verweisen. Im Video siehst du das am Beispiel Person und Personalausweis. Achte darauf, an welcher Klasse welche Zahl steht und wie die beiden Objekte sich gegenseitig kennen. Neu ist die Zeile from __future__ import annotations, sie wird kurz erklärt.

Zum Nachlesen: Typische Multiplizitäten

Multiplizität Bedeutung Python
1 genau ein Objekt self.fach: Fach
0..1 optional – entweder ein Objekt oder keins self.fach: Fach | None
0..* oder * beliebig viele – auch null self.schueler: list[Schueler]
1..* mindestens eins Liste wie oben, man muss aber sicherstellen, dass sie nicht leer ist (z. B. ein Element schon im Konstruktor verlangen)
1..2 mindestens eins, höchstens zwei Liste mit Prüfung der Unter- und Obergrenze
Beispiel 1 einfach Person und Personalausweis

Ausgangssituation: Ein Personalausweis gehört genau einer Person (1), eine Person hat keinen oder einen gültigen Personalausweis (0..1).

  1. Von beiden Seiten fragen: „Wie viele Ausweise hat eine Person?“ → keinen oder einen, also 0..1. „Wie vielen Personen gehört ein Ausweis?“ → genau einer, also 1. Warum: Jede Seite einer Beziehung hat ihre eigene Multiplizität.
  2. An die richtige Seite schreiben: 0..1 steht beim Personalausweis, 1 bei der Person. Warum: Die Zahl steht immer an der Klasse, deren Anzahl sie angibt.
  3. In Python übersetzen: 0..1 wird zu Personalausweis | None mit Startwert None. Genau 1 wird zu einem Pflichtparameter im Konstruktor, damit kein Ausweis ohne Inhaber entstehen kann.
Person1          0..1
────── besitzt ──────		Personalausweis
+ name: str
+ ausweis: Personalausweis | None		+ nummer: str
+ inhaber: Person
from __future__ import annotations

class Person:
    def __init__(self, name: str):
        self.name: str = name
        self.ausweis: Personalausweis | None = None    # 0..1

class Personalausweis:
    def __init__(self, nummer: str, inhaber: Person):
        self.nummer: str = nummer
        self.inhaber: Person = inhaber                 # genau 1
        inhaber.ausweis = self                         # Gegenrichtung

lea = Person("Lea")
print(lea.ausweis)               # None
a = Personalausweis("AUSWEIS-001", lea)
print(lea.ausweis.nummer)        # AUSWEIS-001
print(a.inhaber.name)            # Lea

Ergebnis: UML: Person 1 ——— 0..1 Personalausweis. Im Code steht 0..1 als optionales Attribut und 1 als Pflichtparameter.

Kontrolle:

Aufruferwartete Ausgabe
print(Person("Ben").ausweis)None (untere Grenze 0 erlaubt)
Personalausweis("AUSWEIS-002")TypeError, weil das Argument inhaber fehlt (untere Grenze 1 durchgesetzt)
Hinweis: Wozu from __future__ import annotations?

In Person steht als Typ schon Personalausweis, obwohl diese Klasse erst weiter unten definiert wird. Viele Typangaben wertet Python sofort aus; ein noch unbekannter Name führt dann zu einem NameError (in der Kommandozeile z. B. bei x: Spaeter = 5). Die Zeile from __future__ import annotations ganz oben in der Datei sorgt dafür, dass Typangaben erst später ausgewertet werden. So können sich zwei Klassen in ihren Typangaben gegenseitig nennen.

Schritt 2: Grenzen durchsetzen – 1..2 im Code

Eine Lehrkraft unterrichtet ein oder zwei Fächer (1..2), ein Fach wird von keiner, einer oder mehreren Lehrkräften unterrichtet (0..*). Diese Grenzen sollen nicht nur im Klassendiagramm stehen: Der Code soll selbst dafür sorgen, dass keine Lehrkraft ohne Fach und keine mit drei Fächern entsteht. Achte im Video auf die Reihenfolge in unterrichtet: erst prüfen, dann ändern. Der Operator in für Listen wird kurz erklärt.

Zum Nachlesen: Lehrkraft unterrichtet Fächer

Lehrkraft 0..*        1..2
◄──── unterrichtet ────► 		Fach
+ name: str
+ faecher: list[Fach]		 + titel: str
+ lehrkraefte: list[Lehrkraft]
+ unterrichtet(fach: Fach): bool + lehrkraft_hinzu(lehrkraft: Lehrkraft): None

Abb. 1: Bidirektionale Assoziation „unterrichtet“ mit Multiplizitäten. „1..2“ steht bei Fach (so viele Fächer hat eine Lehrkraft), „0..*“ steht bei Lehrkraft (so viele Lehrkräfte hat ein Fach).

In Python könnte das so aussehen:

Beispiel 2 komplex Die Multiplizität 1..2 wird im Code durchgesetzt

Ausgangssituation: Das Klassendiagramm in Abb. 1 soll so programmiert werden, dass die Grenzen 1..2 nicht nur auf dem Papier stehen: Keine Lehrkraft ohne Fach, keine mit drei Fächern, und beide Seiten der bidirektionalen Beziehung bleiben stimmig.

from __future__ import annotations
# sorgt dafür, dass Typannotationen erst später ausgewertet werden,
# sodass sich Klassen in Typen gegenseitig referenzieren können


class Lehrkraft:
    MAX_FAECHER: int = 2   # Multiplizität 1..2 auf der Seite von Fach

    def __init__(self, name: str, startfach: Fach):
        self.name: str = name
        self.faecher: list[Fach] = []
        self.unterrichtet(startfach)   # mindestens ein Fach (untere Grenze 1)

    def unterrichtet(self, fach: Fach) -> bool:
        if fach in self.faecher:
            return True                  # Beziehung besteht schon
        if len(self.faecher) >= Lehrkraft.MAX_FAECHER:
            print(f"{self.name} darf höchstens {Lehrkraft.MAX_FAECHER} Fächer unterrichten.")
            return False                 # obere Grenze erreicht: abbrechen
        self.faecher.append(fach)
        fach.lehrkraft_hinzu(self)       # Gegenrichtung pflegen
        return True


class Fach:
    def __init__(self, titel: str):
        self.titel: str = titel
        self.lehrkraefte: list[Lehrkraft] = []   # Multiplizität 0..*

    def lehrkraft_hinzu(self, lehrkraft: Lehrkraft) -> None:
        # wird nur von Lehrkraft.unterrichtet() aufgerufen
        if lehrkraft not in self.lehrkraefte:
            self.lehrkraefte.append(lehrkraft)


# -------------------------
# Beispielaufrufe
# -------------------------

# Fächer anlegen
mathe = Fach("Mathematik")
info = Fach("Informatik")
physik = Fach("Physik")

# Lehrkräfte anlegen: jede braucht ein Startfach
lisa = Lehrkraft("Lisa Müller", mathe)
tom = Lehrkraft("Tom Schneider", mathe)

# weitere Beziehungen herstellen
lisa.unterrichtet(info)
tom.unterrichtet(physik)
tom.unterrichtet(info)    # drittes Fach: wird abgelehnt

for lk in (lisa, tom):
    print(lk.name, "->", [f.titel for f in lk.faecher])
for f in (mathe, info, physik):
    print(f.titel, "->", [lk.name for lk in f.lehrkraefte])

# Ausgabe:
# Tom Schneider darf höchstens 2 Fächer unterrichten.
# Lisa Müller -> ['Mathematik', 'Informatik']
# Tom Schneider -> ['Mathematik', 'Physik']
# Mathematik -> ['Lisa Müller', 'Tom Schneider']
# Informatik -> ['Lisa Müller']
# Physik -> ['Tom Schneider']
  1. Untere Grenze 1 durchsetzen: Der Konstruktor verlangt ein startfach und ruft sofort unterrichtet(startfach) auf. Warum: So kann keine Lehrkraft ohne Fach entstehen.
  2. Obere Grenze 2 durchsetzen: unterrichtet() prüft vor dem Anhängen len(self.faecher) >= MAX_FAECHER. Warum: Die Prüfung muss vor der Änderung stehen, sonst wäre das dritte Fach schon eingetragen.
  3. Reihenfolge der Prüfungen: Zuerst wird geprüft, ob die Beziehung schon besteht. Warum: Ruft man lisa.unterrichtet(mathe) ein zweites Mal auf, soll das weder ein Duplikat erzeugen noch als „drittes Fach“ abgelehnt werden.
  4. Gegenrichtung pflegen: Nach dem Anhängen ruft unterrichtet() selbst fach.lehrkraft_hinzu(self) auf. Warum: Bei einer bidirektionalen Assoziation müssen beide Listen zueinander passen.
  5. Ablauf tom.unterrichtet(info): Tom hat schon [Mathematik, Physik]. Info ist nicht enthalten, aber 2 >= 2 ist wahr, also erscheint die Meldung, und False wird zurückgegeben. Diese Meldung steht in der Ausgabe ganz oben, weil sie vor den beiden for-Schleifen gedruckt wird.

Ergebnis: Siehe Ausgabe im Code: Jede Lehrkraft hat 1 oder 2 Fächer, und die Listen beider Seiten stimmen überein.

Kontrolle:

Aufruf (nach dem Programm oben)erwartete Ausgabe
print(lisa.unterrichtet(mathe), len(lisa.faecher))True 2 (kein Duplikat)
print(tom.unterrichtet(info))Meldung „Tom Schneider darf höchstens 2 Fächer unterrichten.“, dann False
kim = Lehrkraft("Kim Berg", physik); print(len(kim.faecher), len(physik.lehrkraefte))1 2
Hinweis: Warum speichert auch das Fach seine Lehrkräfte?

Wenn die Beziehung bidirektional ist, müssen sich die Objekte gegenseitig kennen: Die Lehrkraft kennt ihre Fächer, das Fach seine Lehrkräfte. Beide Seiten müssen dann immer gemeinsam aktualisiert werden. Deshalb ruft unterrichtet() selbst lehrkraft_hinzu() auf – so kann man die Gegenrichtung nicht vergessen.

Praxisbezug: Multiplizitäten als Geschäftsregeln

Alltag: „Ein Konto gehört mindestens einem Inhaber, ein Kunde kann beliebig viele Konten haben“ oder „Pro Bestellung mindestens ein Artikel“ – solche Regeln begegnen dir beim Online-Banking oder im Webshop.

Beruf: Multiplizitäten werden in der Softwareentwicklung zu Datenbankregeln (Fremdschlüssel, Pflichtfelder) und zu Prüfungen im Code. Anforderungsanalystinnen und -analysten klären sie früh mit dem Kunden, denn eine falsch gewählte Multiplizität („ein Kunde hat genau eine Adresse“) ist später nur mit viel Aufwand zu ändern.

Das Wichtigste

Die Multiplizität gibt an, wie viele Objekte an einer Beziehung beteiligt sein können – z. B. genau eins, keins oder eins, oder beliebig viele. Sie wird in der Form untere..obere Grenze an das Ende der Beziehungslinie geschrieben, und zwar an die Klasse, deren Anzahl beschrieben wird: Die Zahl beim Fach sagt, wie viele Fächer eine Lehrkraft hat.

Grundaufgaben

Kurz geprüft 1: Vom Satz zum Attribut AFB I

Ein Fahrrad hat genau einen Rahmen (wird im Konstruktor übergeben), keinen oder einen Korb und beliebig viele Aufkleber. Wie lauten die drei Attribute im Konstruktor mit Typ und Startwert?

Lösung zeigen

self.rahmen: Rahmen = rahmen (1, Pflichtparameter), self.korb: Korb | None = None (0..1), self.aufkleber: list[Aufkleber] = [] (*, eine Liste von Verweisen, anfangs leer).

Kurz geprüft 2: Warum so und nicht anders? AFB I

(a) Warum schreibt der Konstruktor nicht einfach self.faecher = [startfach], sondern ruft self.unterrichtet(startfach) auf? (b) Was müsste man ändern, damit eine Lehrkraft bis zu drei Fächer unterrichten darf?

Lösung zeigen

(a) Mit [startfach] würde die Gegenrichtung fehlen: Das Fach wüsste nichts von der Lehrkraft. Über unterrichtet laufen alle Änderungen durch dieselben Prüfungen und pflegen beide Seiten. (b) Nur das Klassenattribut: MAX_FAECHER: int = 3. Prüfung und Meldung lesen den Wert von dort.
