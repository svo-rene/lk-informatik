Software kann auf viele verschiedene Arten entwickelt werden – und das ist auch gut so. Unterschiedliche Probleme erfordern unterschiedliche Herangehensweisen. Deshalb gibt es verschiedene Programmierparadigmen: Denkmodelle, mit denen Entwicklerinnen und Entwickler ihre Programme strukturieren.

Profis in der Softwareentwicklung nutzen je nach Anwendung unterschiedliche Paradigmen – oft sogar mehrere gleichzeitig. Webserver und Apps werden häufig objektorientiert entworfen. Bei der Datenanalyse und im Machine Learning werden Daten oft deklarativ (z. B. mit SQL) abgefragt und funktional in „Pipelines“ weiterverarbeitet. Regelbasierte Expertensysteme arbeiten logisch. Wer sich in der Informatik auskennt, sollte die wichtigsten Paradigmen kennen – und verstehen.

Imperatives Paradigma

„Sag dem Computer genau, was er tun soll.“
Im Mittelpunkt steht eine klare Abfolge von Anweisungen. Jede Anweisung kann den Zustand des Programms (die Werte der Variablen) ändern. 

let a = 5;
let b = 10;
let sum = a + b;
console.log(sum);

Teste es z. B. online unter jsfiddle.net.

Deklaratives Paradigma

„Beschreibe, was du willst – nicht, wie es passieren soll.“
Beschrieben wird das gewünschte Ergebnis, nicht der konkrete Ablauf. 

SELECT id, username, description
FROM users
WHERE description = 'Info LK > alles';

Teste SQL-Anfragen z. B. auf sqliteonline.com.

Funktionales Paradigma

„Nutze reine Funktionen – ohne Seiteneffekte.“
Die funktionale Programmierung setzt Programme aus Funktionen zusammen, die für dieselbe Eingabe immer dieselbe Ausgabe liefern und keinen veränderbaren Zustand nutzen. 

zahlen = [1, 2, 3, 4, 5]
quadrate = list(map(lambda x: x * x, zahlen))
print(quadrate)            # [1, 4, 9, 16, 25]

def fakultaet(n):
    if n == 0:
        return 1
    else:
        return n * fakultaet(n - 1)

print(fakultaet(5))        # 120

Teste es z. B. auf replit.com.

Logisches Paradigma

„Definiere Fakten und Regeln – der Computer zieht Schlüsse.“
Gut geeignet für Probleme, die sich durch Fakten und logische Regeln beschreiben lassen. 

vogel(pinguin).
vogel(amsel).

kann_fliegen(X) :- vogel(X), X \= pinguin.

?- kann_fliegen(amsel).
% Antwort: true

Teste es in SWISH Prolog.

Objektorientiertes Paradigma (OOP)

„Denke in Objekten – mit Eigenschaften und Fähigkeiten.“
Hier bildest du Dinge der realen Welt nach: Ein Hund hat einen Namen und eine Rasse – und kann bellen. 

class Hund:
    def __init__(self, name, rasse):
        self.name = name
        self.rasse = rasse

    def bellen(self):
        print(f"{self.name} (Rasse: {self.rasse}) bellt!")

mein_hund = Hund("Bello", "Dackel")
mein_hund.bellen()         # Bello (Rasse: Dackel) bellt!

Teste Python-Code z. B. auf replit.com.

Beispiel 1 einfach Summe von 1 bis 10

Ausgangssituation: Summe von 1 bis 10 – imperativ mit Schleife (s = 0; for i in range(1, 11): s += i) oder funktional mit sum(range(1, 11)). Beide liefern 55.

# imperativ
s = 0
for i in range(1, 11):
    s += i
print(s)                    # 55

# funktional
print(sum(range(1, 11)))    # 55
  1. Imperativ – Startzustand festlegen: s = 0. Warum? Die Summe wird schrittweise in einer Variablen aufgebaut, die vorher einen definierten Wert braucht.
  2. Imperativ – Zustand in jedem Durchlauf ändern: range(1, 11) liefert 1, 2, …, 10 (die 11 ist nicht dabei). s durchläuft die Werte 1, 3, 6, 10, 15, 21, 28, 36, 45, 55. Warum imperativ? Wir schreiben dem Computer jeden einzelnen Rechenschritt vor.
  3. Funktional – Ergebnis beschreiben: sum(range(1, 11)) sagt nur „Summe der Zahlen von 1 bis 10“. Es gibt keine Variable, die wir verändern. Warum funktional? Das Ergebnis entsteht durch Zusammensetzen der Funktionen range und sum; derselbe Aufruf liefert immer dasselbe Ergebnis.

Ergebnis: Beide Programme geben 55 aus. Die imperative Lösung zeigt den Weg, die funktionale das Ziel.

Kontrolle: Mit der Gaußschen Summenformel gilt 10 · 11 / 2 = 55. Ersetzt man 11 durch n + 1, ergeben sich diese Testfälle:

obere Grenze nerwartete Ausgabe (beide Varianten)

1005050
Beispiel 2 komplex Dieselbe Aufgabe „Namen aller volljährigen Personen, alphabetisch“ in vier Paradigmen

Ausgangssituation: Gegeben sind drei Personen mit Name und Alter: Mia (17), Ben (19), Ala (21). Gesucht sind die Namen aller Volljährigen in alphabetischer Reihenfolge. Dasselbe Problem wird imperativ, funktional, objektorientiert, logisch (Prolog) und zum Vergleich in SQL gelöst.

personen = [("Mia", 17), ("Ben", 19), ("Ala", 21)]

# imperativ
ergebnis = []
for name, alter in personen:
    if alter >= 18:
        ergebnis.append(name)
ergebnis.sort()

# funktional
ergebnis = sorted(name for name, alter in personen if alter >= 18)

# objektorientiert
class Person:
    def __init__(self, name, alter):
        self.name = name
        self.alter = alter
    def ist_volljaehrig(self):
        return self.alter >= 18

objekte = [Person(n, a) for n, a in personen]
ergebnis = sorted(p.name for p in objekte if p.ist_volljaehrig())
print(ergebnis)            # ['Ala', 'Ben']
-- deklarativ in SQL
SELECT name FROM personen WHERE alter >= 18 ORDER BY name;
% logisch in Prolog (SWI-Prolog)
person(mia, 17).
person(ben, 19).
person(ala, 21).

volljaehrig(Name) :- person(Name, Alter), Alter >= 18.

?- volljaehrig(X).
X = ben ;
X = ala.

?- setof(X, volljaehrig(X), Liste).
Liste = [ala, ben].
  1. Imperativ: Die Liste ergebnis wird schrittweise verändert: [] → ['Ben'] → ['Ben', 'Ala'] → nach sort() ['Ala', 'Ben']. Mia wird übersprungen, weil 17 >= 18 falsch ist. Warum imperativ? Jeder Schritt und jede Änderung ist ausdrücklich vorgeschrieben.
  2. Funktional: sorted(…) erzeugt aus dem Ausdruck „Namen aller Personen mit alter >= 18“ eine neue, sortierte Liste. Nichts wird nachträglich verändert. Warum? Funktionen ohne Seiteneffekte sind leicht zu testen: gleiche Eingabe, gleiche Ausgabe.
  3. Objektorientiert: Name und Alter werden mit der Methode ist_volljaehrig() zu einem Person-Objekt gebündelt. Statt das Alter von außen zu prüfen, „fragt“ man das Objekt. Warum? Die Regel „ab 18“ steht an genau einer Stelle – bei der Person, zu der sie gehört.
  4. Logisch: Prolog bekommt nur Fakten (person(…)) und eine Regel. Bei der Anfrage volljaehrig(X) probiert es die Fakten der Reihe nach: mia scheitert an 17 >= 18, dann folgt X = ben; nach ; sucht Prolog weiter (Backtracking) und findet X = ala. Danach gibt es keine Alternativen mehr, deshalb steht dort ein Punkt. setof sammelt alle Lösungen und sortiert sie. Namen werden kleingeschrieben, weil großgeschriebene Wörter in Prolog Variablen sind.
  5. SQL: Die Abfrage beschreibt Bedingung (WHERE) und Sortierung (ORDER BY); wie gesucht wird, entscheidet die Datenbank.

Ergebnis: Alle Varianten liefern Ala und Ben in dieser Reihenfolge – Python ['Ala', 'Ben'], Prolog Liste = [ala, ben]. Imperativ und objektorientiert wird ein Ablauf vorgegeben, funktional, logisch und in SQL wird das gewünschte Ergebnis beschrieben.

Kontrolle: Testfälle für die drei Python-Varianten. Die Falle liegt beim Grenzfall „genau 18“: Mit > 18 statt >= 18 würde Tom fehlen.

Eingabe personenerwartete Ausgabe
[("Mia", 17), ("Ben", 19), ("Ala", 21)]['Ala', 'Ben']
[("Tom", 18)]['Tom']
[("Zoe", 30), ("Max", 16), ("Eda", 18)]['Eda', 'Zoe']
[("Mia", 17)][]

Sonderfall in Prolog: Gibt es keine einzige volljährige Person, findet setof keine Lösung und antwortet mit false. statt mit einer leeren Liste.

Hinweis: Warum wir in der Schule OOP vertiefen

Objektorientierung ist in der Praxis allgegenwärtig: Fast jede moderne App, jede Website, viele Spiele und technische Systeme nutzen objektorientierte Programmierung. Deshalb ist OOP nicht nur im Lehrplan verankert, sondern ein praxisrelevantes Fundament für alle, die Software entwickeln wollen.

Praxisbezug: Paradigmen im Berufsalltag

Alltag: Die Suche in einer Online-Bibliothek („alle Bücher von Autorin X nach 2020“) ist eine deklarative Datenbankabfrage; die App, die dir die Ergebnisse anzeigt, ist objektorientiert programmiert.

Beruf: Eine Full-Stack-Entwicklerin schreibt an einem Tag objektorientierten Code für das Backend (z. B. in Java oder Python), SQL-Abfragen für die Datenbank und funktionalen JavaScript-Code für die Weboberfläche. Das Wechseln zwischen Paradigmen gehört in Softwarefirmen – auch in der wachsenden IT-Branche in Dresden und Leipzig – zum normalen Arbeitsalltag.

Jedes Paradigma hat seine Stärken. Als Entwicklerin oder Entwickler solltest du flexibel entscheiden können, welches Denkmodell zu welchem Problem passt. Wir steigen jetzt tiefer in das objektorientierte Paradigma ein, denn es bildet die Grundlage vieler moderner Programme.

Das Wichtigste

Programmierparadigma: Ein grundlegender Denkstil der Programmierung. Es legt fest, wie ein Problem betrachtet und wie ein Programm zu seiner Lösung aufgebaut wird.

Imperativ: Eine Folge von Anweisungen verändert schrittweise den Zustand.

Objektorientiert (OOP): Daten und Verhalten werden in Objekten gebündelt; reale Dinge werden mit Klassen und Objekten abgebildet. Das macht große Programme strukturiert und leichter weiterzuentwickeln.

Funktional: Programme bestehen aus Funktionen ohne Seiteneffekte.

Logisch: Man beschreibt Fakten und Regeln, aus denen das System Antworten ableitet.
