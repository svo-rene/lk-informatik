Kurz geprüft 3: Konfliktmarkierungen lesen AFB I

In einer Datei steht nach einem Konflikt:

<<<<<<< main
punkte_pro_aufgabe = 10
=======
punkte_pro_aufgabe = 5
>>>>>>> 13-punkte

Welche Zeile stammt aus welchem Branch? Was muss vor dem Commit auf jeden Fall aus der Datei verschwinden? Kann Git hier selbst entscheiden?

Lösung zeigen

punkte_pro_aufgabe = 10 ist die Fassung von main, punkte_pro_aufgabe = 5 die von 13-punkte. Die drei Markierungszeilen (<<<<<<< main, =======, >>>>>>> 13-punkte) müssen weg, sonst läuft das Programm nicht. Git kann nicht entscheiden, weil beide Branches dieselbe Zeile verschieden geändert haben – welcher Wert gilt, muss die Gruppe nach der Spezifikation festlegen.

Aufgabe 5.4.2: Pull Request und Review üben – zu zweit AFB I–II

Arbeitet zu zweit an zwei Rechnern. Person A legt das private Repository uebung-pr-<name> mit README an und trägt B unter Einstellungen → „Mitarbeiter“ mit Schreibrechten ein (wie in 10.3).

  1. Jede Person legt ein Issue an: „Steckbrief von <Vorname> anlegen“ mit zwei Akzeptanzkriterien als Aufgabenliste und weist es sich selbst zu.
  2. Jede Person legt die Datei steckbrief_<vorname>.md mit drei Zeilen an (Lieblingsfach, Hobby, ein Satz zum Projekt) – mit neuem Branch <issue-nr>-steckbrief-<vorname> und Pull Request, Commit-Nachricht mit Issue-Nummer, im PR „Schließt #…“.
  3. Jede Person reviewt den PR der anderen: einen Zeilenkommentar schreiben, dann zustimmen. Der Autor ergänzt auf seinem Branch eine vierte Zeile und mergt danach.
  4. Konflikt erzeugen: Beide ändern jetzt – jeweils auf einem neuen Branch – die erste Zeile der README.md unterschiedlich und stellen einen PR. A mergt zuerst. Beschreibt, was B in seinem PR sieht, und löst den Konflikt wie in Beispiel 2.
  5. Öffnet die Graph-Ansicht der Commits und skizziert den Verlauf. Prüft: Ist jedes Issue geschlossen? Liegt außer der README-Initialisierung und den Merge-Commits kein Commit direkt auf main?
Aufgabe 5.4.3: Ein Review schreiben AFB II

Ilka stellt einen Pull Request für Issue #12: „Als Schülerin möchte ich nach einer Runde sehen, wie viel Prozent ich richtig hatte.“ Akzeptanzkriterien: Jede Aufgabe zählt höchstens einmal; bei einer Runde ohne Aufgaben erscheint 0 %; Prozent als ganze Zahl, abgerundet. Neue Datei im PR:

 1  # runde.py
 2  class Runde:
 3      def __init__(self, aufgaben):
 4          self.aufgaben = aufgaben
 5          self.richtig = 0
 6
 7      def antworten(self, nr, antwort):
 8          if self.aufgaben[nr].loesung() == antwort:
 9              self.richtig += 1
10              print("Richtig!")
11
12      def prozent(self):
13          return self.richtig / len(self.aufgaben) * 100

Mit drei Aufgaben (3·4, 6·7, 8·8) und den Aufrufen antworten(0, 12), antworten(0, 12), antworten(1, 40) liefert prozent() den Wert 66.66666666666666.

  1. Formuliere mindestens vier Review-Kommentare im Muster Zeile, Problem, Vorschlag. Mindestens zwei sollen Akzeptanzkriterien betreffen, mindestens einer MVC oder Kapselung.
  2. Entscheide, ob du Zustimmen, Kommentieren oder Änderung anfordern wählst, und begründe.
  3. Schreibe die überarbeitete Klasse und drei Tests mit assert, die zu den Akzeptanzkriterien passen.

Aufgabe 5.4.5: Konflikt oder nicht? AFB II

In main steht in aufgabe.py:

1  class Aufgabe:
2      def __init__(self, a: int, b: int):
3          self.__a = a
4          self.__b = b
5
6      def text(self) -> str:
7          return f"{self.__a} · {self.__b} = ?"
8
9      def loesung(self) -> int:
10         return self.__a * self.__b

Von diesem Stand aus ändern zwei Branches:

  • Branch 14-text: Zeile 7 wird zu return f"Was ist {self.__a} mal {self.__b}?"; außerdem eine neue Datei test_aufgabe.py.
  • Branch 15-hinweis: Zeile 7 wird zu return f"{self.__a} · {self.__b} = ? (ohne Rechner)"; Zeile 10 bleibt; am Dateiende kommt eine Methode ist_leicht(self) -> bool dazu.

14-text wird zuerst gemergt.

  1. Gib für jede der drei Änderungen von 15-hinweis an, ob sie beim Merge einen Konflikt auslöst. Begründe.
  2. Gib den Ausschnitt von aufgabe.py mit Konfliktmarkierungen an, so wie Git ihn erzeugen würde.
  3. Löse den Konflikt sinnvoll und gib die Zeile 7 an.
