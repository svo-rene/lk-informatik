Aufgabe 4.7.5: Typen aus der Verwendung ableiten – Playlist AFB II

Für eine Lern-Playlist-App liegt diese Klasse ohne Typangaben vor:

class Playlist:
    def __init__(self, name):
        self.name = name
        self.titel = []            # Einträge: (Titel, Dauer in Sekunden)
        self.oeffentlich = False

    def hinzufuegen(self, titel, dauer):
        self.titel.append((titel, dauer))

    def gesamtdauer(self):
        return sum(d for _, d in self.titel)

    def laengster(self):
        if not self.titel:
            return None
        return max(self.titel, key=lambda t: t[1])[0]
  1. Ergänze alle Typangaben für Parameter, Rückgabewerte und Attribute. Begründe besonders die Typen von titel und laengster().

Aufgabe 4.7.7: Kinokasse – UML mit Typen in Code übersetzen AFB II

Ein kleines Programmkino möchte Reservierungen verwalten. Das Klassendiagramm steht schon:

Kinovorstellung
+ film: str
+ saal: int
+ preis: float
− __plaetze_frei: int
− __reservierungen: dict[str, int]
+ get_plaetze_frei(): int
+ reservieren(name: str, anzahl: int): bool
+ stornieren(name: str): int
+ umsatz(): float
  • Der Konstruktor erhält film, saal, die Anzahl der Plätze und den Preis; zu Beginn gibt es keine Reservierungen.
  • reservieren gelingt nur für mindestens 1 Platz und höchstens so viele, wie frei sind. Reserviert ein Name ein zweites Mal, werden die Plätze addiert.
  • stornieren löscht die Reservierung eines Namens und gibt die Zahl der frei gewordenen Plätze zurück (0, wenn es keine gab).
  • umsatz ist die Zahl aller reservierten Plätze mal Preis.
