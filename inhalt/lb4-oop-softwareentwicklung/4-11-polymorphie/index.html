In der objektorientierten Programmierung kommunizieren Objekte miteinander über sogenannte Botschaften. Eine Botschaft ist dabei ein Methodenaufruf an ein Objekt. 

app.sende_nachricht()

Das Objekt app erhält die Botschaft sende_nachricht und reagiert darauf. Wie genau es reagiert, hängt von seiner konkreten Klasse ab.

Schritt 1: Gleiche Botschaft, anderes Verhalten

Der Begriff Polymorphie bedeutet „Vielgestaltigkeit“. In der OOP beschreibt er, dass unterschiedliche Objekte auf die gleiche Botschaft unterschiedlich reagieren können. Dadurch kann man Objekte verschiedener Klassen einheitlich ansprechen, ohne ihre konkrete Umsetzung zu kennen.

Im Video bekommen ein WhatsApp- und ein Signal-Objekt dieselbe Botschaft sende_nachricht(). Achte rechts darauf, in welcher Klasse Python die Methode findet – und dass die Fassung der Oberklasse Messenger gar nicht erreicht wird.

Kurz geprüft 1: Wer antwortet? AFB I

Was geben d = Discord() und dann d.sende_nachricht() aus, und in welcher Klasse findet Python die Methode? Was gibt m = Messenger() und m.sende_nachricht() aus?

Lösung zeigen

Discord postet die Nachricht in einen Channel. – Python findet sende_nachricht schon in Discord. Ein Objekt der Oberklasse selbst benutzt die Fassung von Messenger: Nachricht wird gesendet ...

Schritt 2: Eine Schleife über verschiedene Objekte

Besonders häufig wird Polymorphie in Schleifen oder Funktionen genutzt, die mit unterschiedlichen Objekten arbeiten, ohne deren genaue Klasse zu kennen.

def nachrichten_testen(liste):
    for app in liste:
        app.sende_nachricht()

Der Code bleibt übersichtlich und muss nicht angepasst werden, wenn neue App-Typen hinzukommen.

Im Video läuft die Schleife aus Beispiel 1 Durchlauf für Durchlauf. Achte darauf, worauf app gerade verweist und welche Methode deshalb gelb markiert ist – die Programmzeile app.sende_nachricht() bleibt immer dieselbe. Am Ende wird isinstance kurz erklärt.

Zum Nachlesen steht der Code aus beiden Videos mit Erklärung und Testfällen in Beispiel 1:

Beispiel 1 einfach Messenger-Apps

Ausgangssituation: Ein Programm soll über mehrere Messenger dieselbe Nachricht verschicken. Jeder Messenger verschickt anders.

class Messenger:
    def sende_nachricht(self):
        print("Nachricht wird gesendet ...")

class WhatsApp(Messenger):
    def sende_nachricht(self):
        print("WhatsApp sendet eine Nachricht mit Lesebestätigung.")

class Signal(Messenger):
    def sende_nachricht(self):
        print("Signal sendet eine verschlüsselte Nachricht.")

class Discord(Messenger):
    def sende_nachricht(self):
        print("Discord postet die Nachricht in einen Channel.")

apps = [WhatsApp(), Signal(), Discord()]
for app in apps:
    app.sende_nachricht()

# Ausgabe:
# WhatsApp sendet eine Nachricht mit Lesebestätigung.
# Signal sendet eine verschlüsselte Nachricht.
# Discord postet die Nachricht in einen Channel.

Obwohl immer dieselbe Botschaft sende_nachricht() gesendet wird, verhält sich jede App anders. Genau das bezeichnet man als Polymorphie.

  1. Gemeinsame Botschaft festlegen: Die Oberklasse Messenger definiert sende_nachricht(). Warum: Damit steht fest, dass jeder Messenger diese Botschaft versteht.
  2. In jeder Unterklasse überschreiben: WhatsApp, Signal und Discord liefern jeweils ihre eigene Umsetzung.
  3. Erster Schleifendurchlauf: app verweist auf ein WhatsApp-Objekt. Python sucht sende_nachricht zuerst in WhatsApp, findet sie dort und führt sie aus. Die Methode der Oberklasse wird nicht erreicht.
  4. Weitere Durchläufe: Dieselbe Zeile app.sende_nachricht() führt nun Signal.sende_nachricht bzw. Discord.sende_nachricht aus. Welche Methode läuft, entscheidet sich erst zur Laufzeit am konkreten Objekt.

Ergebnis: drei unterschiedliche Ausgabezeilen aus einer einzigen Programmzeile (siehe Kommentar im Code).

Kontrolle:

Aufruferwartete Ausgabe
Messenger().sende_nachricht()Nachricht wird gesendet ...
class Threema(Messenger): pass, dann Threema().sende_nachricht()Nachricht wird gesendet ... (nicht überschrieben, also geerbt)
Kurz geprüft 2: Eine Schleife, drei Objekte AFB I

Zu den Klassen aus Beispiel 1 kommt class Threema(Messenger): pass. Was gibt die Schleife for app in [Signal(), Threema(), Signal()]: mit app.sende_nachricht() aus? Und was ergibt isinstance(Threema(), Messenger)?

Lösung zeigen

Drei Zeilen: Signal sendet eine verschlüsselte Nachricht., Nachricht wird gesendet ... (Threema überschreibt nichts, Python findet die Methode erst in Messenger) und noch einmal Signal sendet eine verschlüsselte Nachricht. isinstance(Threema(), Messenger) ergibt True.

Beispiel 2 komplex Flächen verschiedener Formen – ohne if-Kette

Ausgangssituation: Ein Programm für einen Fliesenleger soll die Gesamtfläche einer Liste verschiedener Formen berechnen. Später sollen weitere Formen dazukommen, ohne die Berechnung umzuschreiben. Das Klassendiagramm:

Abb. 1: Rechteck und Kreis überschreiben flaeche() der Oberklasse Form

import math

class Form:
    def flaeche(self) -> float:
        raise NotImplementedError("Jede Form muss flaeche() umsetzen")

class Rechteck(Form):
    def __init__(self, a, b):
        self.a, self.b = a, b
    def flaeche(self):
        return self.a * self.b

class Kreis(Form):
    def __init__(self, r):
        self.r = r
    def flaeche(self):
        return math.pi * self.r ** 2

formen = [Rechteck(3, 4), Kreis(1), Rechteck(2, 2)]
print(round(sum(f.flaeche() for f in formen), 2))   # 19.14

# ohne Polymorphie bräuchte man:
# if type(f) == Rechteck: ... elif type(f) == Kreis: ...
# und müsste diese Stelle bei jeder neuen Form ändern.
  1. Schnittstelle in der Oberklasse: Form.flaeche() löst NotImplementedError aus. Warum: Eine „Form an sich“ hat keine Fläche. Die Methode legt nur fest, dass jede Unterklasse flaeche() anbieten muss.
  2. Überschreiben in den Unterklassen: Rechteck rechnet a · b, Kreis rechnet π · r².
  3. Polymorpher Aufruf: Im Generatorausdruck f.flaeche() for f in formen erhält jedes Objekt dieselbe Botschaft. Werte: Rechteck(3, 4) → 12, Kreis(1) → 3.14159…, Rechteck(2, 2) → 4.
  4. Summieren und runden: 12 + 3.14159… + 4 = 19.14159…, round(…, 2) ergibt 19.14.
  5. Erweitern ohne Änderung: Eine neue Klasse Dreieck(Form) mit eigener flaeche() kann sofort in die Liste; die Summenzeile bleibt gleich. Falle: Vergisst die neue Klasse flaeche(), wird die Methode der Oberklasse geerbt, und die Summe bricht mit NotImplementedError: Jede Form muss flaeche() umsetzen ab. Der Fehler fällt also auf, statt still eine falsche Fläche zu liefern.

Ergebnis: Ausgabe 19.14.

Kontrolle:

print(Kreis(1).flaeche())3.141592653589793

Hinweis: Schnittstellen und „Duck Typing“

Wenn verschiedene Klassen dieselbe Methode besitzen, spricht man von einer gemeinsamen Schnittstelle. Eine Schnittstelle beschreibt also, was ein Objekt können muss – nicht, wie es das umsetzt.
In Python funktioniert Polymorphie sogar ohne gemeinsame Oberklasse: Es genügt, dass das Objekt die aufgerufene Methode besitzt („Wenn es watschelt wie eine Ente und quakt wie eine Ente, ist es eine Ente“ – Duck Typing). Im Projekt (siehe Kurs „Softwareentwicklung“, Seite 4.12) nutzt du Schnittstellen, um deine Klassen austauschbar zu machen.

Warum ist Polymorphie so wichtig?

  • Austauschbarkeit: Objekte können ersetzt werden, ohne den restlichen Code zu ändern.
  • Erweiterbarkeit: Neue Klassen lassen sich leicht hinzufügen.
  • Übersichtlichkeit: Der Code arbeitet mit allgemeinen Begriffen statt mit Spezialfällen.
Praxisbezug: Polymorphie überall

Alltag: Die Taste „Teilen“ auf deinem Smartphone sendet immer dieselbe Botschaft – ob das Ziel ein Messenger, ein E-Mail-Programm oder die Cloud ist, entscheidet das jeweilige Objekt.

Beruf: Druckertreiber, Zahlungsanbieter im Onlineshop (PayPal, Kreditkarte, Rechnung) oder Sensoren in der Industrie werden über gemeinsame Schnittstellen angesprochen. Softwareentwicklerinnen und -entwickler können so einen neuen Zahlungsanbieter einbauen, indem sie nur eine neue Klasse schreiben – der restliche Shop bleibt unverändert. Das spart in großen Projekten viel Test- und Wartungsaufwand.

Zusammenfassung

Objekte reagieren auf Botschaften, also auf Methodenaufrufe. Polymorphie heißt: Dieselbe Botschaft löst bei Objekten verschiedener Klassen unterschiedliches Verhalten aus, weil jede Unterklasse die Methode auf ihre Weise überschreibt. Welche Fassung läuft, entscheidet Python erst beim Ausführen am konkreten Objekt. Deshalb kann eine einzige Schleife Objekte verschiedener Klassen gleich behandeln – und eine neue Klasse lässt sich ergänzen, ohne die Schleife zu ändern.

Das Wichtigste

Eine Botschaft ist ein gezielter Aufruf an ein Objekt (ein Methodenaufruf).
Ein Ereignis ist ein Auslöser von außen (z. B. Klick, Tastendruck, eingehende Nachricht), auf den das Programm mit einer Botschaft an ein Objekt reagiert.
Beides führt dazu, dass ein Objekt reagiert.

Polymorphie bedeutet: gleiche Botschaft – unterschiedliches Verhalten, abhängig von der Klasse des Objekts. Erst zur Laufzeit wird entschieden, welche Methode ausgeführt wird (dynamisches Binden).
