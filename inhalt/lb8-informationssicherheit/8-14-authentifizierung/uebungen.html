Aufgabe 8.14.4: Das TOTP-Zeitfenster AFB II

Bei TOTP berechnen App und Server den Code aus dem gemeinsamen Geheimnis und der Zeitschrittnummer T = ⌊Unixzeit / 30⌋ (Unixzeit = Sekunden seit dem 1.1.1970).

  1. Berechne T für die Unixzeit 1 760 000 000 und gib an, wie viele Sekunden der Code dann noch gültig ist.
  2. Weil Uhren leicht abweichen, akzeptiert der Server auch die Codes des vorherigen und des nächsten Zeitschritts. Gib an, wie lange ein Code dann höchstens verwendbar ist.
  3. Ein Angreifer kennt das Passwort und rät sechsstellige Codes. Der Server erlaubt 3 Versuche pro Zeitschritt. Berechne die Trefferwahrscheinlichkeit für einen Zeitschritt und für einen ganzen Tag, wenn der Server nicht sperrt. Welche Gegenmaßnahme ist nötig?
Aufgabe 8.14.5: Challenge-Response programmieren AFB II

Programmiere das Verfahren aus Beispiel 2 in Python.

  1. Schreibe antwort(challenge, privat) für das Gerät und eine Funktion server_pruefe(challenge, antwort, oeffentlich, benutzt). Die Liste benutzt enthält alle bereits verwendeten Challenges; eine Challenge darf nur einmal akzeptiert werden.
  2. Schreibe neue_challenge(n), die mit dem Modul secrets eine Zahl von 2 bis n − 2 wählt.
  3. Weise dein Programm mit diesen Testfällen nach (erwartete und tatsächliche Ausgabe), mit öffentlichem Schlüssel (3, 85) und privatem Schlüssel (43, 85):
    • antwort(7, (43, 85)) → 48
    • server_pruefe(7, 48, (3, 85), []) → True
    • server_pruefe(7, 48, (3, 85), [7]) → False (Replay)
    • server_pruefe(10, 48, (3, 85), [7]) → False
  4. Erläutere, warum die Challenge zufällig und nicht z. B. fortlaufend (1, 2, 3, …) gewählt werden sollte.
