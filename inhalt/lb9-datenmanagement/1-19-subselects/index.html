Beispiel 1 einfach

Beispiel 1: Ein Subselect Schritt für Schritt

Die Frage: Wie heißen alle Schüler*innen der Klasse „10A“?
Das Problem: In der Tabelle schueler steht gar nicht „10A“, sondern nur eine klasse_id. Die passende id muss also erst aus der Tabelle klasse geholt werden.

Ein Subselect liest man immer von innen nach außen. Die innere Abfrage wird zuerst ausgeführt; ihr Ergebnis wird dann an ihrer Stelle in die äußere Abfrage eingesetzt.

Schritt 1 – die innere Abfrage allein ausführen. Das kannst du im DB Browser wörtlich so machen: markiere den inneren Teil und lass nur ihn laufen.

SELECT id
FROM klasse
WHERE name = '10A';

Ergebnis:

id
1

Schritt 2 – das Ergebnis gedanklich einsetzen. Die äußere Abfrage sieht also in Wirklichkeit so aus:

SELECT name
FROM schueler
WHERE klasse_id = 1;

Schritt 3 – beides zusammensetzen. Statt die 1 fest hineinzuschreiben, setzt man die innere Abfrage in Klammern ein. Das ist der eigentliche Vorteil: Die Abfrage funktioniert auch dann noch, wenn die 10A irgendwann eine andere id bekommt.

SELECT name
FROM schueler
WHERE klasse_id = (
    SELECT id
    FROM klasse
    WHERE name = '10A'
);

Ergebnis:

name
Anna Müller
Lukas Schulz
Felix Test

Die drei Schritte kurz – was und warum:

  1. Innere Abfrage: liefert die id der Klasse „10A“, nämlich 1. Warum zuerst? Die äußere Abfrage braucht diesen Wert für ihre Bedingung.
  2. Einsetzen: WHERE klasse_id = 1. Warum =? Die innere Abfrage liefert genau einen Wert, weil der Klassenname eindeutig ist.
  3. Äußere Abfrage: sucht in schueler alle Zeilen mit klasse_id 1. Warum in Klammern? So wird der Wert bei jeder Ausführung neu ermittelt, statt fest im Code zu stehen.

Ergebnis: 3 Zeilen – Anna Müller, Lukas Schulz, Felix Test (Tabelle oben).

Kontrolle: In der Tabelle schueler haben genau die ids 1, 2 und 3 die klasse_id 1. Die zweite „Anna Müller“ (id 8) gehört zur 9C und erscheint deshalb zu Recht nicht. Gegenprobe mit einem Join: SELECT schueler.name FROM schueler JOIN klasse ON schueler.klasse_id = klasse.id WHERE klasse.name = '10A'; liefert dieselben 3 Namen.

Beispiel 2: Wenn die innere Abfrage mehrere Werte liefert – IN statt =

Die Frage: Wie heißen alle Schüler*innen der Klassen „10A“ und „10B“?

Schritt 1, die innere Abfrage, liefert jetzt zwei Zeilen:

SELECT id
FROM klasse
WHERE name IN ('10A', '10B');
id
1
2

Ein = vergleicht aber immer nur mit einem Wert. Für mehrere Werte braucht man IN – zu lesen als „ist einer von diesen“: 

SELECT name
FROM schueler
WHERE klasse_id IN (
    SELECT id
    FROM klasse
    WHERE name IN ('10A', '10B')
);

Ergebnis:

name
Anna Müller
Lukas Schulz
Felix Test
Marie Becker
Tom Schneider

Beispiel 3: Subselect mit einer Aggregatfunktion

Die Frage: Wer hat die beste Note in der Datenbank? Die beste Note ist die kleinste Zahl – aber welche das ist, weiß man vorher nicht. Genau dafür sind Subselects gemacht.

Schritt 1 – die innere Abfrage allein:

SELECT MIN(wert)
FROM note;
MIN(wert)
1.0

Schritt 2 – dieses Zwischenergebnis als Vergleichswert einsetzen:

SELECT s.name, n.wert
FROM schueler s
JOIN note n ON n.schueler_id = s.id
WHERE n.wert = (
    SELECT MIN(wert)
    FROM note
);

Ergebnis:

namewert
Marie Becker1.0

Warum nicht in einem Schritt? Die Tabelle note enthält keine Namen, du bräuchtest also ohnehin einen JOIN: SELECT s.name, MIN(n.wert) FROM schueler s JOIN note n ON n.schueler_id = s.id; Diese Abfrage ist nach dem SQL-Standard sogar falsch, denn neben einer Aggregatfunktion darf ohne GROUP BY keine normale Spalte stehen. Viele Datenbanksysteme melden deshalb einen Fehler. SQLite führt sie zwar aus und zeigt bei MIN und MAX die passende Zeile an, aber immer nur eine – hätten zwei Personen die Note 1.0, fiele eine unter den Tisch. Das Subselect findet dagegen alle Treffer und funktioniert in jedem Datenbanksystem.

Beispiel 4 komplex

Ausgangssituation: Für eine Ehrung sucht die Schulleitung alle Schüler*innen, deren persönlicher Notendurchschnitt besser ist als der Durchschnitt aller Noten der Schule. Ausgegeben werden Klasse, Name und persönlicher Schnitt, bester Schnitt zuerst.

SELECT k.name AS klasse, s.name, ROUND(AVG(n.wert), 2) AS schnitt
FROM schueler s
JOIN klasse k ON s.klasse_id = k.id
JOIN note n   ON n.schueler_id = s.id
GROUP BY s.id
HAVING AVG(n.wert) < (SELECT AVG(wert) FROM note)
ORDER BY schnitt ASC, s.name ASC;
  1. Innere Abfrage zuerst. SELECT AVG(wert) FROM note liefert (1.7 + 2.3 + 2.0 + 3.0 + 1.3 + 1.0 + 3.7 + 2.7 + 2.0 + 1.7) / 10 = 21.4 / 10 = 2.14. Warum ein Subselect? Der Vergleichswert muss aus derselben Tabelle berechnet werden, ohne dass er vorher bekannt ist.
  2. FROM und JOIN. Drei Tabellen werden verbunden: schueler mit klasse (für den Klassennamen) und mit note (für die Werte). Es entstehen 10 Zeilen, eine je Note.
  3. GROUP BY s.id. Je Person ein Stapel. Warum nicht nach dem Namen? Es gibt zwei verschiedene Personen namens „Anna Müller“ (id 1 in der 10A, id 8 in der 9C). Nach Namen gruppiert würden ihre Noten zu einem Schnitt von 1.9 vermischt.

  4. HAVING mit Subselect. Verglichen wird der Schnitt eines Stapels, also HAVING und nicht WHERE. Fünf Stapel bleiben übrig.
  5. SELECT und ORDER BY. Gerundeter Schnitt, aufsteigend; bei Gleichstand (2.0) alphabetisch.

Falle und Probe: Wer WHERE n.wert < (SELECT AVG(wert) FROM note) schreibt, filtert einzelne Noten statt Durchschnitte: Felix, Tom und Sarah fielen zwar heraus, aber Anna Müller (10A) bekäme mit nur ihrer 1.7 einen Schnitt von 1.7 – ein geschöntes Ergebnis. Probe: Der Gesamtschnitt 2.14 liegt zwischen dem besten (1.15) und dem schlechtesten (3.7) persönlichen Schnitt, wie es sein muss.

Wann verwendet man Subselects?

  • Wenn ein Zwischenergebnis zur Filterung notwendig ist
  • Wenn man keine JOINs verwenden möchte oder kann
  • Zur Verbesserung der Lesbarkeit bei einfachen Abfragen
Hinweis: Wann lieber JOINs?

JOINs sind in der Regel performanter als Subselects, wenn mehrere Tabellen miteinander verbunden werden müssen und größere Datenmengen beteiligt sind.

Faustregel: Brauchst du Spalten aus beiden Tabellen im Ergebnis, nimm einen JOIN. Brauchst du aus der zweiten Tabelle nur einen Vergleichswert, ist ein Subselect meist besser lesbar. Beispiel 1 ließe sich auch als JOIN schreiben: 

SELECT s.name
FROM schueler s
JOIN klasse k ON s.klasse_id = k.id
WHERE k.name = '10A';

Beide Abfragen liefern dasselbe Ergebnis.

Praxisbezug: Subselects in Onlinehandel und Datenbankadministration

„Zeige alle Kund*innen, die mehr ausgegeben haben als der Durchschnitt“ oder „alle Artikel, die teurer sind als der günstigste Artikel der Konkurrenz“ – solche Fragen stellen Data Analysts im Onlinehandel täglich, und sie lassen sich nur mit einem Subselect in einer Abfrage beantworten. In der Datenbankadministration sind Subselects beim Aufräumen wichtig, etwa um alle Bestellungen von gelöschten Konten zu entfernen. Auch hier gilt: erst die innere Abfrage allein prüfen, dann das DELETE ausführen.

Übungsaufgaben

Für alle Übungsaufgaben wird die oben gezeigte Datenbank verwendet: schueler.sql

Das Wichtigste

Subselects liefern ein Ergebnis, das von der übergeordneten SQL-Anweisung weiterverarbeitet wird. Sie können in SELECT-, FROM- oder WHERE-Klauseln verwendet werden.

Achtung, tückischer Fehler: Schreibt man in diesem Fall = statt IN, meldet SQLite keinen Fehler. Es nimmt stillschweigend nur den ersten Wert der inneren Abfrage und liefert nur die drei Namen aus der 10A. Der Fehler fällt also nicht durch eine Fehlermeldung auf, sondern nur dadurch, dass zu wenige Zeilen herauskommen. Prüfe deshalb bei jedem Subselect: Kann die innere Abfrage mehr als eine Zeile liefern? Wenn ja, gehört dort ein IN hin.
