SQL (Structured Query Language) ist eine Datenbanksprache zur Definition, Abfrage und Manipulation von Daten in relationalen Datenbanken. In diesem Abschnitt konzentrieren wir uns auf grundlegende SQL-Abfragen.

Praxisbezug: Warum SQL im Berufsleben so gefragt ist

Stell dir einen Online-Shop vor: Die Marketingabteilung möchte wissen, welche Produkte sich in den letzten drei Monaten am besten verkauft haben, das Controlling will die Umsätze nach Region auswerten, und der Kundenservice sucht alle Bestellungen eines bestimmten Kunden. In all diesen Fällen liegen die Daten in einer relationalen Datenbank – und mit einer einfachen SELECT-Abfrage (ggf. kombiniert mit ORDER BY, wie du es in diesem Kapitel lernst) lassen sich solche Fragen in Sekunden beantworten, statt Tabellen mühsam von Hand zu durchsuchen.

Berufsfelder: SQL-Kenntnisse werden längst nicht nur von Data Analysts, Data Engineers oder Backend-Entwickler*innen erwartet. Auch in Berufen außerhalb der klassischen Informatik gehören Datenbankabfragen mittlerweile zum Alltag – etwa im Controlling und der Buchhaltung (Finanzkennzahlen auswerten), im Marketing und Vertrieb (Kundendaten und Verkaufszahlen analysieren), im Personalwesen/HR-Analytics (Mitarbeiterdaten auswerten) oder in der medizinischen Statistik (Behandlungsdaten auswerten). Wer SQL beherrscht, hat dadurch auf dem Arbeitsmarkt einen klaren Vorteil.

Die SELECT-Anweisung

Die SELECT-Anweisung ist die grundlegendste und am häufigsten verwendete SQL-Abfrage. Sie wird verwendet, um Daten aus einer oder mehreren Tabellen abzurufen.

Wir sprechen von einer Projektion, wenn wir aus einer Tabelle ausgewählte Spalten anzeigen lassen.

Beispiel 1: Alle Spalten auswählen

SELECT *
FROM Studenten;

Ergebnis – der Stern steht für „alle Spalten“, die Tabelle kommt also unverändert zurück (5 Zeilen):

2AnnaSchmidt1999-07-221.8
3LisaMüller2001-01-303.5
4JonasBauer2000-11-122.9

  1. FROM Studenten: Die Datenbank holt alle Zeilen der Tabelle Studenten. Warum? Erst muss feststehen, woher die Daten kommen.
  2. Kein WHERE: Es wird keine Zeile aussortiert. Warum? Ohne Bedingung bleiben alle Datensätze im Ergebnis.
  3. SELECT *: Der Stern wählt alle fünf Spalten in der Reihenfolge aus, in der sie in der Tabelle angelegt sind. Warum? * ist die Kurzform für StudentID, Vorname, Nachname, Geburtsdatum, Notendurchschnitt.

Ergebnis: die Tabelle oben, 5 Zeilen und 5 Spalten (für den Ausschnitt).

Kontrolle: Zeilen- und Spaltenzahl des Ergebnisses stimmen mit der Tabelle überein. In der vollständigen Datei studenten_tabelle.sql liefert dieselbe Abfrage 51 Zeilen; der DB Browser zeigt die Zeilenzahl unter dem Ergebnis an. Erst mit einer Spaltenauswahl wie in Beispiel 2 wird daraus eine echte Projektion.

Verwendung von AS für Aliase

Das Schlüsselwort AS wird in SQL verwendet, um Spalten oder Tabellen einen Alias (einen alternativen Namen) zu geben. Dies ist besonders nützlich, um die Lesbarkeit von Abfragen zu verbessern oder um komplexe Ausdrücke mit einem einfachen Namen zu versehen.

Beispiel 4: Spalten umbenennen

SELECT Nachname AS Familienname, Notendurchschnitt AS Schnitt
FROM Studenten;

Ergebnis – die Daten sind identisch, nur die Überschriften ändern sich:

FamiliennameSchnitt
Mustermann2.75
Schmidt1.8
Müller3.5
Bauer2.9
Klein1.5

Beispiel 5: Einer berechneten Spalte einen Namen geben

Hier wird eine Spalte ausgegeben, die es in der Tabelle gar nicht gibt: das Alter, berechnet aus dem Geburtsjahr. Ohne AS hätte die Spalte die ganze Rechnung als Überschrift.

SELECT Vorname, Nachname, 2026 - CAST(substr(Geburtsdatum, 1, 4) AS INTEGER) AS Lebensjahre
FROM Studenten;

Ergebnis:

VornameNachnameLebensjahre
MaxMustermann26
AnnaSchmidt27
LisaMüller25
JonasBauer26
MiaKlein24
Hinweis: Warum heißt die Spalte nicht einfach „Alter“?

Weil Alter in SQL ein reserviertes Schlüsselwort ist (es gehört zum Befehl ALTER TABLE). Schreibt man AS Alter, antwortet SQLite mit near "Alter": syntax error. Wenn eine Abfrage ohne erkennbaren Grund einen Syntaxfehler wirft, ist ein reservierter Name als Alias oder Spaltenname eine häufige Ursache. Abhilfe: einen anderen Namen wählen oder den Namen in doppelte Anführungszeichen setzen (AS "Alter").

Die ORDER BY-Klausel in SQL

Die ORDER BY-Klausel wird in SQL verwendet, um die Ergebnisse einer Abfrage nach einer oder mehreren Spalten zu sortieren. Sie ist besonders nützlich, wenn du Daten in einer bestimmten Reihenfolge anzeigen möchtest.

Syntax der ORDER BY-Klausel:

SELECT spalte1, spalte2, ...
FROM tabelle
[WHERE bedingung]
ORDER BY spalte1 [ASC|DESC], spalte2 [ASC|DESC], ...;

  • ASC: aufsteigend (Standard)
  • DESC: absteigend

Beispiel 6: Aufsteigend sortieren

SELECT Vorname, Nachname
FROM Studenten
ORDER BY Nachname;

Ergebnis – dieselben fünf Zeilen wie in Beispiel 2, nur in anderer Reihenfolge. ORDER BY ändert nie, welche Zeilen kommen, sondern nur in welcher Reihenfolge:

VornameNachname
JonasBauer
MiaKlein
MaxMustermann
LisaMüller
AnnaSchmidt

Beispiel 7: Absteigend sortieren

SELECT Vorname, Notendurchschnitt
FROM Studenten
ORDER BY Notendurchschnitt DESC;

Ergebnis – größter Wert zuerst. Achtung: Beim Notendurchschnitt ist der größte Wert die schlechteste Note – für „beste zuerst“ bräuchte man ASC:

VornameNotendurchschnitt
Lisa3.5
Jonas2.9
Max2.75
Anna1.8
Mia1.5

Beispiel 8: Nach zwei Kriterien sortieren

Die zweite Spalte im ORDER BY entscheidet nur dann, wenn die erste gleich ist – wie im Telefonbuch, wo bei gleichem Nachnamen der Vorname zählt.

SELECT Vorname, Nachname, Notendurchschnitt
FROM Studenten
ORDER BY Notendurchschnitt ASC, Nachname ASC;

Ergebnis:

VornameNachnameNotendurchschnitt
MiaKlein1.5
AnnaSchmidt1.8
MaxMustermann2.75
JonasBauer2.9
LisaMüller3.5

Die Beispiele 1 bis 8 zeigen jeweils einen Baustein in Reinform (Beispiel 2 ist der einfachste Grundfall einer Projektion). Das folgende Beispiel setzt alle Bausteine der Seite zusammen.

Beispiel 9 komplex

Ausgangssituation: Das Prüfungsamt möchte eine Jahrgangsliste: Nachname, Jahrgang (Geburtsjahr als Zahl) und Notendurchschnitt unter dem Namen Schnitt. Die jüngsten Jahrgänge sollen oben stehen, innerhalb eines Jahrgangs die beste Note zuerst. Grundlage ist der Ausschnitt mit den 5 Zeilen von oben.

SELECT Nachname,
       CAST(substr(Geburtsdatum, 1, 4) AS INTEGER) AS Jahrgang,
       Notendurchschnitt AS Schnitt
FROM Studenten
ORDER BY Jahrgang DESC, Schnitt ASC;
  1. FROM: Alle 5 Zeilen der Tabelle Studenten liegen bereit. Warum zuerst? Ohne Tabelle gibt es keine Spalten, mit denen man rechnen könnte.
  2. WHERE: Entfällt, denn es sollen alle Personen erscheinen.
  3. SELECT: Für jede Zeile wird der Jahrgang berechnet: substr(Geburtsdatum, 1, 4) schneidet die ersten vier Zeichen aus (z. B. '2000'), CAST(… AS INTEGER) macht daraus die Zahl 2000. Warum CAST? Ohne Umwandlung wäre der Jahrgang ein Text; mit Zahlen kann man sicher rechnen und vergleichen. Anschließend bekommen die Spalten ihre neuen Namen Jahrgang und Schnitt.
    NachnameJahrgangSchnitt
    Mustermann20002.75
    Schmidt19991.8
    Müller20013.5
    Bauer20002.9
    Klein20021.5
  4. ORDER BY, erstes Kriterium: Jahrgang DESC ordnet 2002, 2001, 2000, 2000, 1999. Warum darf hier der Alias stehen? ORDER BY wird als letzter Schritt nach dem SELECT ausgeführt, die neuen Namen existieren dann schon.
  5. ORDER BY, zweites Kriterium: Nur beim Jahrgang 2000 gibt es einen Gleichstand (Mustermann und Bauer). Schnitt ASC setzt den kleineren Wert, also die bessere Note, nach oben: 2.75 vor 2.9.

Ergebnis:

NachnameJahrgangSchnitt
Klein20021.5
Müller20013.5
Mustermann20002.75
Bauer20002.9
Schmidt19991.8

Falle und Probe: Wer statt nach dem Jahrgang nach Geburtsdatum DESC sortiert, bekommt Bauer (2000-11-12) vor Mustermann (2000-03-15), denn dann entscheidet der Tag und nicht die Note. Beide Abfragen sehen „richtig“ aus, liefern aber verschiedene Reihenfolgen. Prüfe deshalb immer an einem Gleichstand, ob das zweite Kriterium wirklich greift. Die Probe gelingt hier: Es sind weiterhin genau 5 Zeilen, und nur die Reihenfolge hat sich geändert.

Hinweis: Schritt für Schritt zu einer eigenen Abfrage

Gesucht sind „Vorname und Geburtsdatum aller Studierenden, jüngste Person zuerst, Geburtsdatum umbenannt in Geboren“. So kommst du dahin:

  1. Woher? Die Daten stehen in der Tabelle Studenten → FROM Studenten
  2. Welche Zeilen? Es sollen alle Personen kommen → kein WHERE
  3. Welche Spalten? Vorname und Geburtsdatum → SELECT Vorname, Geburtsdatum
  4. Umbenennen? Ja, das Geburtsdatum → Geburtsdatum AS Geboren
  5. Reihenfolge? Jüngste zuerst, also das späteste Datum oben → ORDER BY Geburtsdatum DESC

Zusammengesetzt ergibt das:

SELECT Vorname, Geburtsdatum AS Geboren
FROM Studenten
ORDER BY Geburtsdatum DESC;

Diese fünf Fragen funktionieren bei jeder Abfrage, auch bei den komplizierteren später – probiere sie gleich an Aufgabe 1.3.2 aus.

Das Wichtigste

Die grundlegende Syntax einer SELECT-Anweisung lautet:
SELECT Spaltenname(n)
FROM Tabellenname;

So arbeitet die Datenbank eine Abfrage ab – nicht in der Reihenfolge, in der sie geschrieben ist:

  1. FROM: Aus welcher Tabelle kommen die Daten? → alle 5 Zeilen liegen bereit
  2. WHERE: Welche Zeilen bleiben übrig? (siehe Seite 1.4)
  3. SELECT: Welche Spalten werden ausgegeben, und wie heißen sie?
  4. ORDER BY: In welcher Reihenfolge werden die Zeilen ausgegeben?

Wenn du eine Abfrage selbst schreibst, gehe in genau dieser Reihenfolge vor. Dann hast du bei jedem Schritt schon alles, was du für den nächsten brauchst.

AS wird verwendet, um:
1. Spalten umzubenennen
2. Berechneten Spalten einen Namen zu geben
3. Tabellen einen Kurznamen zu geben
