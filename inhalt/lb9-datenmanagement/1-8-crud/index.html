CRUD steht für Create, Read, Update und Delete. Dies sind die vier grundlegenden Operationen, die du auf Daten in einer Datenbank ausführen kannst. Da wir uns mit Read schon beschäftigt haben, bleiben nun noch Create, Update und Delete.
Die folgenden Beispiele beziehen sich auf die Datenbank aus der Datei kurs.sql.

1. Create (Erstellen)

Mit dem SQL-Befehl INSERT fügst du neue Datensätze in eine Tabelle ein.

Beispiel aus unserer Datenbank:


INSERT INTO Schueler (s_id, name, vorname) VALUES (6, 'Becker', 'Tom');

2. Update (Aktualisieren)

Mit dem SQL-Befehl UPDATE kannst du bestehende Datensätze in einer Tabelle ändern.

Beispiel aus unserer Datenbank:


UPDATE Kursnote SET note = 1.7 WHERE k_id = 1 AND s_id = 1;

3. Delete (Löschen)

Mit dem SQL-Befehl DELETE kannst du Datensätze aus einer Tabelle entfernen.

Beispiel aus unserer Datenbank:


DELETE FROM Kursnote WHERE k_id = 5 AND s_id = 5;
Hinweis: UPDATE und DELETE ohne WHERE

Sei vorsichtig mit UPDATE- und DELETE-Befehlen, besonders wenn du keine WHERE-Klausel verwendest. Ohne WHERE-Klausel werden alle Datensätze in der Tabelle geändert oder gelöscht!

Alle drei Befehle an einer Tabelle mitverfolgt

Beispiel 1 einfach

Bei SELECT sieht man das Ergebnis sofort. Bei INSERT, UPDATE und DELETE meldet die Datenbank dagegen nur „Ausführung erfolgreich“ – was sich geändert hat, muss man selbst nachsehen. Deshalb hier alle drei Befehle nacheinander an derselben kleinen Tabelle Mitglied eines Sportvereins.

Ausgangszustand

MitgliedNrNameBeitragStatus
1Berger, Anna60.00aktiv
2Kaufmann, Ben60.00aktiv
3Nowak, Clara90.00aktiv

Schritt 1: INSERT – ein neues Mitglied

INSERT INTO Mitglied (MitgliedNr, Name, Beitrag, Status)
VALUES (4, 'Vogt, David', 60.00, 'aktiv');

Die Tabelle hat jetzt vier Zeilen; die neue steht am Ende. Wichtig ist die Zuordnung: Die vierte Spalte in der Klammer bekommt den vierten Wert.

Schritt 2: UPDATE – Beitragserhöhung um 5 Prozent

UPDATE Mitglied
SET Beitrag = Beitrag * 1.05
WHERE Status = 'aktiv';

Ergebnis – rechts wird gerechnet, links zugewiesen. Jede Zeile bekommt ihren eigenen neuen Wert, nicht alle denselben:

MitgliedNrNameBeitrag vorherBeitrag nachher
1Berger, Anna60.0063.00
2Kaufmann, Ben60.0063.00
3Nowak, Clara90.0094.50
4Vogt, David60.0063.00

Schritt 3: DELETE – ein Austritt

DELETE FROM Mitglied
WHERE MitgliedNr = 2;

Endzustand – Zeile 2 ist weg, die übrigen Nummern bleiben unverändert. Die Lücke wird nicht aufgefüllt, und das ist auch richtig so: Die MitgliedNr ist ein Schlüssel und darf nicht neu vergeben werden.

MitgliedNrNameBeitragStatus
1Berger, Anna63.00aktiv
3Nowak, Clara94.50aktiv
4Vogt, David63.00aktiv

Die drei Schritte kurz zusammengefasst – was und warum:

  1. INSERT legt eine neue Zeile an (3 → 4 Zeilen). Warum mit Spaltenliste? Dann ist eindeutig, welcher Wert in welche Spalte kommt, auch wenn sich die Spaltenreihenfolge der Tabelle einmal ändert.
  2. UPDATE ändert Werte in vorhandenen Zeilen (4 Zeilen bleiben 4). Warum Beitrag * 1.05? Der neue Wert wird für jede Zeile aus ihrem eigenen alten Wert berechnet: 60.00 · 1.05 = 63.00, 90.00 · 1.05 = 94.50.
  3. DELETE entfernt genau die Zeilen, die die Bedingung erfüllen (4 → 3 Zeilen). Warum über den Primärschlüssel? MitgliedNr = 2 trifft garantiert höchstens eine Zeile.

Ergebnis: der Endzustand oben mit 3 Zeilen.

Kontrolle: Zeilenzahl 3 + 1 − 1 = 3 stimmt. Summe der Beiträge vorher 60 + 60 + 90 = 210.00, nachher 63 + 94.50 + 63 = 220.50. Vor dem DELETE hätte SELECT * FROM Mitglied WHERE MitgliedNr = 2; genau eine Zeile geliefert – das ist der Sicherheitsgriff aus dem Merkkasten unten.

Praxisbezug: CRUD in Apps und das Recht auf Löschung

Jede App, in der du ein Konto anlegst, dein Profil änderst oder einen Beitrag löschst, führt im Hintergrund INSERT, UPDATE und DELETE aus. In der Datenbankadministration gehören solche Änderungen zu den heikelsten Aufgaben: Vor einem großen UPDATE wird ein Backup angelegt und die Änderung in einer Transaktion ausgeführt, die sich bei Fehlern zurückrollen lässt. Die DSGVO (Art. 17, „Recht auf Löschung“) verlangt außerdem, dass Unternehmen personenbezogene Daten auf Wunsch wirklich löschen – mit DELETE in allen betroffenen Tabellen, nicht nur durch Ausblenden.

Das Vereinsbeispiel zeigt die drei Befehle an einer Tabelle. Sobald Tabellen über Fremdschlüssel verbunden sind, kommt es zusätzlich auf die Reihenfolge der Befehle an.

Beispiel 2 komplex

Ausgangssituation: In der Datenbank kurs.sql verlässt Tim Weber (s_id 4) die Schule. Er soll vollständig aus der Datenbank entfernt werden. In Kursnote verweisen zwei Zeilen über den Fremdschlüssel s_id auf ihn.

  1. Betroffene Zeilen ansehen (Sicherheitsgriff). 
    SELECT * FROM Kursnote WHERE s_id = 4;
    Ergebnis: 2 Zeilen – (3, 4, 2.7) Englisch und (5, 4, 1.3) Geschichte. Warum? So weißt du vorher, wie viele Zeilen der DELETE treffen muss.
  2. Zuerst die abhängigen Zeilen löschen. 
    DELETE FROM Kursnote WHERE s_id = 4;
    Warum zuerst? Die Noten verweisen auf den Schüler. Würde man den Schüler zuerst löschen, zeigten zwei Noten auf einen Datensatz, den es nicht mehr gibt – die referenzielle Integrität wäre verletzt.
  3. Dann den Datensatz selbst löschen. 
    DELETE FROM Schueler WHERE s_id = 4;
  4. Probe mit einem Join. Ein LEFT JOIN von Kursnote zu Schueler zeigt Noten ohne passenden Schüler („verwaiste“ Zeilen): 
    SELECT Kursnote.*
FROM Kursnote
LEFT JOIN Schueler ON Kursnote.s_id = Schueler.s_id
WHERE Schueler.s_id IS NULL;
    Das Ergebnis ist leer. Zusätzlich: SELECT COUNT(*) FROM Kursnote; liefert 8 statt 10, SELECT COUNT(*) FROM Schueler; liefert 4 statt 5.

Ergebnis: Tim Weber und seine beiden Noten sind entfernt; alle übrigen Noten haben weiterhin einen gültigen Schüler.

Falle: Vertauscht man die Schritte 2 und 3, meldet SQLite trotzdem „Ausführung erfolgreich“. SQLite prüft Fremdschlüssel nämlich nur, wenn sie vorher mit PRAGMA foreign_keys = ON; eingeschaltet wurden. Ohne diese Einstellung entstehen stillschweigend zwei verwaiste Noten, die die Probe aus Schritt 4 sofort anzeigen würde. Mit eingeschalteter Prüfung bricht der DELETE auf Schueler dagegen mit FOREIGN KEY constraint failed ab.

Aufgaben mit JOIN und Aggregatfunktionen

Vorgriff: CASE WHEN

CASE WHEN Bedingung THEN Wert1 ELSE Wert2 END ist eine Fallunterscheidung innerhalb einer SQL-Abfrage: Trifft die Bedingung zu, wird Wert1 verwendet, sonst Wert2. So kannst du z. B. verhindern, dass ein berechneter Wert eine Obergrenze überschreitet.

Das Wichtigste

Syntax für INSERT:
INSERT INTO Tabellenname (Spalte1, Spalte2, ...) VALUES (Wert1, Wert2, ...);

Syntax für UPDATE:
UPDATE Tabellenname SET Spalte1 = Wert1, Spalte2 = Wert2, ... WHERE Bedingung;

Syntax für DELETE:
DELETE FROM Tabellenname WHERE Bedingung;

Der Sicherheitsgriff bei UPDATE und DELETE

Schreibe die Bedingung zuerst als SELECT und sieh dir an, welche Zeilen sie trifft: 

SELECT * FROM Mitglied WHERE MitgliedNr = 2;

Stimmt die Trefferzahl, baust du den Befehl um und lässt die WHERE-Bedingung unverändert stehen. Ein vergessenes WHERE trifft jede Zeile der Tabelle – und rückgängig machen lässt sich das nicht.
