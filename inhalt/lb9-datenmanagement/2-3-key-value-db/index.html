Eine Key-Value-Datenbank ist eine einfache Form einer Datenbank, die Daten als Paare von Schlüssel (Key) und Wert (Value) speichert. Dies ist ähnlich wie bei einem Dictionary in Python. Jeder Schlüssel ist eindeutig und kann verwendet werden, um einen zugehörigen Wert abzurufen oder zu setzen.

Praxisbezug: Warenkorb, Sitzung, Cache

Legst du im Onlineshop etwas in den Warenkorb, merkt sich der Shop das oft in einer Key-Value-Datenbank wie Redis: Schlüssel ist deine Sitzungs-ID, Wert ist der Inhalt des Warenkorbs. So kann jede Seite in Millisekunden darauf zugreifen. Backend-Entwickler*innen und Datenbankadministrator*innen setzen Redis außerdem als Cache vor langsame relationale Datenbanken, damit häufig abgefragte Daten nicht jedes Mal neu berechnet werden müssen. Weil Sitzungsdaten personenbezogen sein können, bekommen sie nach DSGVO eine Ablaufzeit: Redis löscht sie mit EXPIRE automatisch nach einer festgelegten Zeit.

Hinweis: So sieht eine echte Key-Value-Datenbank aus

Das Python-Dictionary auf dieser Seite ist ein vereinfachtes Modell, um das Prinzip zu verstehen. In der echten Welt übernimmt diese Aufgabe z. B. Redis – eine sehr schnelle, weit verbreitete Key-Value-Datenbank. Im offiziellen Redis Playground kannst du direkt im Browser echte Redis-Befehle wie SET, GET oder HSET ausprobieren – ganz ohne Installation oder Anmeldung.

Was ist ein Python-Dictionary?

Ein Dictionary in Python ist eine Datenstruktur, die eine Sammlung von Schlüssel-Wert-Paaren speichert. Jeder Schlüssel ist eindeutig und wird verwendet, um auf einen entsprechenden Wert zuzugreifen. Dies funktioniert ähnlich wie ein echtes Wörterbuch, bei dem man ein Wort (den Schlüssel) nachschlägt und dessen Definition (den Wert) erhält.

Dictionaries in Python

Ein Dictionary in Python wird mit geschweiften Klammern { } erstellt, und die Daten werden als Paare von Schlüssel und Wert darin abgelegt. Hier ist ein Beispiel: 

# Ein einfaches Dictionary
benutzer = {
    'Name': 'Alice',
    'Alter': 25,
    'Beruf': 'Entwicklerin'
}

# Zugriff auf Werte über den Schlüssel
print("Name:", benutzer['Name'])
print("Alter:", benutzer['Alter'])

# Wert ändern
benutzer['Alter'] = 26
print("Aktualisiertes Alter:", benutzer['Alter'])

# Ein neues Schlüssel-Wert-Paar hinzufügen
benutzer['Stadt'] = 'Berlin'
print("Stadt hinzugefügt:", benutzer['Stadt'])

# Schlüssel-Wert-Paar löschen
del benutzer['Beruf']
print("Beruf entfernt:", benutzer)
Hinweis: Wichtige Dictionary-Methoden

Python-Dictionaries bieten viele nützliche Methoden, um mit Key-Value-Daten zu arbeiten. Hier sind die wichtigsten (angewendet auf benutzer nach dem Beispiel oben):

  • get(): ruft den Wert zu einem Schlüssel ab, ohne dass ein Fehler auftritt, wenn der Schlüssel nicht existiert. 
    wert = benutzer.get('Name', 'Unbekannt')

    Wenn der Schlüssel 'Name' vorhanden ist, wird der zugehörige Wert zurückgegeben. Wenn nicht, wird 'Unbekannt' als Standardwert zurückgegeben.

  • keys(): gibt alle Schlüssel im Dictionary zurück. 
    alle_schluessel = list(benutzer.keys())

    Ergebnis: ['Name', 'Alter', 'Stadt'].

  • values(): gibt alle Werte im Dictionary zurück, ohne die zugehörigen Schlüssel. 
    alle_werte = list(benutzer.values())

    Ergebnis: ['Alice', 26, 'Berlin'].

  • items(): gibt alle Schlüssel-Wert-Paare gleichzeitig zurück – besonders praktisch zum Durchlaufen (Iterieren) eines Dictionarys. 
    for schluessel, wert in benutzer.items():
    print(schluessel, "->", wert)
  • len(): gibt die Anzahl der gespeicherten Schlüssel-Wert-Paare zurück. 
    anzahl = len(benutzer)   # 3

Über ein Dictionary iterieren

Mit einer for-Schleife kannst du alle Schlüssel eines Dictionarys der Reihe nach durchgehen und darüber auf die zugehörigen Werte zugreifen – hier mit dem Dictionary benutzer von oben: 

for schluessel in benutzer:
    print(schluessel, benutzer[schluessel])

Ausgabe: Name Alice, Alter 26, Stadt Berlin – je eine Zeile. Das ist genau das Muster, das du gleich in den Übungsaufgaben brauchst.

Dictionaries vs. Listen: Wo liegt der Vorteil?

Eine Liste eignet sich gut, wenn du gleichartige Elemente in einer bestimmten Reihenfolge speichern willst (z. B. alle Namen einer Klasse). Willst du aber zu einem eindeutigen Namen gezielt einen Wert nachschlagen, ist ein Dictionary die bessere Wahl: 

# Mit einer Liste musst du dir die Reihenfolge merken:
benutzer_liste = ["Alice", 25, "Entwicklerin"]
print(benutzer_liste[1])   # 25 - aber was war an Position 1 nochmal?

# Mit einem Dictionary greifst du über einen aussagekräftigen Namen zu:
benutzer_dict = {"Name": "Alice", "Alter": 25, "Beruf": "Entwicklerin"}
print(benutzer_dict["Alter"])   # 25 - sofort klar, was gemeint ist

Verschachtelte Dictionaries

Ein verschachteltes Dictionary ist ein Dictionary, bei dem die Werte selbst wieder Dictionaries sein können. Dies ist nützlich, wenn man komplexere Datenstrukturen wie mehrere Benutzer und deren jeweilige Informationen speichern möchte. Hier ist ein Beispiel, wie man mehrere Benutzer mit ihren jeweiligen Altersangaben und Berufen speichern kann:

Mehrere Benutzer in einem verschachtelten Dictionary speichern

# Ein Dictionary, das mehrere Benutzer speichert
benutzer_db = {
    'Alice': {'Alter': 25, 'Beruf': 'Entwicklerin'},
    'Bob': {'Alter': 30, 'Beruf': 'Designer'},
    'Clara': {'Alter': 22, 'Beruf': 'Lehrerin'}
}

# Zugriff auf die Daten eines Benutzers
print("Alices Alter:", benutzer_db['Alice']['Alter'])
print("Bobs Beruf:", benutzer_db['Bob']['Beruf'])

# Alter von Clara ändern
benutzer_db['Clara']['Alter'] = 23
print("Claras aktualisiertes Alter:", benutzer_db['Clara']['Alter'])

# Einen neuen Benutzer hinzufügen
benutzer_db['David'] = {'Alter': 28, 'Beruf': 'Ingenieur'}
print("Neuer Benutzer hinzugefügt:", benutzer_db['David'])

# Beruf von Bob löschen
del benutzer_db['Bob']['Beruf']
print("Bobs Beruf gelöscht:", benutzer_db['Bob'])
Beispiel 1 einfach Ein Punktezähler wie INCR in Redis

Ausgangssituation: Eine Lern-App vergibt Punkte. Wie mit dem Redis-Befehl INCR soll ein Zähler je Nutzer erhöht werden, auch wenn es den Nutzer noch gar nicht gibt.

punkte = {}

def punkte_erhoehen(nutzer, anzahl=1):
    punkte[nutzer] = punkte.get(nutzer, 0) + anzahl
    return punkte[nutzer]

print(punkte_erhoehen("anna"))
print(punkte_erhoehen("anna", 10))
print(punkte_erhoehen("ben"))
print(punkte.get("clara", 0))
print(punkte)
  1. Leeres Dictionary anlegen – Es ist der „Key-Value-Store“. Schlüssel ist der Nutzername, Wert die Punktzahl.
  2. Erster Aufruf mit „anna“ – Den Schlüssel gibt es noch nicht. punkte.get("anna", 0) liefert deshalb den Standardwert 0 statt eines KeyError. 0 + 1 = 1 wird gespeichert und zurückgegeben.
  3. Zweiter Aufruf mit 10 Punkten – Jetzt existiert der Schlüssel: 1 + 10 = 11.
  4. Aufruf mit „ben“ – Neuer Schlüssel, wieder Start bei 0, Ergebnis 1.
  5. Nur lesen für „clara“ – get mit Standardwert liefert 0, legt aber keinen Schlüssel an.

Ergebnis: Die Ausgabe lautet

1
11
1
0
{'anna': 11, 'ben': 1}

Kontrolle: Im Dictionary stehen nur zwei Schlüssel – „clara“ fehlt, weil nur gelesen wurde. Genau so verhält sich Redis: GET auf einen unbekannten Schlüssel ändert nichts.

Beispiel 2 komplex Ein Cache vor einer langsamen Datenbank

Ausgangssituation: Ein Onlineshop fragt Preise aus einer langsamen relationalen Datenbank ab. Häufig gefragte Preise sollen deshalb in einem Key-Value-Cache zwischengespeichert werden (so wird Redis in der Praxis oft eingesetzt). Gezählt wird, wie oft der Cache hilft (Treffer) und wie oft doch die Datenbank gefragt werden muss (Fehlgriff). Die Datenbank wird hier durch ein Dictionary simuliert.

datenbank = {"P1": 19.99, "P2": 5.49, "P3": 12.00}   # die "langsame" Datenbank
cache = {}
statistik = {"treffer": 0, "fehlgriffe": 0}

def preis_holen(produkt):
    if produkt in cache:                  # 1. zuerst im Cache nachsehen
        statistik["treffer"] += 1
        return cache[produkt]
    statistik["fehlgriffe"] += 1          # 2. sonst die Datenbank fragen
    preis = datenbank.get(produkt)        #    None, wenn es das Produkt nicht gibt
    if preis is not None:
        cache[produkt] = preis            # 3. für das nächste Mal merken
    return preis

def preis_aendern(produkt, neuer_preis):
    datenbank[produkt] = neuer_preis
    cache.pop(produkt, None)              # 4. veralteten Cache-Eintrag entfernen

for p in ["P1", "P2", "P1", "P9", "P1"]:
    print(p, preis_holen(p))
print(statistik)
preis_aendern("P1", 17.99)
print("P1", preis_holen("P1"))
print(statistik)
  1. „P1“ (erste Anfrage) – nicht im Cache, also Fehlgriff. Die Datenbank liefert 19.99; der Preis wird im Cache abgelegt.
  2. „P2“ – ebenso Fehlgriff, 5.49 kommt in den Cache.
  3. „P1“ (zweite Anfrage) – jetzt im Cache: Treffer, die Datenbank wird nicht gefragt.
  4. „P9“ – der Sonderfall – gibt es nicht. datenbank.get("P9") liefert None. Dieser Wert wird bewusst nicht gecacht, sonst bliebe ein später angelegtes Produkt P9 unsichtbar.
  5. „P1“ (dritte Anfrage) – Treffer. Stand: 2 Treffer, 3 Fehlgriffe.
  6. Preisänderung – die Falle – Der Preis von P1 sinkt auf 17.99. Würde nur die Datenbank geändert, lieferte der Cache weiter 19.99: Cache und Datenbank wären inkonsistent. Deshalb entfernt preis_aendern den Cache-Eintrag (pop mit Standardwert None, damit es auch ohne Eintrag keinen Fehler gibt). Die nächste Anfrage ist ein Fehlgriff und holt den neuen Preis.

Ergebnis: Die Ausgabe lautet

P1 19.99
P2 5.49
P1 19.99
P9 None
P1 19.99
{'treffer': 2, 'fehlgriffe': 3}
P1 17.99
{'treffer': 2, 'fehlgriffe': 4}
TestfallEingabeerwartete Ausgabe
Cache-Trefferpreis_holen("P1") zum zweiten Mal19.99, Treffer +1
unbekanntes Produktpreis_holen("P9")None, nichts im Cache
nach Preisänderungpreis_aendern("P1", 17.99), dann preis_holen("P1")17.99 (nicht 19.99)

Kontrolle: Treffer und Fehlgriffe zusammen ergeben die Zahl der Anfragen: 2 + 3 = 5 Anfragen in der Schleife, danach 2 + 4 = 6. Das Problem aus Schritt 6 ist dasselbe wie beim CAP-Theorem (Seite 2.1): Zwei Kopien derselben Daten müssen gleich gehalten werden.

Ausblick: Key-Value-Datenbanken in der Praxis und JSON

In der Realität werden Key-Value-Datenbanken häufig in groß angelegten Anwendungen verwendet. Sie arbeiten oft mit JSON (JavaScript Object Notation), einem Datenformat, das der Struktur von Python-Dictionaries sehr ähnlich ist. Viele moderne NoSQL-Datenbanken verarbeiten Daten im JSON-Format oder in einem sehr ähnlichen Format: Couchbase speichert JSON-Dokumente, DynamoDB speichert Datensätze mit verschachtelten Attributen, die sich direkt als JSON ein- und auslesen lassen. Redis speichert als Werte zunächst nur Zeichenketten, Listen, Hashes und Mengen; JSON-Dokumente mit Zugriff auf einzelne Felder kann Redis erst mit dem Modul RedisJSON (in neueren Redis-Versionen mitgeliefert). Ohne dieses Modul legt man JSON als einfache Zeichenkette ab. Ein JSON-Objekt sieht fast genauso aus wie ein Python-Dictionary: 

{
  "Name": "Alice",
  "Alter": 25,
  "Beruf": "Entwicklerin"
}

JSON ist besonders beliebt, weil es leichtgewichtig ist und einfach zwischen verschiedenen Programmiersprachen übertragen werden kann. Es eignet sich perfekt für Web-APIs, mobile Apps und Datenbanken, die schnell und flexibel sein müssen.

In großen Projekten verwendet man spezialisierte Key-Value-Datenbanken, die große Datenmengen speichern und schnell darauf zugreifen können. Python kann mit diesen Datenbanken interagieren, indem es z. B. JSON verwendet (siehe Seite 3.10). Auch wenn XML (ein weiteres Datenformat) in einigen Anwendungen genutzt wird, ist JSON heutzutage viel häufiger, da es kompakter und einfacher zu verwenden ist.

Diese modernen Technologien sind darauf ausgelegt, enorme Mengen von Schlüssel-Wert-Daten effizient zu verarbeiten und in verteilten Systemen zu speichern, was für große Webanwendungen oder mobile Apps unerlässlich ist.

Das Wichtigste

Key-Value-Datenbank: speichert jeden Datensatz als Paar aus einem eindeutigen Schlüssel und einem Wert. Gelesen und geschrieben wird immer über den Schlüssel; im Wert selbst wird nicht gesucht.

Einsatz: besonders schnell bei einfachen Zugriffen, z. B. für Konfigurationen, Sitzungsdaten oder Caches.

Dictionary: In Python schlägt man Werte über einen eindeutigen, aussagekräftigen Schlüssel nach – genau das Prinzip einer Key-Value-Datenbank.

Liste: eignet sich dagegen für geordnete Sammlungen gleichartiger Elemente.
