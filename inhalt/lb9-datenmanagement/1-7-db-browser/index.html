DB Browser für SQLite ist ein Open-Source-Tool zur Erstellung, Bearbeitung und Abfrage von SQLite-Datenbanken. Es bietet eine benutzerfreundliche grafische Oberfläche, mit der du SQLite-Datenbanken auch ohne SQL-Befehle verwalten kannst.

SQLite ist ein relationales Datenbankmanagementsystem, das sich von anderen Systemen wie MySQL oder PostgreSQL unterscheidet. Der Hauptunterschied liegt in der Ausführung:

  • Serverseitige Ausführung: Traditionelle Datenbanksysteme wie MySQL laufen auf einem separaten Server. Clients verbinden sich über ein Netzwerk mit diesem Server, um Datenbankoperationen durchzuführen.
  • Clientseitige Ausführung: SQLite wird direkt in die Anwendung integriert. Die gesamte Datenbank ist in einer einzigen Datei gespeichert, die lokal auf dem Gerät liegt.

Vorteile von SQLite:

  • Leichtgewichtig und schnell
  • Keine Serverinstallation oder -konfiguration erforderlich
  • Ideal für eingebettete Systeme und mobile Anwendungen
  • Einfach zu sichern (nur eine Datei)
  • Plattformunabhängig

Praxisbezug: SQLite im Alltag und im Beruf

SQLite steckt in fast jedem Smartphone: Messenger, Browser und Foto-Apps speichern ihre Daten in SQLite-Dateien, weil kein eigener Datenbankserver nötig ist. In der Datenbankadministration und der Softwareentwicklung nutzt man Werkzeuge wie DB Browser, um solche Dateien zu untersuchen, Testdaten anzulegen oder Fehler zu finden. Auch in der IT-Forensik, etwa beim Landeskriminalamt Sachsen, werden SQLite-Datenbanken aus beschlagnahmten Handys mit genau solchen Programmen ausgewertet – natürlich nur mit richterlichem Beschluss, denn es handelt sich um personenbezogene Daten.

Übung 1: Kurs-Datenbank

Beispiel 1 einfach

Ausgangssituation: Du hast einen SQL-Dump kurs.sql und möchtest die Daten darin im DB Browser ansehen. Der Dump ist noch keine Datenbank, sondern nur eine Textdatei mit Befehlen.

Importieren und erste Abfrage

  1. Lade die Datei kurs.sql herunter.
  2. Öffne DB Browser für SQLite.
  3. Klicke auf „Datei“ > „Importieren“ > „Datenbank aus SQL-Datei“.
  4. Wähle die Datei „kurs.sql“ aus und klicke auf „Öffnen“.
  5. Speichere die entstehende Datenbank unter einem passenden Namen ab (z. B. kurs.db).
  6. Gehe zum Reiter „SQL ausführen“.
  7. Gib folgende Abfrage ein und führe sie aus: 
    SELECT *
FROM Schueler;
  8. Betrachte das Ergebnis der Abfrage.

Was bei den wichtigsten Schritten passiert und warum:

  1. Importieren (Schritte 3–4): DB Browser führt die Befehle der Datei nacheinander aus: drei CREATE TABLE (Schueler, Kurs, Kursnote) und drei INSERT. Warum? Erst dadurch entstehen aus dem Text echte Tabellen mit Daten.
  2. Speichern (Schritt 5): Die Datenbank wird als eine einzige Datei abgelegt. Warum? Ohne Speichern wäre die importierte Datenbank nach dem Schließen verloren.
  3. Abfrage ausführen (Schritte 6–7): SELECT * FROM Schueler; liest alle Zeilen und Spalten der Tabelle Schueler. Warum gerade diese Abfrage? Sie zeigt ohne Vorwissen über die Spalten, ob der Import geklappt hat.

Ergebnis (mit den Daten aus kurs.sql):

s_idnamevorname
1MüllerLisa
2SchmidtMax
3FischerAnna
4WeberTim
5MeyerSophie

Kontrolle: Im Reiter „Datenbankstruktur“ müssen drei Tabellen stehen. Das Ergebnis hat 5 Zeilen – genau so viele, wie im Dump für Schueler eingefügt werden. Erscheint eine Fehlermeldung wie no such table: Schueler, ist der Import nicht gelaufen oder es wurde eine andere Datenbankdatei geöffnet.

Das Wichtigste

DB Browser (SQLite) ist ein grafisches Werkzeug für SQLite-Datenbanken. Eine SQLite-Datenbank ist eine einzige Datei (z. B. kurs.db). Ein SQL-Dump (.sql) ist dagegen nur ein Text mit SQL-Befehlen, der beim Import ausgeführt wird und die Tabellen samt Daten erzeugt: Datei > Importieren > Datenbank aus SQL-Datei. Änderungen werden erst mit „Änderungen schreiben“ (Strg + S) dauerhaft in der Datenbankdatei gespeichert.

Mit LIMIT n am Ende einer Abfrage begrenzt du die Anzahl der zurückgegebenen Zeilen auf n. In Kombination mit ORDER BY erhältst du so z. B. die ersten 5 Einträge einer sortierten Liste.
