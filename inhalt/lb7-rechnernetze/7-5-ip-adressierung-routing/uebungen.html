Aufgabe 7.5.3: Fehlersuche im Netzwerk AFB III

Öffne die Datei netz_fehlersuche.fls in Filius. Das Netz besteht aus zwei Client-Netzen mit je einem DHCP-Server, einem DNS-Server, einem Webserver unter der Adresse gdp.de und einem Vermittlungsrechner. Im Netz sind vier Fehler versteckt.

  1. Starte die Simulation und teste von je einem Client aus jedem Netz: ipconfig, ping zum Webserver, Aufruf von gdp.de im Browser.
  2. Grenze jeden Fehler systematisch ein. Arbeite dich dabei vom eigenen Rechner über das Gateway bis zum Ziel vor.
  3. Behebe die Fehler.
  4. Dokumentiere jeden Fehler in einer Tabelle mit Symptom, Ursache und Korrektur.
  5. Weise mit Screenshots nach, dass danach alle Clients die Webseite über den Namen erreichen.

Aufgabe 7.5.4: Routingtabellen erstellen AFB II
  1. Erstelle die Routingtabellen von R1, R2 und R3 (Zielnetz mit Präfix, Next Hop, Schnittstelle), sodass alle drei LANs einander und das Internet erreichen. Nimm die direkt angeschlossenen Netze mit auf und verwende Default-Routen, wo es möglich ist.
  2. Ein Rechner 192.168.10.5 sendet ein Paket mit TTL 64 an 192.168.30.8. Gib für jeden Router an, welcher Eintrag nach dem Longest-Prefix-Match gewählt wird, und mit welcher TTL das Paket ankommt.
  3. Verfolge ebenso die Antwort von 192.168.30.8 an 192.168.10.5.

Überlege für jeden Router: In welcher Richtung liegt „der Rest der Welt“? Dorthin zeigt die Default-Route.

Aufgabe 7.5.6: Was traceroute verrät AFB II

Das Programm tracert (Windows) bzw. traceroute sendet Pakete mit TTL 1, dann TTL 2, TTL 3 usw. an das Ziel. Ein Router, bei dem die TTL auf 0 sinkt, verwirft das Paket und schickt eine ICMP-Meldung „Zeitüberschreitung“ zurück – mit der Adresse der Schnittstelle, an der das Paket ankam. Das Ziel selbst antwortet mit einem Echo Reply.

  1. Gib die Ausgabe von tracert 192.168.30.8 auf dem Rechner 192.168.10.5 an (Nummer, antwortende Adresse) und erkläre, warum jede Zeile genau so entsteht.
  2. Nach einer Störung endet die Ausgabe nach Zeile 2, danach erscheinen nur noch Sternchen (keine Antwort). Nenne zwei mögliche Ursachen und wo du weitersuchen würdest.
  3. Erkläre mit der TTL, warum das Paket an 192.168.5.5 aus Aufgabe 7.5.5 nicht für immer im Netz bleibt.
