Was ist ein Unterprogramm?

Unterprogramme helfen dabei, …

  • … den Quellcode übersichtlicher zu gestalten,
  • … weniger Quellcode zu schreiben,
  • … denselben Code an verschiedenen Stellen im Programm wiederzuverwenden,
  • … das Programm leichter zu verändern,
  • … weniger Fehler zu erzeugen.

Warum Unterprogramme verwenden?

DRY steht für „Don't Repeat Yourself“. Nach diesem Prinzip vermeidet man in der Programmierung Redundanzen. Wenig redundanter Quellcode enthält weniger potenzielle Fehler und lässt sich auch im Nachhinein einfacher anpassen und aktuell halten.

Erstellen von Funktionen

Sie werden in Python mit dem Schlüsselwort def definiert und enthalten eine return-Anweisung, die den Wert zurückgibt.

def quadrat(x):
    return x * x

ergebnis = quadrat(4)   # der Rückgabewert 16 kann weiterverwendet werden

Erstellen von Prozeduren

Sie werden ebenfalls mit def definiert, enthalten jedoch keine return-Anweisung mit Wert. Streng genommen gibt jede Python-Funktion ohne return automatisch den Wert None zurück.

def gruesse(name):
    print("Hallo,", name)

gruesse("Lina")        # Ausgabe: Hallo, Lina
x = gruesse("Tom")     # Ausgabe: Hallo, Tom – x hat den Wert None
Beispiel 1 einfach

Ausgangssituation: Für einen Austausch mit einer Partnerschule in den USA soll eine Temperaturtabelle von Grad Celsius in Grad Fahrenheit entstehen. Die Umrechnung lautet F = C · 9 / 5 + 32.

def celsius_in_fahrenheit(c):          # Funktion: liefert einen Wert
    return c * 9 / 5 + 32

def drucke_tabelle(von, bis, schritt): # Prozedur: bewirkt eine Ausgabe
    for c in range(von, bis + 1, schritt):
        print(c, "°C =", celsius_in_fahrenheit(c), "°F")

drucke_tabelle(-20, 40, 20)
  1. Aufruf der Prozedur: Die Argumente −20, 40 und 20 werden an die Parameter von, bis und schritt übergeben. Warum: Die Zuordnung erfolgt nach der Reihenfolge.
  2. Schleife: range(-20, 41, 20) liefert −20, 0, 20, 40. Warum bis + 1: range schließt die Obergrenze aus.
  3. Aufruf der Funktion: Für c = −20 rechnet celsius_in_fahrenheit −20 · 9 / 5 + 32 = −36.0 + 32 = −4.0 und gibt den Wert mit return zurück. Die Prozedur setzt ihn in die Ausgabe ein.
  4. Rückkehr: Nach dem return geht es an der Aufrufstelle weiter, also in der print-Zeile der Prozedur.

Ergebnis:

-20 °C = -4.0 °F
0 °C = 32.0 °F
20 °C = 68.0 °F
40 °C = 104.0 °F

Beispiel 2 komplex

Ausgangssituation: Funktionen rufen andere Funktionen auf. Gesucht sind alle Primzahlen bis zu einer Grenze.

def ist_teiler(t, n):
    return n % t == 0

def ist_primzahl(n):
    if n < 2:
        return False
    for t in range(2, n):
        if ist_teiler(t, n):
            return False
    return True

def primzahlen_bis(grenze):
    treffer = []
    for n in range(2, grenze + 1):
        if ist_primzahl(n):
            treffer.append(n)
    return treffer

print(primzahlen_bis(20))   # [2, 3, 5, 7, 11, 13, 17, 19]
  1. Zerlegen in Teilaufgaben: „Ist t ein Teiler von n?“, „Ist n eine Primzahl?“ und „Sammle alle Primzahlen bis zur Grenze“. Warum: Jede Funktion hat genau eine Aufgabe und lässt sich einzeln testen.
  2. Aufrufhierarchie verfolgen für ist_primzahl(9): t = 2 → ist_teiler(2, 9) liefert False (9 % 2 = 1). t = 3 → ist_teiler(3, 9) liefert True, also gibt ist_primzahl sofort False zurück. Warum sofort: return beendet die Funktion, auch mitten in der Schleife.
  3. Sonderfälle zuerst: Zahlen kleiner als 2 sind keine Primzahlen. Deshalb prüft die erste Zeile n < 2. Ohne diese Prüfung wäre 1 eine „Primzahl“, weil range(2, 1) leer ist und direkt return True folgt.
  4. Zusammensetzen: primzahlen_bis ruft ist_primzahl für jede Zahl von 2 bis zur Grenze auf und sammelt die Treffer in einer Liste.
  5. Vorteil der Zerlegung: Soll die Primzahlprüfung schneller werden (es genügt, Teiler bis √n zu testen), ändert man nur ist_primzahl. Die anderen Funktionen bleiben unverändert (DRY).

Ergebnis: [2, 3, 5, 7, 11, 13, 17, 19].

Funktionen aus Modulen importieren

Einige grundlegende Funktionen wie print oder len sind als eingebaute Funktionen (built-ins) immer verfügbar. Viele weitere Funktionen stehen in Modulen: entweder in Modulen der mitgelieferten Standardbibliothek wie random oder math oder in zusätzlich installierten Paketen wie matplotlib. Mit der folgenden Syntax importierst du ein Modul, um auf die enthaltenen Funktionen zugreifen zu können:

# Zugriff auf alle enthaltenen Funktionen über den Modulnamen
import math
print(math.sqrt(16))      # Aufruf über die Punktnotation

# alle Funktionen direkt importieren (unübersichtlich, besser vermeiden)
from math import *
print(sqrt(16))

# Es können auch nur einzelne Funktionen eines Moduls importiert werden:
from random import randint
print(randint(1, 6))

Neben den Modulen der Standardbibliothek kannst du auch eigene Funktionen in Modulen speichern und importieren. Module sind eine flexible Möglichkeit, Code zu organisieren und zu strukturieren. Das erleichtert die Entwicklung und verbessert die Qualität des Codes.

# Datei mein_modul.py
def sag_hallo(name):
    print("Hallo, " + name + "!")
# Datei hauptprogramm.py im selben Ordner
import mein_modul

mein_modul.sag_hallo("Python")
Praxisbezug: Bibliotheken statt Rad neu erfinden

Alltag: Jede App, die dir das Wetter anzeigt, ruft Funktionen auf wie „hole Wetterdaten für Dresden“ – geschrieben hat sie meist jemand anderes und in einer Bibliothek bereitgestellt.

Beruf: In Softwarefirmen arbeiten Teams arbeitsteilig an Modulen: Ein Team entwickelt z. B. das Modul für die Zahlungsabwicklung, ein anderes nutzt nur dessen Funktionen. Gute Funktionsnamen, klare Parameter und eine Dokumentation (Docstring) sind deshalb im Berufsalltag genauso wichtig wie korrekter Code.

Das Wichtigste

Ein Unterprogramm ist ein benannter, wiederverwendbarer Codeblock, der eine bestimmte Teilaufgabe erfüllt und über seinen Namen aufgerufen wird. Man unterscheidet Funktionen (liefern mit return einen Wert zurück) und Prozeduren (bewirken etwas, z. B. eine Ausgabe, ohne einen Wert zurückzugeben).

Funktionen sind Unterprogramme, die einen Wert zurückgeben.

Prozeduren sind Unterprogramme, die keinen Wert zurückgeben.

Grundaufgaben

Aufgabe 2.1.5.1: Funktionen und Prozeduren schreiben AFB I–II
  1. Erstelle eine Funktion addiere(a, b), die zwei Zahlen addiert und das Ergebnis zurückgibt. Rufe die Funktion auf und gib das Ergebnis aus.
  2. Erstelle eine Prozedur drucke_zufallszahl(), die eine zufällige Zahl zwischen 1 und 100 erzeugt und ausgibt. (Hinweis: Du brauchst dafür das Modul random und daraus die Funktion randint.)
  3. Erstelle eine Funktion zufallsliste(), die eine Liste mit 100 zufälligen Zahlen zwischen 1 und 6 erstellt und zurückgibt.
  4. Erstelle eine Funktion gerade(zahl), die überprüft, ob eine übergebene Zahl gerade ist, und True oder False zurückgibt.
  5. Erstelle eine Funktion palindrom(text), die prüft, ob ein Text ein Palindrom ist, und das Ergebnis zurückgibt.
  6. Erstelle eine Funktion pasch(), die zwei Würfelzahlen zufällig erzeugt und prüft, ob es sich um einen Pasch handelt. Zurückgegeben wird, ob ein Pasch gewürfelt wurde (True) oder nicht (False).
Aufgabe 2.1.5.2: Eigenes Modul AFB II

Erstelle eine Funktion sag_hallo(name) und speichere das Programm als mein_modul.py. Erstelle eine zweite Datei im selben Ordner und importiere daraus die Funktion sag_hallo(). Erweitere das Modul um eine zweite Funktion und nutze sie ebenfalls.
