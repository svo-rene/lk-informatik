Parameter sind die „Eingänge“ eines Unterprogramms. Beim Aufruf werden Argumente übergeben, zum Beispiel verdopple(wert). Spannend ist die Frage: Kann das Unterprogramm dabei die Variable des Aufrufers verändern? Programmiersprachen beantworten das unterschiedlich.

Referenzparameter (call by reference)

Beide Arten gibt es z. B. in Pascal (var-Parameter) oder C++ (&-Parameter). In Python gibt es keine echten Referenzparameter.

Parameter in Python: call by sharing

Beispiel 1 einfach

Ausgangssituation: neue Zuweisung – das Original bleibt gleich

def verdopple(zahl):
    zahl = zahl * 2       # zahl zeigt jetzt auf ein neues int-Objekt
    return zahl

wert = 5
verdopple(wert)
print(wert)               # Ausgabe: 5 (wert zeigt weiterhin auf 5)
print(verdopple(wert))    # Ausgabe: 10 (Rückgabewert)

Zahlen, Texte und Tupel sind in Python unveränderlich (immutable). Bei ihnen verhält sich call by sharing deshalb wie ein Werteparameter.

Im Speicherbild stehen links die Namen, rechts die Objekte im Speicher. Ein Pfeil bedeutet „zeigt auf“.

  1. Nach wert = 5: 
    global      wert ──────► [int 5]
  2. Beim Aufruf verdopple(wert): Der Parameter zahl erhält eine Referenz auf dasselbe Objekt. Kopiert wird nichts. 
    global      wert ──────┐
                       ├──► [int 5]
verdopple   zahl ──────┘
  3. Nach zahl = zahl * 2: zahl * 2 erzeugt ein neues Objekt 10, und nur zahl wird umgehängt. Warum: Ein int-Objekt lässt sich nicht verändern, jede Rechnung erzeugt ein neues Objekt. 
    global      wert ──────► [int 5]
verdopple   zahl ──────► [int 10]
  4. Nach dem return: Der Name zahl verschwindet mit dem Funktionsaufruf. Der Rückgabewert 10 wird in Zeile 6 nicht gespeichert und geht verloren.

Ergebnis: Ausgabe 5, dann 10. Wer das Ergebnis behalten will, muss es zuweisen: wert = verdopple(wert).

Beispiel 2 komplex

Ausgangssituation: Verändern und neu Zuweisen einer Liste im Vergleich

def aendere_liste(liste):
    liste.append(42)      # verändert das gemeinsame Objekt

def ersetze_liste(liste):
    liste = [0, 0, 0]     # nur der Parameter zeigt auf eine neue Liste

zahlen = [1, 2, 3]
aendere_liste(zahlen)
print(zahlen)             # [1, 2, 3, 42]
ersetze_liste(zahlen)
print(zahlen)             # [1, 2, 3, 42] – unverändert!
  1. Aufruf aendere_liste(zahlen): liste und zahlen zeigen auf dieselbe Liste. append verändert dieses eine Objekt. 
    global          zahlen ──┐
                         ├──► [list 1, 2, 3, 42]
aendere_liste   liste  ──┘
    Warum sieht der Aufrufer die Änderung? Es gibt nur ein Listenobjekt, und Listen sind veränderlich (mutable).
  2. Aufruf ersetze_liste(zahlen): Zuerst zeigen wieder beide Namen auf dieselbe Liste. Dann erzeugt [0, 0, 0] eine neue Liste, und nur liste wird umgehängt. 
    global          zahlen ──► [list 1, 2, 3, 42]
ersetze_liste   liste  ──► [list 0, 0, 0]     (verschwindet nach dem Aufruf)
  3. Falle +=: Bei Listen verändert liste += [7] das vorhandene Objekt (wie extend). liste = liste + [7] erzeugt dagegen eine neue Liste. 
    def anhaengen_a(liste):
    liste += [7]              # verändert das gemeinsame Objekt

def anhaengen_b(liste):
    liste = liste + [7]       # neue Liste, nur lokal

z = [1]
anhaengen_a(z)
print(z)                      # [1, 7]
anhaengen_b(z)
print(z)                      # [1, 7]
    Warum ist das eine Falle? Bei Zahlen sehen x += 1 und x = x + 1 gleich aus und verhalten sich gleich. Bei Listen verhalten sie sich unterschiedlich.
  4. Kontrolle mit id: id(objekt) liefert eine Kennnummer des Objekts. Gibt man id(liste) in der Funktion und id(zahlen) außerhalb aus, erscheint dieselbe Zahl. Nach liste = [0, 0, 0] ist sie verschieden.

Ergebnis: Veränderungen am Objekt (append, +=, liste[0] = …) wirken nach außen. Neue Zuweisungen an den Parameter wirken nicht nach außen. Soll eine Funktion die übergebene Liste nicht verändern, arbeitet sie mit einer Kopie: kopie = liste.copy().

Praxisbezug: Nebenwirkungen vermeiden

Alltag: Teilst du ein Online-Dokument per Link, arbeiten alle am selben Dokument – Änderungen sehen alle (wie append bei call by sharing). Schickst du dagegen eine Kopie als Anhang, bleibt dein Original unberührt (wie eine Kopie mit copy()).

Beruf: Unerwartete Änderungen an übergebenen Listen oder Objekten („Seiteneffekte“) gehören zu den häufigsten Fehlern in größeren Python-Projekten. In Code-Reviews achten Softwareentwicklerinnen und -entwickler deshalb darauf, dass Funktionen übergebene Daten nur dann verändern, wenn das im Namen oder in der Dokumentation klar erkennbar ist.

Das Wichtigste

Werteparameter erhalten eine Kopie des übergebenen Werts. Änderungen am Parameter innerhalb des Unterprogramms wirken sich nicht auf die Variable des Aufrufers aus.

Referenzparameter erhalten einen Verweis auf die Variable des Aufrufers. Jede Änderung am Parameter – auch eine neue Zuweisung – verändert die Variable des Aufrufers.

Python übergibt an den Parameter immer eine Referenz auf das Objekt, kopiert wird dabei nichts. Man nennt das call by sharing (auch „call by object reference“). Daraus folgt:
1. Wird dem Parameter ein neuer Wert zugewiesen (zahl = zahl * 2), zeigt nur der Parameter auf ein neues Objekt. Die Variable des Aufrufers bleibt unverändert.
2. Wird ein veränderbares Objekt (Liste, Dictionary, eigenes Objekt) über den Parameter verändert (liste.append(42)), sieht der Aufrufer die Änderung, denn beide Namen zeigen auf dasselbe Objekt.

Erstelle eine Funktion addiere(a, b), die zwei Zahlen entgegennimmt und ihre Summe zurückgibt. Rufe die Funktion auf und gib das Ergebnis aus.
