In der Informatik gibt es zwei grundlegende Techniken, um Abläufe zu wiederholen: Iteration und Rekursion. Stell dir zwei Spiegel vor, die sich gegenüberstehen: Das Bild enthält sich selbst immer kleiner – das ist die Grundidee der Rekursion.

Schritt 1: Die Idee – Wie viele stehen vor dir?

Rekursion löst ein Problem, indem sie dieselbe Frage für ein kleineres Problem stellt. Das Video zeigt das an einer Mensa-Schlange: Niemand überblickt die ganze Schlange, trotzdem kommt die richtige Antwort heraus. Achte auf zwei Dinge: Wo hört das Weiterfragen auf (Basisfall)? Und in welche Richtung fließen danach die Antworten?

Kurz geprüft 1: Puppen zählen AFB I

Eine Matroschka enthält eine kleinere Puppe, diese wieder eine kleinere und so weiter. Die kleinste Puppe lässt sich nicht öffnen. Beschreibe, wie du die Anzahl der Puppen rekursiv bestimmst: Was ist der Basisfall, was der rekursive Fall?

Lösung zeigen

Basisfall: Die Puppe lässt sich nicht öffnen – Anzahl 1. Rekursiver Fall: Puppe öffnen, die Puppen in der inneren Puppe (nach derselben Regel) zählen und 1 addieren.

Schritt 2: Die Summe mit einer Schleife (Iteration)

Iteration ist ein wiederholter Prozess, bei dem eine Aufgabe Schritt für Schritt wiederholt wird, bis eine bestimmte Bedingung erfüllt ist. Das geschieht mit Schleifen, zum Beispiel einer for- oder einer while-Schleife. Im Video verfolgst du sum_iteration(3) in einer Tabelle. Kurz erklärt wird range(n + 1).

Zum Nachlesen – Beispiel in Python: die Summe von 0 bis n mit Iteration berechnen

def sum_iteration(n):
    result = 0
    for i in range(n + 1):
        result = result + i
    return result

n = 5
print("Summe von 0 bis", n, "mit Iteration:", sum_iteration(n))
# Ausgabe: Summe von 0 bis 5 mit Iteration: 15
Kurz geprüft 2: Die Schleife verfolgen AFB I

Welche Zahlen liefert range(4 + 1)? Welchen Wert hat result nach jedem Schleifendurchlauf von sum_iteration(4)?

Lösung zeigen

range(5) liefert 0, 1, 2, 3, 4. result ist nacheinander 0, 1, 3, 6, 10 – Rückgabe 10.

Schritt 3: Die Summe rekursiv

Bei der Rekursion ruft eine Funktion sich selbst auf, um ein Problem in kleinere Teilprobleme aufzuteilen und diese zu lösen. Jeder rekursive Aufruf verkleinert das Problem, bis die Abbruchbedingung erreicht ist. Achte im Video darauf, welche Zeilen den Basisfall und welche den Rekursionsschritt bilden, und vergleiche mit der Schleife aus Schritt 2.

Zum Nachlesen – Beispiel in Python: die Summe von 0 bis n mit Rekursion berechnen

def sum_recursion(n):
    # Abbruchbedingung
    if n == 0:
        return 0
    # Rekursionsschritt
    else:
        return n + sum_recursion(n - 1)

n = 5
print("Summe von 0 bis", n, "mit Rekursion:", sum_recursion(n))
# Ausgabe: Summe von 0 bis 5 mit Rekursion: 15

In diesem Beispiel ist die Abbruchbedingung erreicht, wenn n gleich 0 ist. Ist n größer als 0, ruft sich die Funktion selbst mit n − 1 auf und addiert n zum Ergebnis dieses Aufrufs.

Kurz geprüft 3: Basisfall und Rekursionsschritt AFB I

Schreibe die Kette der Aufrufe für sum_recursion(4) auf. Was ist das Ergebnis? Welcher Aufruf ruft sich nicht mehr selbst auf?

Lösung zeigen

sum_recursion(4) = 4 + sum_recursion(3) = 4 + 3 + sum_recursion(2) = … = 4 + 3 + 2 + 1 + sum_recursion(0) = 10. sum_recursion(0) ist der Basisfall und gibt direkt 0 zurück.

Schritt 4: Rekursion Schritt für Schritt – der Aufrufstapel

Was macht Python, wenn sich eine Funktion selbst aufruft? Jeder Aufruf, der noch auf ein Ergebnis wartet, liegt auf dem Aufrufstapel. Im Video wächst der Stapel bei sum_recursion(3) zuerst (Abstieg) und schrumpft dann wieder (Aufstieg). Achte darauf, dass jeder Aufruf sein eigenes n hat und wie die Rückgabewerte von oben nach unten durchgereicht werden.

Zum Nachlesen steht der Ablauf mit Aufrufstapel und Testfällen in Beispiel 1:

Beispiel 1 einfach

Ausgangssituation: Ablauf von sum_recursion(3)

Jeder Aufruf, der noch auf ein Ergebnis wartet, liegt auf dem Aufrufstapel (engl. call stack). Ein neuer Aufruf wird oben aufgelegt, ein beendeter Aufruf oben entfernt.

  1. Abstieg: sum_recursion(3) kann nicht sofort antworten und ruft sum_recursion(2) auf. Der Aufruf mit n = 3 bleibt mit seiner offenen Rechnung „3 + ?“ auf dem Stapel liegen. Genauso geht es mit n = 2 und n = 1 weiter.
  2. Abbruchbedingung: sum_recursion(0) erreicht den Basisfall und gibt 0 sofort zurück. Warum nötig: Ohne Basisfall würde der Stapel immer weiter wachsen.
  3. Aufstieg: Die wartenden Aufrufe werden von oben nach unten abgeschlossen. Jeder setzt den erhaltenen Wert in seine offene Rechnung ein.

Schritt 5: Wenn die Rekursion nicht endet

Der häufigste Fehler bei Rekursion: Der Basisfall fehlt oder wird nie erreicht. Dann ruft sich die Funktion immer weiter auf, bis Python mit RecursionError abbricht. Im Video siehst du diese Fehlermeldung in der Kommandozeile und erfährst, warum sogar eine korrekte Rekursion an eine Grenze stoßen kann, die eine Schleife nicht hat.

Zum Nachlesen: Beispiel 2 zeigt, wo Rekursion ihre Stärke hat (verschachtelte Daten wie Ordner), wo sie an die Grenze der Rekursionstiefe stößt und wie man dieselbe Aufgabe iterativ mit einem eigenen Stapel löst.

Beispiel 2 komplex

Ausgangssituation: rekursives Durchsuchen einer verschachtelten Liste (wie Ordner mit Unterordnern)

def zaehle_dateien(ordner):
    anzahl = 0
    for eintrag in ordner:
        if isinstance(eintrag, list):      # Unterordner
            anzahl = anzahl + zaehle_dateien(eintrag)
        else:                              # Datei
            anzahl = anzahl + 1
    return anzahl

schule = ["plan.pdf", ["info.py", ["alt.py", "neu.py"]], "notizen.txt"]
print(zaehle_dateien(schule))   # 5

Hier ist die Rekursion natürlicher als eine Schleife, weil die Schachtelungstiefe vorher nicht bekannt ist.

  1. Basisfall erkennen: Ein Eintrag, der keine Liste ist, ist eine Datei und zählt 1. Ein leerer Ordner liefert 0, weil die Schleife nicht läuft. Warum gibt es kein eigenes if für den Basisfall? Die Rekursion endet automatisch, sobald keine Unterordner mehr da sind.
  2. Rekursionsschritt: Für jeden Unterordner wird dieselbe Funktion mit dem kleineren Teilproblem aufgerufen. Das Ergebnis wird zur eigenen Anzahl addiert.
  3. Aufrufbaum zeichnen: Jeder Knoten ist ein Aufruf, die Kinder sind die Aufrufe, die er selbst auslöst. 
    zaehle(schule)                              -> 1 + 3 + 1 = 5
├── "plan.pdf"                              +1
├── zaehle(["info.py", [...]])              -> 1 + 2 = 3
│   ├── "info.py"                           +1
│   └── zaehle(["alt.py", "neu.py"])        -> 2
│       ├── "alt.py"                        +1
│       └── "neu.py"                        +1
└── "notizen.txt"                           +1
    Es gibt 3 Aufrufe. Höchstens 3 sind gleichzeitig offen, die Rekursionstiefe entspricht also der Schachtelungstiefe der Ordner.
  4. Falle Rekursionstiefe: Eine 2000-fach verschachtelte Liste führt zu 2001 gleichzeitig offenen Aufrufen. Python bricht mit RecursionError: maximum recursion depth exceeded ab, obwohl die Funktion korrekt ist. 
    tief = []
for i in range(2000):
    tief = [tief]              # [[[[ … ]]]] – 2000 Ebenen
zaehle_dateien(tief)           # RecursionError
  5. Iterative Lösung mit eigenem Stapel: Jede Rekursion lässt sich iterativ formulieren. Man verwaltet die noch zu bearbeitenden Ordner selbst in einer Liste, die als Stapel dient (append legt auf, pop nimmt oben weg). 
    def zaehle_dateien_iterativ(ordner):
    anzahl = 0
    stapel = [ordner]
    while len(stapel) > 0:
        aktuell = stapel.pop()
        for eintrag in aktuell:
            if isinstance(eintrag, list):
                stapel.append(eintrag)     # später bearbeiten
            else:
                anzahl = anzahl + 1
    return anzahl

print(zaehle_dateien_iterativ(schule))   # 5
print(zaehle_dateien_iterativ(tief))     # 0 – kein RecursionError

Ergebnis: 5 Dateien. Die rekursive Fassung ist kürzer und folgt direkt der Struktur der Daten. Die iterative Fassung ist länger, kommt aber mit beliebig tiefer Schachtelung zurecht.

def schritte(n):
    if n == 0:
        return 0
    return 1 + schritte(n - 2)

Für welche Werte von n liefert schritte(n) ein Ergebnis, für welche gibt es einen RecursionError? Wie lässt sich die Funktion absichern?

Lösung zeigen

Nur für gerade n ≥ 0 wird 0 genau getroffen (z. B. 6, 4, 2, 0 → Ergebnis 3). Bei ungeraden oder negativen n springt n an 0 vorbei (z. B. 3, 1, −1, −3, …) – RecursionError. Absichern mit if n <= 0: als Basisfall.

Praxisbezug: Rekursion im Alltag und im Beruf

Alltag: Wenn du auf deinem Rechner die Größe eines Ordners anzeigen lässt, berechnet das Betriebssystem rekursiv die Größe aller Unterordner. Auch Fraktale wie der Romanesco-Kohl oder Schneeflocken sind rekursive Strukturen.

Beruf: Compiler und Interpreter zerlegen Programmcode rekursiv, weil Ausdrücke wie (a + (b * c)) ineinander geschachtelt sind. Wer beruflich Suchmaschinen, Dateisysteme oder Spiele-KI (z. B. Schachprogramme) entwickelt, arbeitet ständig mit rekursiven Algorithmen.

Zusammenfassung

Iteration und Rekursion sind zwei unterschiedliche Ansätze zur Lösung von Problemen. Die Wahl zwischen ihnen hängt von der Struktur des Problems und von den Anforderungen deiner Implementierung ab. Jede rekursive Lösung lässt sich auch iterativ formulieren; rekursive Lösungen sind oft kürzer, brauchen aber für jeden offenen Aufruf Speicher auf dem Aufrufstapel.

Das Wichtigste

Iteration: Wiederholung mithilfe einer Schleife (for, while).

Rekursion: Eine Funktion ruft sich selbst mit einem kleineren Teilproblem auf. Sie braucht eine Abbruchbedingung und einen Rekursionsschritt.

Abbruchbedingung (Basisfall): liefert das Ergebnis direkt, ohne weiteren Aufruf.

Rekursionsschritt: verkleinert das Problem und ruft die Funktion erneut auf.

Fehlender Basisfall: Fehlt die Abbruchbedingung oder wird sie nie erreicht, bricht Python mit RecursionError ab (Standardgrenze: etwa 1000 Aufrufe).
