Aufgabe 2.2.7.4: Warum die rekursive Fibonacci-Funktion exponentiell ist AFB III 
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
  1. Zeichne den vollständigen Aufrufbaum für fib(4). Markiere Teilbäume, die mehrfach berechnet werden.
  2. A(n) sei die Anzahl aller Aufrufe beim Berechnen von fib(n). Stelle eine Rekursionsgleichung für A(n) auf und berechne A(0) bis A(10).
  3. Begründe mit der Gleichung, dass A(n) ≤ 2n+1 gilt, die Laufzeit also in O(2n) liegt, und dass A(n) ≥ 2(n−1)/2 gilt, die Laufzeit also tatsächlich exponentiell wächst.
  4. Die Rekursionstiefe von fib(n) ist nur n. Erkläre, wie das zu exponentiell vielen Aufrufen passt.
  5. Miss mit time.perf_counter() die Zeit für fib(20), fib(22), fib(24) und fib(26). Gib den Faktor an, um den die Zeit wächst, wenn n um 2 steigt.
  6. Schreibe eine iterative Fassung fib_iterativ(n) in O(n) und teste beide Fassungen mit n = 0, 1, 2, 10 und 20. Bei negativen oder nicht ganzzahligen n soll fib_iterativ None zurückgeben.
Aufgabe 2.2.7.5: Fehler finden – drei kaputte Rekursionen AFB III 
# A: soll x hoch n berechnen (n ≥ 0)
def potenz(x, n):
    if n == 1:
        return x
    return x * potenz(x, n - 1)

# B: soll die Summe einer Liste berechnen
def summe_liste(liste):
    if len(liste) == 0:
        return 0
    return liste[0] + summe_liste(liste)

# C: soll 3, 2, 1, Start! ausgeben
def countdown(n):
    if n == 0:
        print("Start!")
    print(n)
    countdown(n - 1)
  1. Lege für jede Funktion eine Tabelle Eingabe | erwartete Ausgabe | tatsächliche Ausgabe an. Verwende potenz(2, 3), potenz(2, 0), summe_liste([]), summe_liste([4]) und countdown(3).
  2. Benenne jeweils, welche der beiden Bedingungen für eine korrekte Rekursion verletzt ist: Basisfall vorhanden und erreichbar, Problem wird in jedem Schritt kleiner.
  3. Korrigiere alle drei Funktionen.
