Aufgabe 2.2.6.6: Fehler finden im Struktogramm AFB III

Das Struktogramm beschreibt eine lineare Suche:

┌──────────────────────────────────────────────┐
│ Eingabe: liste, x                            │
├──────────────────────────────────────────────┤
│ i ← 0                                        │
├──────────────────────────────────────────────┤
│ solange i < Länge(liste) und liste[i] ≠ x    │
│   ┌──────────────────────────────────────────┤
│   │ i ← i + 1                                │
├───┴──────────────────────────────────────────┤
│ Ausgabe: „gefunden an Position“, i           │
└──────────────────────────────────────────────┘
  1. Bestimme die Ausgabe für liste = [4, 8, 1] mit x = 8, mit x = 5 sowie für die leere Liste mit x = 5. Lege eine Tabelle Eingabe | erwartete Ausgabe | tatsächliche Ausgabe an.
  2. Beschreibe den Fehler und korrigiere das Struktogramm.
  3. Ein Mitschüler setzt die Schleifenbedingung in Python als while liste[i] != x and i < len(liste): um. Gib an, bei welchen Testfällen das Programm abstürzt, und begründe mit der Auswertungsreihenfolge von and.
Aufgabe 2.2.6.7: Zahlenraten ohne Sprung darstellen AFB III

Beim Zahlenraten aus Aufgabe 2.1.2.2 endet die Schleife, wenn die Zahl erraten wurde oder 7 Versuche verbraucht sind. Viele Lösungen verwenden dafür break. Struktogramme kennen keine Sprünge, deshalb müssen beide Abbruchgründe in die Schleifenbedingung.

  1. Erstelle ein Struktogramm mit einer kopfgesteuerten Schleife, deren Bedingung beide Abbruchgründe enthält. Verwende eine Variable erraten.
  2. Damit sich das Programm testen lässt, werden die Tipps nicht eingegeben, sondern als Liste übergeben. Implementiere rateversuche(geheim, tipps) nach deinem Struktogramm. Die Funktion gibt die Anzahl der Versuche bis zum Treffer zurück. Wurde nach 7 Versuchen oder am Ende der Liste nicht getroffen, gibt sie None zurück. Teste mit (42, [50, 25, 42]), (42, []), (1, [1]), (42, [1, 2, 3, 4, 5, 6, 7, 42]) und (42, [42, 42]).
  3. Beurteile, welche Darstellung (Pseudocode, Struktogramm oder PAP) am besten geeignet ist (a) für ein Gespräch mit einer Spieleentwicklerin ohne Programmierkenntnisse, (b) für die Umsetzung in Python und (c) für die Suche nach einem Fehler in der Abbruchbedingung.
