Mergesort teilt stur in der Mitte und hat die ganze Arbeit beim Zusammenführen. Quicksort macht es genau umgekehrt: Er steckt die Arbeit ins Aufteilen – und danach muss nichts mehr zusammengeführt werden. Quicksort ist eines der am häufigsten eingesetzten Sortierverfahren überhaupt, braucht in der einfachen Form keinen zusätzlichen Speicher und ist im Mittel sehr schnell. Er hat aber eine Schwachstelle, die du auf dieser Seite selbst auslösen wirst.

Die Idee in einem Bild

Stell dir eine Klasse vor, die sich der Größe nach aufstellen soll. Eine Person – das Pivot – stellt sich in die Mitte. Alle anderen vergleichen sich nur mit ihr: Wer kleiner ist, geht nach links, wer größer ist, nach rechts. Jetzt steht die Pivot-Person schon richtig, egal wie es links und rechts aussieht! Dann machen die linke und die rechte Gruppe für sich dasselbe, jede mit ihrem eigenen Pivot – bis jede Gruppe nur noch aus einer Person besteht.

  • Aufteilen ist die eigentliche Arbeit: Jedes Element wird einmal mit dem Pivot verglichen.
  • Zusammensetzen kostet nichts: links + Pivot + rechts liegt schon in der richtigen Reihenfolge.
  • Gut ist ein Pivot, das die Gruppe ungefähr halbiert. Dann gibt es wie bei Mergesort nur etwa log2 n Ebenen.
Mit den Karten: Station Quicksort

Holt eure Zahlenkarten aus 2.2.1 wieder heraus. Es gelten die bekannten Regeln, neu erlaubt sind ein linker und ein rechter Stapel.

  1. Die letzte Karte der Reihe wird das Pivot. Sie liegt offen in der Mitte (Zeiger „Pivot“).
  2. Jede andere Karte wird einzeln aufgedeckt und nur mit dem Pivot verglichen (1 Strich V): kleiner → linker Stapel, sonst → rechter Stapel.
  3. Das Pivot liegt jetzt an seinem endgültigen Platz und wird nie wieder angefasst.
  4. Mit dem linken und dem rechten Stapel macht ihr dasselbe – gern zwei Personen gleichzeitig. Stapel mit einer oder keiner Karte sind fertig.

Spielt Quicksort zweimal: mit gut gemischten Karten und mit Karten, die schon sortiert liegen. Vergleicht die Strichlisten (Aufgabe 2.2.9b.1).

Schritt 2: Quicksort in Python

Die einfachste Fassung baut beim Aufteilen drei neue Listen und hängt die sortierten Teile am Ende aneinander. Das ist fast wörtlich die Idee aus Schritt 1:

def quicksort(liste):
    if len(liste) <= 1:
        return liste
    pivot = liste[len(liste) - 1]       # letzte Zahl als Pivot
    kleiner = []
    gleich = []
    groesser = []
    for x in liste:
        if x < pivot:
            kleiner.append(x)
        elif x == pivot:
            gleich.append(x)
        else:
            groesser.append(x)
    return quicksort(kleiner) + gleich + quicksort(groesser)

zahlen = [4, 7, 2, 6, 1, 5]
zahlen = quicksort(zahlen)
print(zahlen)   # [1, 2, 4, 5, 6, 7]
Kurz erklärt: elif und + bei Listen

elif heißt „sonst, wenn“: Es wird nur geprüft, wenn die Bedingung davor falsch war. So landet jede Zahl in genau einer der drei Listen. + hängt zwei Listen zu einer neuen Liste aneinander:

>>> [1, 2] + [4]
[1, 2, 4]
>>> [] + [5] + [6, 7]
[5, 6, 7]

Wie bei Mergesort gibt quicksort eine neue Liste zurück. Deshalb steht im Programm zahlen = quicksort(zahlen).

Und in Zeile 15 werden nur noch Listen aneinandergehängt – dort passiert kein einziger Vergleich mehr. Probiere auch eine Liste mit doppelten Zahlen, z. B. 5, 3, 5, 1, 5.

Schritt 3: Die Schwachstelle – ein schlechtes Pivot

Quicksort ist nur dann schnell, wenn das Pivot die Liste ungefähr halbiert. Was passiert, wenn die Liste schon sortiert ist und wir immer die letzte Zahl als Pivot nehmen? Probiere es aus: Im Labor unten liegt eine sortierte Liste. Schau dir den Baum an – und dann stelle oben „Pivot: mittlere Zahl“ ein.

Bei der sortierten Liste ist das letzte Element immer das größte. Dann ist groesser immer leer, und kleiner enthält alle übrigen Zahlen: Jeder Aufruf wird nur um eine Zahl kleiner. Statt log2 n Ebenen gibt es n Ebenen, und die Vergleiche summieren sich zu n + (n − 1) + … + 2 ≈ n² / 2 – so schlecht wie Bubblesort.

Liste mit 8 ZahlenPivotEbenen im BaumVergleiche mit dem Pivot

schon sortiert: 1, 2, …, 8letzte Zahl88 + 7 + … + 2 = 35
schon sortiert: 1, 2, …, 8mittlere Zahl417

Deshalb nimmt man in der Praxis nicht blind das erste oder letzte Element, sondern das mittlere, ein zufälliges oder den Median aus drei Elementen (erstes, mittleres, letztes). Ganz ausschließen lässt sich der schlechteste Fall damit nicht, aber er wird extrem unwahrscheinlich.

Schritt 4: Quicksort ohne zusätzliche Listen (in place)

Die Fassung aus Schritt 2 baut bei jedem Aufruf drei neue Listen – das kostet Speicher, genau wie bei Mergesort. Der eigentliche Vorteil von Quicksort ist, dass das Aufteilen auch in derselben Liste geht, nur durch Tauschen. Das heißt Partitionieren. Statt Teillisten bekommt quicksort zwei Grenzen links und rechts: Sortiert wird nur der Bereich dazwischen.

So funktioniert partitioniere (Pivot ist die Zahl ganz rechts im Bereich):

  1. Der Zeiger grenze startet links. Links von grenze sammeln sich die Zahlen, die kleiner als das Pivot sind (im Labor blau).
  2. Der Zeiger j läuft von links bis vor das Pivot. Ist liste[j] kleiner als das Pivot, wird es an die Stelle grenze getauscht, und grenze rückt eins weiter. Sonst bleibt es, wo es ist (orange).
  3. Zum Schluss wird das Pivot an die Stelle grenze getauscht. Jetzt steht links nur Kleineres, rechts nur Größeres oder Gleiches – und das Pivot an seinem endgültigen Platz p.
  4. Dann werden die Bereiche links und rechts von p genauso sortiert.
def tausche(liste, a, b):
    temp = liste[a]
    liste[a] = liste[b]
    liste[b] = temp

def partitioniere(liste, links, rechts):
    pivot = liste[rechts]
    grenze = links
    for j in range(links, rechts):
        if liste[j] < pivot:
            tausche(liste, grenze, j)
            grenze = grenze + 1
    tausche(liste, grenze, rechts)
    return grenze

def quicksort(liste, links, rechts):
    if links < rechts:
        p = partitioniere(liste, links, rechts)
        quicksort(liste, links, p - 1)
        quicksort(liste, p + 1, rechts)

zahlen = [5, 8, 2, 9, 1, 7, 3, 6]
quicksort(zahlen, 0, len(zahlen) - 1)
print(zahlen)   # [1, 2, 3, 5, 6, 7, 8, 9]

Diese Fassung gibt nichts zurück – sie sortiert die übergebene Liste selbst (call by sharing, 2.1.6). Deshalb steht hier kein zahlen = ….

Praxisbezug: Quicksort in echter Software

Alltag: Wenn eine Tabellenkalkulation eine Spalte mit Zahlen sortiert oder ein Spiel seine Objekte nach Entfernung ordnet, steckt oft eine Variante von Quicksort dahinter – sie ist im Mittel sehr schnell und braucht kaum zusätzlichen Speicher.

Beruf: Die Standardbibliotheken von C++ und Java sortieren Zahlen mit verbesserten Quicksort-Varianten (Median-of-three, zwei Pivots, Umschalten auf Insertionsort für kleine Bereiche). Weil eine böswillig gewählte Eingabe den schlechtesten Fall auslösen kann, schalten manche Implementierungen bei zu tiefer Rekursion auf ein anderes Verfahren um („Introsort“). Python selbst verwendet für sorted() Timsort, eine Mischung aus Mergesort und Insertionsort – weil es stabil sein soll.

Zusammenfassung

Quicksort wählt ein Pivot, teilt die übrigen Elemente in kleinere und größere auf und sortiert beide Teile rekursiv. Das Pivot steht danach endgültig an seinem Platz, zusammengeführt werden muss nichts. Halbiert das Pivot die Liste ungefähr, entstehen etwa log2 n Ebenen mit je höchstens n Vergleichen: O(n · log n). Ist das Pivot immer das kleinste oder größte Element – etwa bei einer schon sortierten Liste mit der letzten Zahl als Pivot –, wird jeder Teil nur um eins kleiner: O(n²). Partitioniert man in place durch Tauschen, braucht Quicksort keine zusätzlichen Listen, ist dann aber nicht stabil.

Das Wichtigste

Quicksort wählt ein Element der Liste als Pivot (Drehpunkt) und teilt die übrigen Elemente auf: alle kleineren nach links, alle größeren nach rechts. Danach steht das Pivot an seinem endgültigen Platz. Die beiden Teile werden rekursiv genauso sortiert. Eine Liste mit höchstens einem Element ist sortiert (Basisfall).
Laufzeit: im besten und im mittleren Fall O(n · log n), im schlechtesten Fall – wenn das Pivot immer das kleinste oder größte Element ist – O(n²). Mit Aufteilen in place (durch Tauschen in derselben Liste) braucht Quicksort keinen zusätzlichen Speicher für Teillisten.
