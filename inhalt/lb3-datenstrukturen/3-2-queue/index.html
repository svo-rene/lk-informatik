Beispiel 1 einfach Mensa-Warteschlange als gekapselte Klasse

Ausgangssituation: enqueue(A), enqueue(B), enqueue(C), dequeue() → A, enqueue(D), dequeue() → B. In der Schlange stehen danach C, D (C vorn).

Diesen Ablauf an der Mensa-Ausgabe setzen wir mit einer Klasse ListenQueue um. Sie speichert die Wartenden in einer Python-Liste. Diese Liste ist ein privates Attribut __daten: Von außen wird die Schlange nur über enqueue, dequeue, peek und is_empty benutzt.

class ListenQueue:
    def __init__(self):
        self.__daten = []                # privat; vorn = Index 0

    def is_empty(self):
        return len(self.__daten) == 0

    def enqueue(self, x):
        self.__daten.append(x)           # hinten anstellen

    def dequeue(self):
        if self.is_empty():
            raise IndexError("dequeue aus leerer Schlange")
        return self.__daten.pop(0)       # vorn entnehmen

    def peek(self):
        if self.is_empty():
            raise IndexError("peek auf leerer Schlange")
        return self.__daten[0]           # nur ansehen, nicht entfernen

mensa = ListenQueue()
mensa.enqueue("A")
mensa.enqueue("B")
mensa.enqueue("C")
print(mensa.dequeue())   # A
mensa.enqueue("D")
print(mensa.dequeue())   # B
print(mensa.peek())      # C
  1. Leere Schlange anlegen: Der Konstruktor erzeugt eine leere Liste __daten. Die zwei Unterstriche machen das Attribut privat (vgl. Kapselung, Kurs OOP und Softwareentwicklung, Seite 4.6): Es ist ein Implementierungsdetail, nur die eigenen Methoden benutzen es, von außen ist __daten nicht erreichbar.
  2. Anstellen mit enqueue: A, B und C werden mit append hinten angehängt. Das Ende der Liste ist das Ende der Schlange, deshalb stellen sich Neue immer hinten an.
  3. Bedienen mit dequeue: pop(0) entfernt das Element mit Index 0, also A, und gibt es zurück. Vorher prüft die Methode, ob die Schlange leer ist, und meldet diesen Fehlerfall mit einem IndexError und einer verständlichen Meldung.
  4. Weitere Schritte: D stellt sich hinter C an, danach wird B bedient. Die Reihenfolge des Ankommens bleibt immer erhalten (FIFO).
  5. Nachsehen mit peek: peek liefert C, verändert die Schlange aber nicht. So kann man sehen, wer als Nächstes dran ist, ohne die Person schon zu bedienen.

Schritt 3: Warum ist pop(0) langsam?

Eine Schlange kann auf verschiedene Arten implementiert werden. Die beiden häufigsten Ansätze sind ein Array und eine verkettete Liste.

1. Implementierung mit einem Array

  • Die Elemente liegen hintereinander im Speicher; es wird kein zusätzlicher Speicher für Verweise benötigt.
  • Problem: Entfernt man vorn ein Element, müssten alle übrigen um eine Stelle nach vorn rücken – bei einer Python-Liste ist pop(0) deshalb O(n).
  • Lösung: ein Ringpuffer mit zwei Indizes für Anfang und Ende, die im Kreis weiterwandern. Damit sind enqueue und dequeue O(1).
  • Ist die Kapazität erschöpft, muss in ein größeres Array umkopiert werden (O(n) für diesen einen Schritt).

Im Video siehst du, was bei pop(0) im Speicher passiert (wie beim Einfügen vorn auf Seite 3.0.1), und warum wir deshalb in Video 4 und 5 eine eigene Schlange aus Knoten bauen. Achte darauf, wie viele Elemente bei einem einzigen dequeue rutschen.

Beispiel 2 komplex Schlange mit einer verketteten Liste

Ausgangssituation: Der Schuldrucker soll Druckaufträge in der Reihenfolge ihres Eintreffens abarbeiten, und zwar auch bei sehr vielen Aufträgen schnell. Statt der Python-Liste aus Beispiel 1 verwendet die Klasse Queue deshalb Knoten. Sie merkt sich in den privaten Attributen __head den vorderen und in __tail den hinteren Knoten. Die Schnittstelle (enqueue, dequeue, peek, is_empty) bleibt gleich.

class Node:
    def __init__(self, data):
        self.data = data
        self.next = None

class Queue:
    def __init__(self):
        self.__head = None    # vorn: hier wird entnommen
        self.__tail = None    # hinten: hier wird eingefügt

    def is_empty(self):
        return self.__head is None

    def enqueue(self, data):
        neu = Node(data)
        if self.__tail is None:         # Schlange war leer
            self.__head = neu
        else:
            self.__tail.next = neu
        self.__tail = neu

    def dequeue(self):
        if self.is_empty():
            raise IndexError("dequeue aus leerer Schlange")
        data = self.__head.data
        self.__head = self.__head.next
        if self.__head is None:         # letztes Element entnommen
            self.__tail = None
        return data

    def peek(self):
        if self.is_empty():
            raise IndexError("peek auf leerer Schlange")
        return self.__head.data

if __name__ == "__main__":        # Testzeilen nur beim direkten Start (F5), nicht beim import
    q = Queue()
    for auftrag in ["Brief.pdf", "Foto.jpg", "Referat.docx"]:
        q.enqueue(auftrag)
    print(q.dequeue())   # Brief.pdf
    print(q.peek())      # Foto.jpg
  1. Erster Auftrag in leerer Schlange: __tail ist None, also wird der neue Knoten zugleich __head und __tail. Diesen Sonderfall braucht man, weil es noch keinen letzten Knoten gibt, an den man anhängen könnte.
  2. Weitere Aufträge: Der neue Knoten wird an __tail.next gehängt, danach rückt __tail auf ihn weiter. Weil __tail direkt auf das Ende zeigt, muss nichts durchlaufen werden: O(1).
  3. dequeue(): Die Daten des vorderen Knotens werden gemerkt, dann rückt __head auf den Nachfolger. Kein Element wird verschoben, nur ein Verweis wird umgesetzt: O(1). Der alte Knoten ist nicht mehr erreichbar und wird von Python freigegeben.
  4. peek(): Liefert nur __head.data, die Verweise bleiben unverändert.
  5. Sonderfall „letztes Element entnommen“: Wird __head beim Entnehmen None, muss auch __tail auf None gesetzt werden. Sonst zeigte __tail noch auf den entnommenen Knoten. Das nächste enqueue würde dort anhängen und __head bliebe None; der neue Auftrag wäre „verschwunden“.

import time
from queue_knoten import Queue

def messen_liste(n):
    liste = []
    for i in range(n):
        liste.append(i)
    start = time.perf_counter()
    while len(liste) > 0:
        liste.pop(0)                 # O(n) je Aufruf
    return time.perf_counter() - start

def messen_queue(n):
    q = Queue()
    for i in range(n):
        q.enqueue(i)
    start = time.perf_counter()
    while not q.is_empty():
        q.dequeue()                  # O(1) je Aufruf
    return time.perf_counter() - start

for n in [20000, 40000, 80000]:

    print("  list.pop(0):   ", round(messen_liste(n), 3), "s")
    print("  Queue.dequeue: ", round(messen_queue(n), 3), "s")

Das Wichtigste

Schlange (Queue): Datenstruktur nach dem FIFO-Prinzip („First In – First Out“): Das Element, das zuerst eingefügt wurde, wird auch zuerst entnommen.

Grundoperationen: enqueue(x) fügt x am Ende ein, dequeue() entfernt das Element am Anfang und gibt es zurück. peek() liefert das vordere Element, ohne es zu entfernen, is_empty() prüft, ob die Schlange leer ist.

Aufwand: Bei geeigneter Umsetzung, z. B. als verkettete Liste mit Verweis auf den ersten und den letzten Knoten, liegen alle Operationen in O(1).

Node und Queue bleiben unverändert. Der ganze Druckauftrag kommt als data in den Knoten: drucker.enqueue(Druckauftrag("Brief.pdf", 2)). dequeue() liefert dieses Objekt zurück, dann liest du auftrag.name und auftrag.seiten. So bleibt die Schlange für jeden Inhalt verwendbar – Zahlen, Namen oder Aufträge.
