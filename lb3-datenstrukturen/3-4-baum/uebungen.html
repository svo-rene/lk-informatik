Datei: 2_baeume/baum.py – weiterführen

  2. Schreibe eine Funktion ausgeben(knoten, tiefe=0), die den Baum eingerückt wie ein Dateiverzeichnis ausgibt.

Code lesen, untersuchen, abwandeln

Bevor du selbst programmierst, liest du fertigen Code und findest heraus, was er tut. Das geht in fünf Schritten: Vorhersagen (auf Papier, ohne Rechner) → Ausführen → Untersuchen mit dem Debugger → Abwandeln → Fehler finden. Rechne mit etwa 25 Minuten. Eine Vorhersage, die nicht stimmt, ist kein Fehler – sie zeigt dir genau, was du noch nicht verstanden hast.

So debuggst du in Thonny
  1. Starten: Statt F5 drückst du Strg + F5 (Menü Ausführen → Aktuelles Skript debuggen, englisch Run → Debug current script). Das Programm hält vor der ersten Anweisung an.
  2. Schritt über (F6): führt die markierte Zeile aus, ohne in aufgerufene Funktionen hineinzugehen.
  3. Schritt hinein (F7): geht in den Funktionsaufruf hinein. Bei Rekursion öffnet Thonny für jeden Aufruf ein eigenes Fenster – so siehst du den Aufrufstapel.
  4. Fortsetzen (F8): läuft bis zum nächsten Haltepunkt. Einen Haltepunkt setzt du mit einem Klick auf die Zeilennummer.
  5. Variablen ansehen: Menü Ansicht → Variablen (View → Variables). In jedem Aufruf-Fenster stehen außerdem die lokalen Variablen dieses Aufrufs.

Tipp: Beim Fehlersuchen erst überlegen, welchen Wert eine Variable an einer Stelle haben sollte, dann nachsehen, welchen sie hat. Die erste Stelle, an der beides nicht übereinstimmt, ist der Fehler.

In den PRIMM-Vorlagen hat Knoten zusätzlich eine Methode __repr__. Sie sorgt nur dafür, dass der Debugger einen Knoten als Knoten('A') anzeigt statt als <__main__.Knoten object at 0x…>. Du kannst sie in deine eigenen Klassen übernehmen.

PRIMM 3.4: Was macht raetsel? AFB I–II

Dateien: primm_3-4_raetsel.py und primm_3-4_fehler.py in 2_baeume/ speichern – erst nach Schritt 1 öffnen.

1 Vorhersagen (Papier, ohne Rechner): Was gibt das Programm aus? Schreibe auch auf, in welcher Reihenfolge die Knoten besucht werden.

def raetsel(knoten):
    if knoten.kinder == []:
        return knoten.wert
    ergebnis = ""
    for kind in knoten.kinder:
        ergebnis = ergebnis + raetsel(kind)
    return ergebnis

# Baum: A hat die Kinder B und C, B hat D und E, C hat F
print(raetsel(a))
Lösung zeigen

Ausgabe: DEF. Die Funktion hängt die Werte aller Blätter von links nach rechts aneinander; die inneren Knoten A, B und C liefern selbst nichts, sie sammeln nur. Besucht werden A, B, D, E, C, F.

2 Ausführen: Öffne primm_3-4_raetsel.py in Thonny, starte mit F5 und vergleiche mit deiner Vorhersage.

3 Untersuchen mit dem Debugger (Strg + F5):

  1. Wie viele Aufrufe von raetsel gibt es insgesamt?
  2. Wie viele Aufrufe sind höchstens gleichzeitig offen? Bei welchen Knoten ist das der Fall?
  3. Welchen Wert hat ergebnis im Aufruf für B, kurz bevor er zurückkehrt?
Lösung zeigen

1. Sechs Aufrufe – einer je Knoten. 2. Höchstens drei, z. B. raetsel(A) → raetsel(B) → raetsel(D); in Thonny siehst du dann drei Aufruf-Fenster übereinander. 3. "DE".

4 Abwandeln:

  1. Ändere die Funktion so, dass sie alle Knoten in Pre-Order-Reihenfolge aneinanderhängt, also "ABDECF" liefert.
  2. Ändere sie so, dass die Blätter mit Komma getrennt erscheinen: "D, E, F". Tipp: Lass die Funktion eine Liste zurückgeben und verbinde erst am Ende.

5 Fehler finden: Die Funktion soll die Blätter zählen, liefert aber 1. Setze einen Haltepunkt in die Zeile anzahl = anzahl_blaetter(kind) und beobachte anzahl im Aufruf für A. Finde und korrigiere den Fehler.

def anzahl_blaetter(knoten):
    anzahl = 0
    for kind in knoten.kinder:
        anzahl = anzahl_blaetter(kind)
    if knoten.kinder == []:
        return 1
    return anzahl

print(anzahl_blaetter(a))      # erwartet: 3, ausgegeben wird 1

Lösungen zu Schritt 4 und 5 stehen in der Musterlösung.
