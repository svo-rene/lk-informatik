4.7 Typisierung in Python: Klarheit im Code

Einführung 2Übungen 4Vertiefung 1

Python ist eine dynamisch typisierte Sprache. Das bedeutet: Du musst keine Typen angeben, der Typ einer Variablen ergibt sich erst beim Ausführen aus ihrem Wert. Trotzdem ist es sehr sinnvoll, Typen freiwillig anzugeben – mit sogenannten Typhinweisen (engl. type hints).

Gerade bei größeren Programmen, bei Klassen und bei der Zusammenarbeit mit anderen helfen Typen enorm dabei, Code zu verstehen und Fehler zu vermeiden.

Schritt 1: Typhinweise lesen und schreiben

Typhinweise stehen hinter einem Doppelpunkt (zahl: int), der Rückgabetyp steht hinter einem Pfeil (-> bool). Im Video liest du zuerst die Typhinweise einer Funktion, dann die einer Klasse. Kurz erklärt werden type(…) und str | None. Achte im Speicherbild darauf, welchen Wert das Attribut projekt am Anfang hat.

Zum Nachlesen: Typisierung bei Funktionen

Bei Funktionen gibst du Typen für Parameter und Rückgabewerte an:

def ist_positiv(zahl: int) -> bool:
    return zahl > 0

So ist klar: Die Funktion erwartet eine ganze Zahl und liefert einen Wahrheitswert zurück.

Zum Nachlesen: Typisierung bei Klassen – unser Ansatz

Bei Klassen führen wir Typisierung direkt im Konstruktor ein. Die Typen werden dabei direkt bei der Initialisierung der Attribute angegeben. 

class Schueler:
    def __init__(self, name: str, klasse: int):
        self.name: str = name
        self.klasse: int = klasse
        self.projekt: str | None = None

Was passiert hier genau?

  • name: str beim Parameter legt fest, welcher Typ übergeben werden soll.
  • self.name: str = name sagt ausdrücklich: Das Attribut name ist ein Text.
  • projekt: str | None zeigt: Das Attribut kann leer sein (z. B. zu Beginn).

Warum ist diese Schreibweise sinnvoll?

  • Alles an einem Ort: Typ und Startwert stehen direkt zusammen.
  • Sehr gut lesbar: Man sieht sofort, welche Attribute eine Klasse hat.
  • Praxisnah: Diese Schreibweise wird in echten Python-Projekten häufig verwendet.
  • IDE-Unterstützung: Autovervollständigung und Fehlerhinweise funktionieren besser.
  • Besonders wichtig bei None: Ohne Typangabe wäre unklar, was später erlaubt ist.
Hinweis: Typ am Parameter und am Attribut

Auch wenn der Typ bereits beim Parameter steht, ist die zusätzliche Typangabe beim Attribut sinnvoll. Das Attribut kann später auch an anderer Stelle geändert werden.

Zum Nachlesen: Komplexere Typen

Ab Python 3.10 kannst du mehrere mögliche Typen mit dem Zeichen | angeben:

def ausgabe(wert: int | float) -> None:
    print("Wert:", wert)

int | float bedeutet: Der Wert kann entweder eine ganze Zahl oder eine Kommazahl sein. -> None kennzeichnet eine Prozedur ohne Rückgabewert.

Kurz geprüft 1: Einen Funktionskopf lesen AFB I

Was verrät dir der Kopf def mittelwert(werte: list[float]) -> float | None:? Was soll übergeben werden, und was kann zurückkommen? In welchem Fall ist None als Rückgabe vermutlich gedacht?

Lösung zeigen

Übergeben wird eine Liste von Kommazahlen. Zurück kommt eine Kommazahl – oder None. None ist vermutlich für eine leere Liste gedacht, denn dort gibt es keinen Mittelwert (man würde sonst durch 0 teilen).

Schritt 2: Was Python prüft – und was nicht

Typhinweise sind Hinweise, keine Kontrolle. Im Video werden die Funktionen und die Klasse aus Schritt 1 und die Funktion finde_index aus Beispiel 1 mit falschen Typen aufgerufen. Achte darauf, wann es keine Fehlermeldung gibt, wann ein Fehler erst an einer ganz anderen Stelle auftaucht – und wann einfach ein falsches Ergebnis herauskommt.

Zum Nachlesen: Listen und optionale Rückgabewerte

Seit Python 3.9 kannst du die eingebauten Typen direkt verwenden: list[str], dict[str, int], tuple[int, int]. Seit Python 3.10 schreibst du optionale Werte als int | None. Das Modul typing mit List und Optional brauchst du nur noch für ältere Python-Versionen; in älterem Code wirst du diese Schreibweise aber oft sehen.

Beispiel 1 einfach moderne Schreibweise (ab Python 3.10, z. B. in Thonny)

Ausgangssituation: Eine Funktion soll die Position eines Namens in einer Namensliste liefern. Kommt der Name nicht vor, gibt es keine Position.

def finde_index(name: str, namen: list[str]) -> int | None:
    if name in namen:
        return namen.index(name)
    return None
  1. Parameter typisieren: name: str und namen: list[str]. Warum: Wer die Funktion aufruft, sieht sofort, dass eine Liste von Texten erwartet wird – nicht etwa ein einzelner Text mit Kommas.
  2. Alle Rückgabewege prüfen: Im ersten Fall wird ein Index (int) zurückgegeben, im zweiten None. Warum: Der Rückgabetyp muss jeden möglichen Ausgang abdecken.
  3. Rückgabetyp festlegen: -> int | None. Warum: So weiß der Aufrufer, dass er den Fall None behandeln muss, bevor er mit dem Ergebnis rechnet.

Ergebnis: Die Signatur finde_index(name: str, namen: list[str]) -> int | None beschreibt die Funktion vollständig.

Kontrolle:

Aufruferwartete Rückgabe
finde_index("Ben", ["Mia", "Ben"])1
finde_index("Tom", ["Mia", "Ben"])None
finde_index("Mia", [])None (leere Liste)

Gleichwertige ältere Schreibweise mit dem Modul typing:

from typing import List, Optional

def finde_index(name: str, namen: List[str]) -> Optional[int]:
    ...
Beispiel 2 komplex Typhinweise mit verschachtelten Typen und eigener Klasse

Ausgangssituation: Ein Kurs soll zu jedem Namen beliebig viele Punktzahlen speichern und den Namen mit dem besten Durchschnitt liefern. Das Klassendiagramm mit Typen:

Kurs
+ fach: str
+ noten: dict[str, list[int]]
+ eintragen(name: str, punkte: int): None
+ bester(): tuple[str, float] | None
class Kurs:
    def __init__(self, fach: str):
        self.fach: str = fach
        self.noten: dict[str, list[int]] = {}      # Name -> Liste von Punkten

    def eintragen(self, name: str, punkte: int) -> None:
        self.noten.setdefault(name, []).append(punkte)

    def bester(self) -> tuple[str, float] | None:
        if not self.noten:
            return None
        name = max(self.noten, key=lambda n: sum(self.noten[n]) / len(self.noten[n]))
        return name, sum(self.noten[name]) / len(self.noten[name])

lk = Kurs("Informatik")
lk.eintragen("Mia", 13)
lk.eintragen("Mia", 11)
lk.eintragen("Ben", 14)
print(lk.bester())      # ('Ben', 14.0)
  1. Verschachtelten Typ lesen: dict[str, list[int]] heißt: Schlüssel sind Namen, Werte sind Listen von Punktzahlen. Warum: Ohne diese Angabe müsste man den ganzen Code lesen, um herauszufinden, was in noten steckt.
  2. Eintragen nachvollziehen: setdefault(name, []) liefert die vorhandene Liste oder legt eine leere an. Nach den drei Aufrufen gilt noten == {"Mia": [13, 11], "Ben": [14]}.
  3. Besten bestimmen: max vergleicht die Durchschnitte: Mia (13 + 11) / 2 = 12.0, Ben 14 / 1 = 14.0. Ben gewinnt, zurückgegeben wird das Tupel ("Ben", 14.0).
  4. Sonderfall leerer Kurs: Ohne Einträge gibt es keinen Besten. Deshalb lautet der Rückgabetyp tuple[str, float] | None und nicht nur tuple[str, float].
  5. Falle – Python prüft die Typen nicht: lk.eintragen("Tom", "15") läuft ohne Fehlermeldung, obwohl punkte: int verlangt ist. Erst der nächste Aufruf lk.bester() bricht ab: sum(["15"]) löst TypeError: unsupported operand type(s) for +: 'int' and 'str' aus. Der Fehler zeigt sich also an einer ganz anderen Stelle als dort, wo er gemacht wurde. Ein Prüfwerkzeug wie mypy meldet ihn dagegen schon in der Zeile mit eintragen.

Ergebnis: Ausgabe ('Ben', 14.0). Die Typangaben dokumentieren den Aufbau der Daten und machen den Sonderfall None sichtbar.

Kontrolle:

Aufruferwartete Ausgabe
print(Kurs("Physik").bester())None
wie oben, zusätzlich lk.eintragen("Ben", 10), dann print(lk.bester())('Mia', 12.0) (Ben jetzt 12.0, bei Gleichstand liefert max den zuerst eingetragenen Namen)
Kurz geprüft 2: Fehler oder nicht? AFB I

Was passiert beim Ausführen von finde_index("a", "Banane") und von Schueler("Tom", "11")? Gibt Python eine Fehlermeldung aus?

Lösung zeigen

Keine Fehlermeldung. finde_index("a", "Banane") liefert 1 – in und index arbeiten auch mit einem Text, gefunden wird der Buchstabe a an Position 1. Schueler("Tom", "11") legt ein Objekt an, dessen Attribut klasse der Text "11" ist. Beides widerspricht den Typhinweisen, aber Python prüft sie nicht; erst ein Prüfwerkzeug wie mypy würde es melden.

Danach: Aufgabe 4.7.4 – Notenliste. Zum Vertiefen passt Aufgabe 4.7.6 – Typangaben, die lügen.

Praxisbezug: Typen in großen Projekten

Alltag: Ein Formular, das bei „Geburtsdatum“ nur ein Datum annimmt, verhindert Eingabefehler – Typhinweise tun dasselbe für Programmcode.

Beruf: In großen Python-Projekten (z. B. bei Instagram oder Dropbox) wurden Typhinweise nachträglich eingeführt, weil Fehler mit falschen Typen sonst erst beim Kunden auftraten. In vielen Firmen prüft ein Werkzeug wie mypy vor jeder Veröffentlichung automatisch, ob alle Typangaben zusammenpassen.

Zusammenfassung

Typhinweise beschreiben, welche Typen Parameter (zahl: int), Rückgabewerte (-> bool) und Attribute (self.name: str = name) haben sollen. Mit | gibst du mehrere mögliche Typen an, z. B. str | None; list[str] ist eine Liste von Texten. Python prüft die Hinweise beim Ausführen nicht: Falsche Typen laufen oft still durch und führen erst später oder gar nicht sichtbar zu Fehlern. Prüfwerkzeuge wie mypy finden solche Fehler schon vor dem Start.

Das Wichtigste

Typhinweise: Sie geben an, welchen Datentyp Parameter, Rückgabewerte und Attribute haben sollen, z. B. def f(x: int) -> str.

Keine Prüfung durch Python: Python prüft Typhinweise beim Ausführen nicht; ein falscher Typ führt nicht automatisch zu einer Fehlermeldung. Entwicklungsumgebungen und Prüfwerkzeuge wie mypy werten sie aber aus.

Nutzen: Typisierung ist freiwillig, macht Code aber übersichtlicher, sicherer und leichter verständlich.

def mittlere_laenge(worte):
    gesamt = sum(len(w) for w in worte)

def erste_ziffer(text):
    for zeichen in text:
        if zeichen.isdigit():
            return int(zeichen)
    return None
