4.6 Kapselung, Sichtbarkeit und kontrollierter Zugriff

Einführung 2Übungen 2Vertiefung 2

In der objektorientierten Programmierung sollen Objekte ihre Daten selbst verwalten. Du möchtest verhindern, dass jemand von außen direkt auf sensible Daten zugreift oder sie unkontrolliert verändert. Genau dafür gibt es das Prinzip der Kapselung – unterstützt durch Sichtbarkeiten und sogenannte Getter- und Setter-Methoden.

Schritt 1: Warum direkter Zugriff schiefgeht

Ein einfaches Konto speichert Inhaber und Kontostand in öffentlichen Attributen. Im Video siehst du im Speicherbild, was passiert, wenn jemand von außen unsinnige Werte einträgt – und wie die Idee der Kapselung das verhindert. Achte am Ende auf die Zeichen +, # und - im Klassendiagramm.

Zum Nachlesen: Problem – direkter Zugriff kann schiefgehen oder ausgenutzt werden

class Konto:
    def __init__(self, inhaber, kontostand):
        self.inhaber = inhaber
        self.kontostand = kontostand

konto1 = Konto("Alex", 100)
konto1.kontostand = -5000     # Das sollte nicht erlaubt sein.
konto1.kontostand = 10000000  # Geld „aus dem Nichts“ – ebenfalls ein Fehler.

So sieht Sichtbarkeit in UML aus

In UML-Diagrammen wird die Sichtbarkeit durch Symbole angegeben:

  • + → öffentlich
  • - → privat
  • # → geschützt

Das gilt sowohl für Attribute als auch für Methoden.

Kurz geprüft 1: Was passiert ohne Kapselung? AFB I

Im Konto ohne Kapselung wird nach konto1 = Konto("Alex", 100) die Zeile konto1.kontostand = konto1.kontostand - 250 ausgeführt. Welchen Wert hat der Kontostand danach, und meldet Python einen Fehler? Mit welchem UML-Zeichen müsste kontostand im Klassendiagramm stehen, damit so etwas nicht vorgesehen ist?

Lösung zeigen

Der Kontostand ist −150, Python meldet keinen Fehler – das Konto kann sich nicht wehren. Im Klassendiagramm sollte das Attribut privat sein: - kontostand. Geändert wird es dann nur über öffentliche Methoden (+), die prüfen können.

Weiter mit Schritt 2: Privat und geschützt in Python →

Schritt 2: Privat und geschützt in Python

In Sprachen wie Java gibt es Schlüsselwörter wie private oder public. Python macht das anders: Hier regeln Namenskonventionen die Sichtbarkeit. Achte im Video darauf, unter welchem Namen das private Attribut __kontostand wirklich im Objekt steht, was Python beim Zugriff von außen meldet und was eine Zuweisung von außen im Speicherbild anrichtet.

Zum Nachlesen: Sichtbarkeit in Python

  • name: öffentlich (public) – darf von überall verwendet werden.
  • _name: geschützt (protected) – nur für die Klasse und ihre Unterklassen gedacht. Das ist reine Konvention; Python verhindert den Zugriff nicht.
  • __name: privat (private) – Python benennt das Attribut intern in _Klassenname__name um („Name Mangling“). Von außen ist es unter dem Namen __name nicht erreichbar.
Kurz geprüft 2: Wie heißt das Attribut wirklich? AFB I

Mit der Klasse Konto aus dem Video (privates Attribut __kontostand) wird k = Konto("Ben", 40) angelegt. Was liefern k._Konto__kontostand und k.__kontostand? Was liefert k.get_kontostand(), nachdem jemand k.__kontostand = 0 ausgeführt hat?

Lösung zeigen

k._Konto__kontostand liefert 40 (so heißt das Attribut intern – benutzen sollte man das aber nicht). k.__kontostand löst einen AttributeError aus. Die Zuweisung k.__kontostand = 0 legt ein neues, zusätzliches Attribut an; k.get_kontostand() liefert weiterhin 40.

Danach: Aufgabe 4.6.1 – Sichtbarkeit erkennen.

Weiter mit Schritt 3: Getter und Setter mit Prüfung →

Schritt 3: Getter und Setter mit Prüfung

Um ein Attribut zu schützen und trotzdem Zugriff zu erlauben, nutzt man Getter (zum Lesen) und Setter (zum kontrollierten Ändern). Im Video läuft der Setter einmal mit einem ungültigen und einmal mit einem gültigen Wert. Achte darauf, welcher Zweig der if-Anweisung jeweils läuft und wann sich der Wert im Objekt ändert.

Zum Nachlesen steht der Setter in Beispiel 1. Beispiel 2 zeigt, wie fachliche Methoden einen allgemeinen Setter ersetzen, und erklärt noch einmal genau, was beim Zugriff von außen passiert.

Beispiel 1 einfach Kontostand mit Getter und Setter schützen

Ausgangssituation: Im Problem-Code oben kann jeder den Kontostand beliebig überschreiben, auch mit −5000. Ziel: Der Kontostand soll nie negativ werden.

class Konto:
    def __init__(self, inhaber, kontostand):
        self.inhaber = inhaber
        self.__kontostand = kontostand

    def get_kontostand(self):
        return self.__kontostand

    def set_kontostand(self, neuer_betrag):
        if neuer_betrag >= 0:
            self.__kontostand = neuer_betrag
        else:
            print("Kontostand darf nicht negativ sein.")

Jetzt ist das Attribut __kontostand privat und wird nur über Methoden gelesen oder verändert. So schützt du dein Objekt vor falscher Benutzung.

  1. Attribut privat machen: Aus self.kontostand wird self.__kontostand. Warum: Von außen ist das Attribut unter diesem Namen nicht mehr erreichbar; niemand ändert es „aus Versehen“.
  2. Getter ergänzen: get_kontostand() gibt den Wert nur zurück. Warum: Lesen soll weiterhin erlaubt sein, Lesen kann nichts kaputt machen.
  3. Setter mit Prüfung ergänzen: set_kontostand() übernimmt den neuen Wert nur, wenn er nicht negativ ist. Warum: Die Regel „nie negativ“ steht jetzt an genau einer Stelle, und jede Änderung muss an ihr vorbei.
k = Konto("Alex", 100)
k.set_kontostand(-5000)     # Kontostand darf nicht negativ sein.
print(k.get_kontostand())   # 100
k.set_kontostand(250)
print(k.get_kontostand())   # 250

Ergebnis: Ein ungültiger Wert wird abgewiesen, ein gültiger übernommen.

Kontrolle:

Beispiel 2 komplex Statt eines allgemeinen Setters bietet das Konto fachlich sinnvolle Methoden an – und was beim Zugriff von außen wirklich passiert

Ausgangssituation: Ein allgemeiner Setter erlaubt immer noch, den Kontostand von 100 auf 1 000 000 zu setzen. Bei einer Bank darf sich der Kontostand aber nur durch Einzahlen und Abheben ändern. Das Klassendiagramm zeigt die gewünschte Schnittstelle:

Konto
+ inhaber: str
− __kontostand: float
+ get_kontostand(): float
+ einzahlen(betrag: float): None
+ abheben(betrag: float): bool
class Konto:
    def __init__(self, inhaber, kontostand=0):
        self.inhaber = inhaber
        self.__kontostand = kontostand

    def get_kontostand(self):
        return self.__kontostand

    def einzahlen(self, betrag):
        if betrag > 0:
            self.__kontostand += betrag

    def abheben(self, betrag):
        if 0 < betrag <= self.__kontostand:
            self.__kontostand -= betrag
            return True
        return False

k = Konto("Alex", 100)
k.abheben(500)                 # False, Kontostand bleibt 100
k.__kontostand = 10000000      # legt ein NEUES Attribut __kontostand an!
print(k.get_kontostand())      # 100 – das private Attribut ist unverändert
print(k._Konto__kontostand)    # 100 – so heißt es intern (bitte nicht benutzen)
  1. Setter durch fachliche Methoden ersetzen: Es gibt nur noch einzahlen() und abheben(). Warum: Die Schnittstelle bildet ab, was eine Bank erlaubt; einen Kontostand einfach „setzen“ gibt es in der Realität nicht.
  2. k.abheben(500): Die Bedingung 0 < 500 <= 100 ist falsch, also wird nichts abgezogen und False zurückgegeben. Warum: Der Rückgabewert teilt dem Aufrufer mit, dass die Botschaft abgelehnt wurde – ohne Ausgabe im Objekt selbst.
  3. k.__kontostand = 10000000 außerhalb der Klasse: Die Umbenennung („Name Mangling“) findet nur innerhalb der Klasse statt. Außerhalb legt Python deshalb ein zusätzliches Attribut mit dem Namen __kontostand an. Das echte private Attribut heißt intern _Konto__kontostand und bleibt 100.
  4. k.get_kontostand(): Im Klassenrumpf wird self.__kontostand zu self._Konto__kontostand umbenannt. Deshalb liefert der Getter 100 – der „Angriff“ hat nichts bewirkt.

Ergebnis: Ausgaben: 100 und 100. Der Kontostand ist nur über die beiden fachlichen Methoden veränderbar.

Kurz geprüft 3: Der Setter entscheidet AFB I

Mit der Klasse aus Beispiel 1: k = Konto("Ben", 40), dann k.set_kontostand(-1), k.set_kontostand(0) und print(k.get_kontostand()). Was wird insgesamt ausgegeben?

Lösung zeigen

Zuerst Kontostand darf nicht negativ sein. (−1 wird abgewiesen, der Wert bleibt 40), dann 0: Der Grenzfall 0 erfüllt neuer_betrag >= 0 und wird übernommen.

Danach: Aufgabe 4.6.2 – Temperatursensor schützen.

Hinweis: Warum ist das wichtig?

Denk an komplexe Systeme wie Banking-Apps oder Spiele: Wenn jede Komponente einfach alles ändern darf, entstehen Fehler und Chaos. Kapselung hilft, klare Schnittstellen zu schaffen – für sauberen und wartbaren Code. In fortgeschrittenem Python werden Getter und Setter oft mit @property geschrieben; das Prinzip bleibt dasselbe.

Praxisbezug: Kapselung schützt Daten

Alltag: Am Geldautomaten kannst du nur über festgelegte Funktionen (Abheben, Kontostand anzeigen) auf dein Konto zugreifen – nicht direkt auf die Datenbank der Bank. Das ist Kapselung im Großen.

Beruf: In der Bank- und Versicherungs-IT – etwa bei Rechenzentren großer Finanzdienstleister in Sachsen – verlangen Sicherheitsrichtlinien, dass sensible Daten nur über geprüfte Methoden verändert werden. Jede Änderung wird dort zusätzlich protokolliert. Softwareentwicklerinnen und -entwickler sowie IT-Sicherheitsfachleute prüfen in Code-Reviews, ob Attribute ausreichend gekapselt sind.

Zusammenfassung

Öffentliche Attribute kann jeder von außen beliebig ändern. Kapselung verbirgt die Daten im Objekt und bietet Methoden an, die Änderungen prüfen. In Python ist _name geschützt (nur eine Abmachung) und __name privat: Python benennt das Attribut in der Klasse in _Klasse__name um, sodass objekt.__name von außen einen AttributeError auslöst und eine Zuweisung von außen nur ein neues Attribut anlegt. Getter lesen, Setter ändern nach einer Prüfung – oft passen fachliche Methoden wie einzahlen und abheben noch besser.

Das Wichtigste

Kapselung: Ein Objekt verbirgt seine inneren Daten und stellt nach außen nur ausgewählte Methoden zur Verfügung, über die auf die Daten zugegriffen wird.

Sichtbarkeit: Legt fest, ob und von wo aus auf Attribute und Methoden zugegriffen werden darf. Im UML-Klassendiagramm: + öffentlich, - privat.

Getter und Setter: Öffentliche Methoden, über die man ein geschütztes Attribut liest bzw. ändert. Der Setter prüft den neuen Wert, bevor er ihn übernimmt.

In Python: Nichts ist wirklich unsichtbar. _ oder __ vor dem Namen zeigt: nur für den internen Gebrauch; __ schützt zusätzlich durch Umbenennung vor versehentlichem Zugriff.
